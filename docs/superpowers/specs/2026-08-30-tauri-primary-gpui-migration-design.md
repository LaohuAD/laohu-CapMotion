# Tauri 主线与 GPUI 迁移设计

## 1. 决策

Cap 当前只把 Tauri 桌面应用作为日常使用、功能验收和自定义开发的正式产品线。GPUI 源码继续保留并跟随官方更新，但在达到迁移门槛前，不再把用户自定义界面功能只实现到 GPUI，也不把 GPUI 直接启动脚本作为默认入口。

这不是永久放弃 GPUI。目标是让当前版本稳定可用，同时把未来迁移范围压缩为界面适配，而不是重新实现录制、剪辑、动画、工程协议和渲染系统。

## 2. 当前事实

- Tauri 已有较完整的区域选择压暗、录制控制条折叠、手动放大取景框、摄像头与音频交互和中英文界面。
- 手动放大的工程状态、录制片段、柔性跟随和渲染计算已有共享 Rust 实现；取景框和快捷键交互主要在 Tauri。
- Motion 定义、实例、事务、Remotion 渲染缓存和原生合成位于共享工程、CLI 与渲染层；可编辑 MotionTrack 和属性面板位于 Tauri。
- Q/W/E 时间线即时剪辑的完整执行路径主要落在 GPUI，Tauri 已有快捷键配置与部分时间线命令，但尚未完成同等行为。
- 当前分支把录制前启动控件的位置改在了 GPUI，并创建了直接运行 `apps/desktop-gpui` 的脚本。这会绕过 Tauri 的成熟交互，是需要纠正的入口错误。

## 3. 架构边界

### 3.1 共享核心层

共享 Rust 层负责与界面框架无关的能力：

- `.cap` 工程模型、版本兼容和事务；
- 时间线分割、向前裁剪、向后裁剪等编辑命令；
- 录制状态机、手动放大状态和 ZoomTrack 数据；
- Remotion Motion 定义、实例、缓存和 CLI 协议；
- 预览与导出共用的渲染、合成和媒体处理；
- Agent/Codex 修改工程所需的稳定命令与数据协议。

共享核心不得依赖 SolidJS、DOM、Tauri 窗口组件或 GPUI 控件。

### 3.2 Tauri 适配层

Tauri 是当前唯一正式界面，负责：

- 录制入口、设备选择和区域框选；
- 区域外压暗、录制控制条折叠和手动放大取景提示；
- 设置、快捷键、中英文文案和错误提示；
- 时间线轨道、拖拽、滚动、缩放和属性面板；
- MotionTrack 的移动、拉伸和公开参数编辑；
- 把用户交互转换成共享核心命令。

界面层不得复制共享核心中的时间线和工程变换算法。

### 3.3 GPUI 适配层

GPUI 在迁移门槛满足前只保留官方实现和必要的上游兼容，不作为自定义功能的唯一落点。未来迁移时，GPUI 负责重新实现界面呈现、窗口行为和输入适配，并调用同一套共享核心。

不得为了“看起来两边都有”而在当前阶段同步维护两套界面。只有修复上游合并冲突、共享协议兼容或迁移验收所必需的 GPUI 改动才进入当前范围。

## 4. 本轮纠偏范围

1. 把本地启动脚本改为只启动 Tauri，明确关闭 GPUI 并行开发循环。
2. 撤回当前分支上仅针对 GPUI 的录制启动控件位置改动。
3. 在 Tauri 的录制目标选择界面把启动控件放到屏幕水平居中、垂直约 40% 的中间偏上位置，并保证不同显示器和录制区域下可点击。
4. 不重写 Tauri 已有的区域外压暗、录制条折叠和手动放大交互；通过回归测试确认位置调整没有破坏它们。
5. 把 Q/W/E 即时编辑行为补齐到 Tauri：W 在播放头分割，Q 分割并删除播放头前方，E 分割并删除播放头后方；只作用于选中且与播放头相交的片段。
6. 保留用户可在设置中修改或清除 Q/W/E 绑定的能力。
7. 保留 Tauri 现有的中英文系统、MotionTrack、Remotion CLI、缓存和原生 MotionLayer，不迁移到 GPUI。
8. 记录一份功能落点清单，后续新增功能先判断属于共享核心还是 Tauri 适配，禁止再次出现启动不同版本导致功能集变化。

## 5. 启动与构建策略

- 日常开发入口为 Tauri，启动时设置 `CAP_GPUI_DEV=0`，避免开发脚本同时运行 GPUI。
- 启动脚本从仓库根目录解析路径，不依赖调用者当前目录。
- 缺少前端依赖时给出明确错误和安装提示，不自动执行大规模依赖安装。
- 不主动构建 `apps/desktop-gpui/target`，避免约数 GB 的额外 Rust 构建缓存。
- 用户没有明确要求打开应用时，只进行后台编译和自动测试；需要人工验收时再启动可见窗口，并避免反复抢焦点。

## 6. 本地化策略

当前继续使用 Tauri 的统一 i18n 入口。面向用户的按钮、标签、说明、错误和状态跟随 `uiLanguage`；代码、命令、路径、占位符、配置键和协议值保持英文。

后续新增文案不得散落为无法检索的中英文条件分支。现有文案在相关功能被修改时逐步收敛到统一翻译资源，但本轮不做与纠偏无关的全量重构。GPUI 可以读取共享的语言偏好，但在正式迁移前不要求与 Tauri 同步完成全部翻译界面。

## 7. Motion 与 Remotion 策略

Motion 工程模型、Remotion 渲染缓存、CLI 和原生合成路径维持现状，继续作为界面无关能力。Tauri MotionTrack 是当前正式编辑入口。

移动实例或调整仅影响时间位置的参数时，不应无条件触发 Remotion 重渲染；修改动画定义、公开渲染参数、尺寸、帧率或源码指纹时才使缓存失效。未来 GPUI 只需要实现 MotionTrack 和属性面板适配，不重新定义 Motion 协议。

## 8. 错误处理与兼容

- 启动入口必须明确标识所运行的桌面实现，不能静默切换到 GPUI。
- Tauri 启动失败时保留完整错误输出，不以启动 GPUI 作为自动降级。
- 编辑命令不满足“已选中、播放头相交、可编辑”条件时不修改工程，并给出无副作用的界面反馈。
- 新旧 `.cap` 工程必须保持向后兼容；未知 Motion 字段和旧手动放大数据不能因界面切换而丢失。
- Remotion 缓存缺失或陈旧时可以重新生成，源码和 Motion 定义仍是事实来源。

## 9. 验证标准

### 自动验证

- Tauri 启动脚本解析、环境变量和缺少依赖时的失败信息测试；
- 录制目标控件定位函数在单屏、多屏和不同缩放比例下的边界测试；
- Q/W/E 对视频、缩放、场景、字幕、文字、遮罩、音频和 Motion 轨道中受支持片段的命令测试；
- 未选中、播放头不相交、片段过短和锁定状态不产生工程改动；
- 快捷键持久化、解绑和冲突校验；
- 现有手动放大、Motion、事务、渲染和本地化测试继续通过。

### 人工验证

- 区域录制时选区保持明亮，外部区域压暗；
- 开始录制控件位于中间偏上且不会被屏幕边缘遮挡；
- 录制后控制条可以收缩到边缘，悬停展开，计时不中途清零；
- 手动放大时取景框持续显示，外部正常画面可见但压暗，窗口不抢焦点，鼠标可穿透；
- 中文模式下用户界面中文完整，技术字符串保持英文；
- Tauri 编辑器可以完成 Q/W/E、轨道水平滚动、纵向滚动和缩放；
- MotionTrack 可移动、拉伸、编辑参数，预览和导出结果一致。

## 10. GPUI 迁移门槛

只有同时满足以下条件，才创建普通 Git 迁移分支评估切换；不创建额外 worktree：

1. 官方把 GPUI 作为默认稳定桌面实现，而非可选试用入口；
2. 显示器、窗口、区域、摄像头、麦克风和系统声音录制通过；
3. 长时间录制、崩溃恢复、音画同步和导出通过；
4. 区域压暗、录制条折叠、手动放大和柔性跟随通过；
5. 中英文、可配置快捷键和编辑器关键轨道通过；
6. MotionTrack、Remotion 预览/导出和 Agent/CLI 工程修改通过；
7. 旧 `.cap` 工程兼容性通过。

迁移时优先复用共享核心，只重做 GPUI 的界面与输入适配。任何无法复用的功能都进入明确的迁移清单，不以静默缺失换取切换进度。

## 11. Git 与上游同步

- 使用当前单工作目录和普通 `codex/` 功能分支，不创建 Git worktree。
- 自定义功能按“共享核心、Tauri 适配、测试和文档”组织提交，避免把多层无关改动混在一个提交中。
- 定期获取官方主分支，但不盲目合并；先审查 GPUI、共享 crate 和项目格式变更，再在普通分支中完成兼容验证。
- 大视频、构建缓存、Remotion 渲染产物和 GPUI `target/` 不进入 Git。

## 12. 成功结果

用户始终通过一个明确的 Tauri 入口获得完整、稳定且一致的功能。当前开发不再因为切换界面实现而丢失交互；新增能力优先沉淀到共享核心；未来官方 GPUI 稳定后，迁移工作集中在界面适配和验收，而不是推倒重写整个 Cap、Remotion 和 Agent 工作流。
