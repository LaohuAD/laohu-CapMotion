# CapMotion 首次语言与权限引导设计

## 目标

把首次进入 CapMotion 的流程收敛成两个清楚阶段：先完成一次语言选择，再完成权限检查。语言选择在普通升级、本地重新编译和覆盖安装后继续沿用；权限页只要求屏幕录制和辅助功能，麦克风与摄像头可选。用户不需要判断何时重启，也不会进入反复授权、反复重启的循环。

## 已确认问题与根因

1. 语言选择已经接入 `uiLanguage`，但只有该值为空时才显示。这个行为符合“一次选择、升级沿用”，需要保留并补回归测试。
2. 现有权限弹窗在打开系统设置后立即出现，没有先等用户明确完成，也没有在按钮动作后重新检查权限。
3. 现有弹窗文案写死为英文，没有使用当前 `uiLanguage`。
4. 权限页面以 250 毫秒间隔持续轮询，既不符合用户期望，也把权限状态变化与用户动作混在一起。
5. 当前本地 ad-hoc 包的指定要求是本次构建的 `CDHash`。每次重新编译都会改变身份，导致 macOS 设置仍显示旧 CapMotion 已开启，而新二进制仍被 TCC 拒绝。仅修前端检测不能根治。
6. 当前代码把屏幕录制、辅助功能、麦克风和摄像头四项全部纳入进入门槛，与界面中后两项“可选”的语义冲突。

## 用户可见流程

### 1. 语言选择

- 当 `uiLanguage` 为空时，语言选择是第一个页面，目前提供简体中文和 English。
- 选择后立即写入应用数据目录中的用户设置，再进入权限页。
- 普通应用升级、重新编译、重新签名和覆盖 `.app` 都不得清除该值。
- 只有用户主动清除应用数据或执行包含个人设置清理的完整卸载，才重新出现语言选择。
- 后续所有引导、权限、错误和重启文案均使用该语言。

### 2. 权限页

同一页展示四项：

| 权限 | 属性 | 是否阻塞进入 |
| --- | --- | --- |
| 屏幕录制 | 必选 | 是 |
| 辅助功能 | 必选 | 是 |
| 麦克风 | 可选 | 否 |
| 摄像头 | 可选 | 否 |

页面首次显示时做一次权限检查。已经授权的项目直接显示“已授权”，不再要求用户重复操作。缺失项显示“授权”或“打开系统设置”。

### 3. 单项授权

用户点击某一项后打开对应的 macOS 设置。CapMotion 不做定时轮询，也不立即断言必须重启。用户回到应用后看到当前语言的确认弹窗：

- `我已授权，检查一次`：立即执行一次新的权限检查。
- `继续设置其他权限`：关闭弹窗，保留当前页面，允许继续处理其他项目。

可选权限拒绝、跳过或暂未授权都不阻塞主流程。

### 4. 自动决定进入或重启

用户不选择“直接进入”还是“重启”，程序依据一次检查结果自动分流：

1. 两项必选权限均返回 `granted`：主按钮变为“进入 Cap”，无需重启。
2. 用户明确点击“我已授权”，但该必选权限仍返回未生效：把该项记为本次会话的“等待重启”，允许继续处理另一必选权限。
3. 两项必选权限都已授权或声明已完成，并且至少一项等待重启：主按钮变为“完成授权并重启”。只统一重启一次。
4. 重启后页面初始化时检查一次。两项均成功则直接允许进入；仍失败则进入恢复状态，不再自动提出第二次重启。

“等待重启”只是本次引导会话状态，不写成永久权限事实；系统检测结果始终是权限真源。

### 5. 权限未生效恢复

重启后仍未授权时，页面明确显示失败的是哪一项，并提供：

- `重新检查`：用户主动触发一次检查。
- `打开系统设置`：回到对应权限页。
- 简短说明：关闭再开启 CapMotion 开关；仍无效时移除旧条目并重新添加当前 CapMotion。

恢复页不得再次自动弹出“需要重启”，避免死循环。

## 内部状态与边界

前端权限流程使用可测试的纯状态模型，至少区分：

- `checking`：正在执行一次检查。
- `ungranted`：系统当前未授权。
- `granted`：系统已确认授权。
- `pendingRestart`：用户声明已授权，但本进程仍未观察到生效。
- `recovery`：重启后仍未生效，需要人工恢复。

允许发生权限检查的事件只有：

1. 权限页首次打开。
2. 用户点击“我已授权，检查一次”。
3. 用户点击“重新检查”。
4. 应用重启后首次进入权限页。

禁止基于定时器持续检查。权限检查进行中禁用重复操作，防止并发结果覆盖。

## 本地签名身份稳定

`scripts/build-cap-local.sh` 继续使用免费 ad-hoc 签名，但必须为 CapMotion 主程序和最终应用包嵌入稳定的指定要求：

```text
designated => identifier "com.laohu.capmotion"
```

打包完成后必须验证最终 `.app` 的 designated requirement 是固定 identifier，而不是 `cdhash H"..."`。这使后续本地覆盖安装维持同一 TCC 身份。

从旧 `CDHash` 身份迁移到固定 identifier 的第一个版本可能仍需用户关闭再开启权限，或移除旧条目后重新添加；这是一次性迁移。迁移成功后，后续本地更新不应再次要求授权。

## 错误处理

- 权限命令失败：保留原状态，显示当前语言的非阻塞错误，并允许重新检查。
- 打开系统设置失败：不显示重启选项，显示失败信息和重试按钮。
- 设置写入语言失败：恢复先前语言，不进入权限页。
- 未知权限状态：按未授权显示，但不得直接推断需要重启。
- 可选权限失败：不改变“进入 Cap”的可用性。

## 测试与验收

### 自动测试

- `uiLanguage` 为空时显示语言页；已有中文或英文时跳过，覆盖安装所用设置迁移不覆盖该值。
- 权限门只检查屏幕录制和辅助功能；麦克风、摄像头为空或拒绝时仍可进入。
- 页面初始化只检查一次，不创建轮询定时器。
- 用户确认授权时只检查一次；成功、等待重启和恢复三条分支分别有状态测试。
- 所有确认、重启和恢复文案在中英文资源中都有键值，不存在硬编码英文弹窗。
- 打包脚本测试并在实际包上验证稳定 designated requirement。

### 人工验收

1. 清除测试数据后首次打开，语言页必须先于权限页。
2. 选择中文后，权限页和所有弹窗保持中文；选择英文时全部保持英文。
3. 已授权项目首次检查后直接显示“已授权”。
4. 只授权前两项即可进入；后两项明确显示可选。
5. 设置一项后选择继续，可继续设置下一项；不会立刻强迫重启。
6. 需要重启时只在两项必选权限处理完成后统一出现一次。
7. 连续构建并覆盖安装两次，语言偏好保留，已完成的系统权限不再重复索取。

## 非目标

- 本轮不增加简体中文和 English 之外的新语言。
- 本轮不改变录制界面内后续请求麦克风、摄像头权限的既有入口。
- 本轮不清理用户现有应用数据，也不自动重置 macOS TCC 数据库。
