# 字幕的烧录

**声音不断，字幕不断；意思完整，屏幕才换。** 展示文字可以更干净，但不能因为删了语气词就缩短讲话覆盖；气口、意群和观看速度共同决定换屏。

把已经校对确认的字幕压制进视频。这个流程只负责画布、字幕排版、翻译、渲染和验证，不借机改写观点或再次精剪。

## 前置条件

1. 找到当前最终成片和与其时间轴一致的正式校对 SRT。
2. 同时找到与当前成片对应的原始词级时间戳 JSON。正式校对 SRT 决定正确文字，词级 JSON 决定拆分后的精确时码。
3. 如果只有原始 ASR、仍有疑难项或字幕时间轴不对应当前成片，先执行 `correct-srt-subtitles`；未经确认的错词不得烧录。
4. 输出前检查同名文件，禁止静默覆盖。

## 从校对稿生成展示稿

正式校对 SRT 是保真文字主稿，不能原样烧录。压制前必须生成职责不同的中文字幕展示稿和双语展示稿：

1. 先把相邻 SRT 条目按原始词流和上下文重新连起来。原 SRT 边界不是展示边界；上一条和下一条本来属于同一个词组或句法成分时，先合并再重新切分。
2. 以词级时间戳为边界拆成短字幕，禁止把一个长 SRT 区间按字数或时长平均切割。
3. 先以原始词级 ASR 建立“讲话覆盖时间轴”，再整理展示文字。每条展示字幕的文字可以删除语气词、口吃或重复起头，但它必须继承对应原始口播意群的完整时间范围；不能因为保留文字变少，就把起点推迟到第一个保留词或把终点提前到最后一个保留词。连续讲话期间相邻展示字幕应连续覆盖，只有真实无讲话区间或明确保护的纯画面演示区间才允许留白。最终视频按帧输出时，再把边界对齐到对应帧；30fps 的画面精度约为 `33.3ms`。
4. 优先在真实停顿、并列项结束、分句边界或完整意群之后断开。不得拆开专名、英文词组、数字与单位、固定搭配、修饰语与中心词、动宾结构或介宾结构。
5. 中文单条通常控制在约 `8-18` 个汉字、`1-4` 秒且默认单行。数字只是安全范围，不可为了达标破坏完整词组；语速快慢和术语长度可以例外。
6. 展示稿允许轻度清理不承载含义的独立“啊、嗯、呃”、拖音、口吃和紧邻的自我修正。这里删除的是屏幕文字，不是讲话时间：清理后的字幕必须继续覆盖这些声音所在的原始口播时间，使观众在听到人声时始终有对应字幕。不得把被清理词的时长变成无字幕空档。
7. 如果重复已经构成数秒的完整语义绕述，只隐藏文字会造成明显音画文不一致，必须回到精剪阶段处理视频，不能假装成字幕清理。
8. 中文展示字幕默认不加逗号、句号等停顿标点。英文也默认不加句末句号和非必要逗号；如果一句长到必须依赖标点理解，优先继续拆成下一条。撇号、连字符、小数点、版本号和网址中的符号属于词义本身，应保留。生成 Cap 中文字幕轨时还要删除相邻汉字词组间由稿件或翻译过程误带入的 ASCII 空格，例如把“人物的停顿 情绪和重音”规范为“人物的停顿情绪和重音”；英文单词空格和中英边界的必要空格不得删除。

展示稿建议使用职责名而非版本名，例如：

```text
*_烧录中文字幕.srt
*_烧录中英双语.srt
```

## 默认交付

默认只输出一份中英双语版：中文在上、英文在下；英文是忠实、自然、简洁的字幕翻译，不添加原话没有的观点。只有用户明确要求中文版时，才额外或单独输出只显示中文的版本。

用户要求先看效果，或本条作品首次采用/改变字幕样式时，先输出一份双语短样片。用户指定时长时按指定值执行，未指定时约 10 秒。用户确认字体、字号、描边、阴影、行距和位置后，再渲染全片；样片不是正式版本。

## 固定视觉规则

- 横屏最终画布统一为 16:9，默认 `1920x1080`。
- 先判断源画面比例。源视频已经是标准 16:9 时，等比铺满 `1920x1080`，不得为了字幕人为缩小画面或新增黑边；字幕直接叠在原画面下方安全区。
- 只有源画面不是 16:9 时，才等比完整保留、水平居中，并把画布余量放到不遮挡主体的位置；可优先把黑色余量放在下方，不为铺满画面而裁切软件界面或人物。
- 字体使用 Cap 中稳定标识为 `Source Han Sans CN VF` 的思源黑体，并选择真实 `700` 字重；中文白色、居中、字间距 0、行间距 0。渲染器必须验证最终排版字形来自该命名字体；不得只检查工程字段或字体库“可解析”就判定已生效。
- 黑色描边参考剪映粗细 40。
- 黑色阴影参考剪映：不透明度 75%、模糊度 15%、距离 5、角度 -45°。这里的长期默认指“描边阴影”——阴影从黑色描边轮廓向外延伸，不是只给白色字形本身投影；Cap 同时保留独立“文字阴影”能力，但老胡预设默认关闭文字阴影，开启描边阴影。
- 标准 16:9 素材的字幕直接放在画面内底部安全区；非 16:9 素材存在下方黑色余量时，字幕可以落在黑色余量内。双语始终中文在上、英文在下且英文更小。
- 剪映字号 5、坐标、描边 40、阴影数值和其他引擎不是同一单位。跨引擎必须先生成代表性静帧，与用户参考图按视觉效果标定，禁止直接当像素值。
- 单条字幕以一眼能读完为准。长 ASR 句必须按语义和词级时码拆成短句，不能把整段识别文本塞进同一屏。

“老胡预设”当前经 1920x1080 成片静帧校准后的双引擎映射如下，属于同一视觉效果而不是同一数值：

- 直接 MP4 / ASS：中文 `Noto Sans CJK SC Bold`（思源黑体同源字形）字号 `64`、描边 `5`、阴影 `4`；英文同字体字号 `34`、描边 `3`、阴影 `3`。中文在上、英文在下，源画面为 1920x950 时贴顶，底部 130px 黑色区域承载字幕。
- Cap Motion 可编辑工程：用户预设 `Laohu` 使用 `Source Han Sans CN VF`（中文界面显示“思源黑体（简体中文·可变字重）”）、字重 `700`、字号 `50`、字间距 `0`、黑色描边宽度 `4`；文字阴影关闭，描边阴影开启，描边阴影为黑色、不透明度 `75`、模糊 `15`、距离 `5`、角度 `-45`，位置 `bottom-center`，无逐词高亮、无弹跳动画。英文副行相对中文缩小，不能反过来放大。
- 画布固定 `16:9`。直接 MP4 对非 16:9 源画面采用完整保留并贴顶；Cap Motion 的 `Laohu` 工程预设也必须把画布写为 `wide`，并使用工程内保存的当前桌面背景快照，不能留下 `wallpaper + path:null` 的白底状态。

## 文件位置

- 双语版、按需生成的中文版和预览视频都输出到输入成片所在目录。
- 项目目录只保存正式 SRT、双语字幕文本、烧录参数、输出绝对路径与质检记录，不保存视频副本。
- 字幕图层、临时音频和测试帧放进任务专用 `/tmp` 目录，交付验证后删除。

## 验证

至少完成以下检查：

1. 用 `ffprobe` 确认 16:9 分辨率、视频流和音频流存在，时长符合预览或全片要求。
2. 全程或样片完整解码，确认没有坏帧、时间戳错误和意外字幕流。
3. 抽取有字幕的静帧，检查字体、描边、阴影、上下层级、字幕安全区、中文断行和英文宽度；标准 16:9 素材还要确认没有被错误缩小或新增黑边。
4. 检查字幕时码不越界、单调递增，并抽查开头、中段、结尾及全部专名修改点。
5. 将展示 SRT 与最终成片的词级时间轴做全量覆盖率检查：运行 `node workflows/laohu-video/模板/video-editing/validate-word-coverage.mjs --raw 成片.raw.json --srt 展示字幕.srt --exclude-ranges system-audio-events.json`。排除项只允许是已确认的系统声音演示，其余人物讲话要求 `uncoveredWordCount=0`；发现空档必须回到时间映射修正。
6. 最终 ASR 必须晚于最后一次 EDL 和媒体渲染；生成并验证 `final-asr-provenance.json`。媒体、EDL、raw JSON 或 SRT 任一哈希改变，禁止继续引用旧覆盖率或旧 ASR 报告。
7. 只有验证通过后才能报告完成；如果仍在等待用户确认样式，要明确说明尚未渲染全片。
