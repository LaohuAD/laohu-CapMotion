# 四层能力进化与保真

## 一、审计不是看文件长短

从真实任务向下画能力链，并给每个节点记录：

| 项目 | 要回答的问题 |
| --- | --- |
| 触发 | 什么请求应进入这里，什么请求不该进入 |
| 输入 | 负责人必须知道哪些事实、时间权威和用户决定 |
| 灵魂判断 | 哪个取舍会改变候选胜负 |
| 筋骨产物 | 哪个中间结果必须交给下一步 |
| 血肉方法 | 哪些材料与技法怎样产生目标效果 |
| 表皮门槛 | 哪些硬规格和审美分寸决定返工 |
| 例外与失败 | 什么条件下反转、停止、降级或回退 |
| 调用关系 | 谁调用它，它又调用谁，交接带什么 |
| 证明 | 什么测试或真实成品证明它生效 |

只有能在这张表中指出去向，才算完成能力迁移。

## 二、从 Git 原文迁移成熟能力

大幅改写已有 Skill 前：

1. 读取当前文件及其真实调用者。
2. 用 Git 读取被改写前的原文；若有多个关键版本，比较改变能力而非比较行数。
3. 提取每条有价值信息的触发、动作、因果、例外、失败分支和输出。
4. 建立“旧信息 → 新权威位置 → 调用入口 → 回归场景”映射。
5. 新位置接通并通过回归后，才删除被完整替代的旧表达。

可以提炼，不能凭记忆提炼；可以删重复，不能把没有迁移证明的内容当冗余。

## 三、判断四层是否真正落地

### 灵魂失效

典型表现：只写“高质量、沉浸、炫酷、专业”，没有观众变化、真实冲突和主取舍；所有候选都能同时满足原则。

可观察修复：原则能否决至少一个原本看似合理的方向，并说明反转条件。

### 筋骨失效

典型表现：文件里提到很多 Skill 和 Reference，但没有触发、必要中间结果、交接字段、时间权威或失败返回。

可观察修复：真实请求能路由到唯一负责人；上游产物缺字段时，下游明确拒绝而不是猜。

### 血肉失效

典型表现：列出镜头、动画、字幕、数字人等方法，却没说作用对象、材料来源、目标效果、使用条件和过量风险。

可观察修复：同一技法在不同材料和目的下会被选择、降权或否决，而不是到处套用。

### 表皮失效

典型表现：硬规格写成“尽量”，审美判断写成计数器；schema 通过后就宣布画面优秀。

可观察修复：硬失败可被机械打回，审美分寸通过观看、手机缩略图、候选对照和整片连续性判断。

## 四、Reference 必须被激活

每份条件性知识都要由主 Skill 写明触发条件。重要任务读取后记录：

```text
asset：读取什么
trigger：为什么此刻需要
judgment：取得什么判断
changedDecision：改变或确认哪个具体决定
resultLocation：变化落在哪里
unusedBoundary：哪些内容本轮未采用
```

如果读取前后没有决定改变，也没有原决定得到可审计确认，这份知识本轮没有激活。

## 五、回归与删除门槛

回归三面：

- 当前：原失败在同构输入下不再出现。
- 旧任务：改造前成立的高价值能力继续成立。
- 相邻：新规则没有劫持其他题材、阶段或媒介。

删除前必须同时满足：已有唯一替代位置、真实路由可达、行为回归覆盖、没有独立追溯价值。否则保留、迁移或降级。
