# 老胡教学视频后期总装

**声音定路，画面作证。** 第二遍最终声音决定成片时间；字幕、动画和数字人只能解释、证明或承接这条主线。完整信息和可追溯性优先于盲目压短；覆盖效果优先放在上层，不以破坏底层录制换取方便。

**剪辑不是把素材排进时间轴，而是让观众只走一条路。** 后期先确定这条视频许诺观众什么、观众从哪里进入、最后带走什么，再决定删哪一句、补哪幅画面。技术任务齐全不等于作品成立。

## 边界与权威

- 第一遍自由录制属于“老胡文稿”。上游只调用 `scripts/cap-project-asr.mjs`，本 Skill 必须拒绝第一遍任务。
- 第二遍正式录制后，每条视频建立一个独立 Codex 任务。上游只创建并发送首份任务包，之后由老胡直接在该任务返工。
- `S2` 是第二遍源时间，`T2` 是冻结 EDL 后的成片时间。所有覆盖任务只写 `T2`；第一遍 `F1` 永不进入成片映射。
- 任务包唯一契约和状态见 [handoff-contract.md](references/handoff-contract.md)。先运行 `node scripts/postproduction-package.mjs validate <package.json>`。 这是正式执行校验：遇到动画批注、知识视觉或叠层设计不完整，先转入下述设计准备，不把校验失败直接当成要求用户补动画设计；其余阶段、授权、来源和时间错误仍分别处理。
- 任务明确指定用户命名预设时，在做剪辑、字幕和动画判断前用 `cap presets inspect <name> --json` 读取同一条目的 `agentProfile`，并把当时的预设 store revision 记入任务记录。没有 `agentProfile` 时使用本 Skill 的项目规则，不猜用户偏好；预设与用户当轮明确指令冲突时，当轮指令优先。
- 任务包必须先写 `intent`、`knowledgeActivations` 和每个覆盖任务的 `narrative`。没有观众变化、媒介理由和前后交接的任务，即使时码与接口正确，也不能进入制作。
- `narrative.purpose=UNDERSTAND` 且任务类型为 `REMOTION / AI_VIDEO` 时，任务必须带完整 `KnowledgeVisualContract`。它要说清口播主张、语义对象、起始状态、作用、状态变化、结果、口播触发、少量中文大标签及静音 / 声画同步验收；不承担知识证明的 `TRANSITION`任务不强行增加。
- 每个 `REMOTION` 任务必须带 `OverlayContinuityContract`，明确连续组、顺序、宿主载体、前后状态、唯一焦点、保护区、最低充分对比方式和交接。跨载体组必须满足前一任务 `stateAfter =` 后一任务 `stateBefore`，否则返回 `OVERLAY_STATE_DISCONTINUITY`。
- 当 Remotion 覆盖在 `AI_VIDEO_FULL` 上时，必须携带 `hostCompatibility`，并在真实生成视频到位后复核视觉锚点、稳定负空间、亮度与运动负荷。上游建议不替代真实像素验收；不因有动画而默认全幅蒙版。

## 多工程合并的同步完整性

触发：合并多个 Cap 工程、重编号录制段，或合并后仅后半段出现句尾截断、起音留白、音画错位。

- 合并必须共同迁移录制元数据、时间轴的 `recordingSegment` 和 `clips[].index` 对应的同步配置。逐源段复制 `offsets.mic`、`offsets.system_audio`、`offsets.camera` 及自动计算标记，按同一索引映射重编号；禁止只复制首工程的 `clips`，也不能把缺失项当作零偏移。
- 写入前检查每个合并源段恰好有一个对应同步配置，且数值与源工程一致；缺失、重复或冲突即停止组装，不能仅凭通用工程校验通过就交付。源工程无配置时先按应用的正式时钟算法解析并留下证据，不凭经验填零。
- 分清麦克风源时间、画面源时间、成片时间。已有有效配置和用户校准值须保留，不因气口返修重新套用默认值。
- 出现集中于换源后的截尾时，先查源段索引及同步配置，再判断是否需要放宽剪口；不能用添加静音或整体移动字幕掩盖取音错位。
- 合成主音频的 ASR 只验证那份音频，不能证明 Cap 播放或导出使用相同取音边界。后续正常验收应取 Cap 实际导出音频，覆盖每个新增源工程及重编号录制段的代表剪口，与源声音和映射核对。用户明确暂停复核时只交付已授权修复，标注“工程参数已修复，实际导出听感待用户确认”，不得宣称已通过导出验收。

失败案例：作品016合并了18段媒体，但同步配置仅有首工程的12项，后6段按零偏移取音，造成句尾截断。修复为补齐缺失配置，保留剪口、时长、字幕与已有参数；记录见该作品制作/音画同步修复回执.json。

## 阶段顺序硬约束（2026-09-20 用户确认）

完整录屏口播后期唯一顺序：**粗剪 → 精剪 → 调整顺序（仅用户明确要求时）→ 字幕与动画（可并行）**。虚拟剪辑也必须按同样顺序完成，不能先策划动画再倒推保留区间。每一步以上一步已成立的结果为输入；联合 HTML 是审核容器，不是各阶段同时决定内容的授权。 联合 HTML 的默认阅读模式应优先突出“最终拟用字幕/源时码/剪辑决定”；`BASE` 底画保持属于低优先级上下文，默认折叠或隐藏，不得在每句右侧重复占据视觉焦点。只有 `LOCAL/FULL/SIDE` 等实际画面增强单元默认展开；页面必须提供一次点击即可显示全部底画安排的切换，不改变审稿数据。

1. **粗剪**：老胡明确约定录制操作时会发声。检查麦克风与系统的实际有效声音；两者均无有效声音的气口、思考空白和等待按已确认的紧凑剪口规则删除，不因鼠标移动、点击、页面变化、截图价值、EVENT 标签或未来动画保留。ASR 空白不等于无声；完整字音、辅音闭塞及真实有声播放仍保护。只有用户明确指定保留的无声段才例外，不自行猜测“必要画面等待”。
2. **精剪**：只接粗剪保留序列，默认保持原顺序与观点，处理失败起头、口误重说和语义重复。真正重复的同一语义删前留后；前版独有的主语、条件、论据等不属于重复，保留必要部分，不整句误删。仅在用户明确指定重排时调整片段位置；发现理解断裂先提出具体问题，不擅自重构章节。
3. **调整顺序（可选）**：位于精剪之后，只有用户明确要求重排才启用，按其指定的片段与位置执行并重算映射。用户只说“按正常流程剪辑”时直接跳过，不主动重构，不为是否重排重复询问。
4. **字幕 / 动画**：精剪内容与顺序通过后，两者可并行，字幕不必等动画，动画不必等翻译结束。都只引用同一精剪 EDL 修订与映射。动画导演查看剪后连续画面，决定哪里需要辅助解释、哪里直接保留剪后原画；无权复活已删除气口、为动画延长原声或反向影响剪辑。

虚拟粗剪通过须留下粗剪保留区间、无声删除及明确例外；虚拟精剪通过须留下重复对照（删前/留后源范围）、保留顺序及当前映射；有明确重排要求时还须完成独立的调整顺序步骤，再向下游交付最终映射。缺任一前置产物不得进入下游字幕设计或动画策划。正式落轨前须冻结同一 EDL，并试听剪口与全片剩余气口；仅有候选表、字词覆盖或解码通过不算剪辑完成。可在工程中预览验收，无需为每阶段单独导出整片。剪辑返工使下游时码失效时，先修剪辑再重新派生字幕与动画，不能为了保住已做动画而拒绝剪口修正。

上述录制约定适用于老胡录屏口播，不扩展为所有无声视频都删；纯音乐、有声案例、用户指定无声展示和独立动画各守原任务边界。

## 必要运行链

```text
RECEIVED
→ 原 Cap 工程只读校验并建立非破坏工作副本
→ 读取 Laohu 预设供审稿使用（画幅、背景、画面位置、字幕样式），暂不写入工程
→ 第二遍 Cap 新 ASR
→ 确认观众、承诺和原有主线（不提前策划动画）
→ 虚拟粗剪及验收：去无声气口与等待，产出粗剪保留序列
→ 虚拟精剪及验收：默认顺序，重复删前留后，产出精剪 EDL 与映射
→ 可选调整顺序：仅用户明确要求时执行，否则跳过；完成后重算并验收映射
→ 基于同一最终剪辑结果并行做字幕切分/顺句与动画必要性/覆盖/素材策划
→ 同一份全片预剪辑审稿文档（逐候选片段 + 预期成片字幕时间轴 + 动画效果/时间/图片与覆盖方案 + 全部疑难）
→ 用户参谋与修改，反馈写回对应单元并重算受影响的时码与衔接
→ 用户批准当前整份方案：文字、剪口、音频分类、字体样式、画面动画及素材安排
→ PRE_EDIT_REVIEW_APPROVED
→ 应用已确认预设到非破坏工作工程
→ 将已审定的粗剪、精剪结果按依赖顺序落实工程并验收（不重新让画面决定取舍）
→ EDL_FROZEN（Cap revision + EDL hash + S2→T2 hash）
→ 将已批准的动画设计按冻结 T2 编译为正式任务合同并校验；改变观看效果的冲突返回审稿
→ 并行：修正 SRT 与中英双展示字幕轨物化 / 已授权动画及其他覆盖制作
→ Cap Motion 上层覆盖写入并核对共同 EDL 修订
→ REVIEW
→ DELIVERED 或 FAILED
```

任一步都必须给下一步留下可验证产物。EDL 或 Cap revision 改变时，旧覆盖计划作废并重新映射；不得在过期时间轴上“挪一挪继续用”。

用户直接交付正式录制 `.cap` 时，`capProject.sourcePath` 是只读原工程，`capProject.path` 必须是不同路径的新工作工程，且 `nonDestructiveCopy=true`。目标已存在时不覆盖，而是继续使用任务记录里已建立的同一工作工程；不得在每次反馈时制造 `_v2 / _最终版`。建立工作工程后先验证媒体、源音轨和 revision，再把任务明确指定的用户预设应用到工作工程。对于 `Laohu`，可渲染结果必须同时满足：画布 `16:9`；背景保存为 `currentDesktop` 语义绑定并解析到本工程的桌面快照；录屏等比完整保留并整体上移；字幕公共样式读取当时用户命名预设的字体和字重，保留白字黑描边、黑色阴影、无实心底框。预设不能携带字幕正文、EDL、源媒体路径或覆盖轨。

全片预剪辑审稿文档承接剪辑授权；含画面增强时也承接动画与素材方案的整体批准，不是可选分析附件。执行 AI 必须先在文档中走完虚拟初剪、虚拟精剪、字幕切分和字幕顺句，再交付“按此方案剪完后”的预期成片字幕时间轴；每条同时带源时码和连续计算的目标时码。拟用字幕必须先跨相邻 ASR 条目恢复连续词流，再按完整意群重新切分；每条能独立顺读，上一句的句尾不遗落到下一条，模型名、版本号和术语组合不从中间拆开。文档还必须覆盖源视频首尾，逐个候选剪辑片段写明 ASR 原文、建议状态和理由，并集中列出会影响剪口、字幕文字、专名、字体或样式的疑难。 **句级审稿硬约束**：正式审稿单元默认以一句完整口播（通常一个 ASR utterance，必要时按词级边界再拆）为最小单位；不得把数分钟连续口播合成一个审稿段。每个单元必须独立写出源起止、拟保留/删除/替换文字、重复或口水话理由、目标时码和上下句关系。跨句的动画组合只能在 `visuals` 层合并，不能用大段 `segments` 隐藏中间剪辑判断。若审稿单元超过 30 秒，必须拆分并说明拆分依据；超过 90 秒直接视为审稿不完整，返回 `PRE_EDIT_VIRTUAL_EDIT_INCOMPLETE`。录制音频只分麦克风声音和系统声音；外部录音归入麦克风声音。两者都无有效声音才进入气口候选；系统声音持续存在时，才结合画面和语境判断作品播放或操作演示。证据不足时只能标 `待确认`，不得用“可能是动画”直接保护或删除。只有用户明确批准且疑难清零后，任务包才能进入真实 EDL 与媒体执行阶段。

初剪与精剪职责必须分开。初剪只处理已确认的气口、空白和无意义等待；精剪才处理失败起头、前后重录和可证明的语义重复，默认对同一重复语义删前留后，保留前版独有信息。精剪冻结后再以最终保留语音和词级时码重新切分展示字幕，在不改变事实、观点和语气含义的前提下改善书面语序；切分后反查句尾残词、跨条目承接和专名完整性。上下文唯一的术语错词直接修正并记录，存在两个以上合理候选才询问用户。除系统声音演示外，每段有效人物讲话都必须有字幕覆盖，并沿用用户已确认的双语字体与样式。

重复试说必须按“最小重复语义单元”删除，不能按整条 ASR 或整句话粗删。后一版只替换前一版中的谓语、形容词或局部说法时，前一版独有的主语、对象、条件和句架仍是唯一信息，必须保留并与后一版自然拼接。例如“然后你又发现你创作出来的人物的脸很油的”后接“很油腻的话”，只能删除前版“很油的”和后版无必要的“的话”，保留前版完整句架并接后版“很油腻”。冻结前为每条润色字幕保存 `sourceRanges`，并做字幕语义支持审计：字幕中的主语、对象、判断和结论都必须能在这些可听源区间中找到，不得用只剩一个谓语的音频承载一整句字幕。

剪辑范围必须先由任务包和当前作品控制文档限定。原录制已有清楚主线时，默认做保守顺序剪辑：只删除波形确认的无意义静音中段、独立语气声、失败起头、紧邻自我纠正和可证明的重复试说；不得把“内容导演”自动扩张成章节重排、表达改写或个人语感清除。气口依据真实波形与试听收紧到上一词收音、下一词起音附近；同时检查片段内部和跨片段拼接后的总空白，不机械为每一侧叠加固定余量。用户要求紧凑口播时，优先切除两段有效声波之间的无意义低能量区，使句子连续；完整辅音、词尾、必要语义停顿和系统有声演示优先于压短，不直接采用 ASR 词级边界。冻结前必须生成内容覆盖审计：除明确排除项外，每个有效 ASR 词都应仍映射到至少一个 EDL 保留区间，未覆盖即失败。

2026-09-10 老胡已通过“六个部分”和两个“到”的真实试听选择 B 档：已确认属于犹豫的无声区以约20ms总余量为听感基准，通常两侧各约10ms；句内、句间都处理，拖音本体与实际字音保留。此数值不是检测阈值，不压缩有声字音来凑数；真正的辅音闭塞和有声演示仍保护。ASR词时间可能包住无声区，须分别记录“静音与识别词时码重叠”和“实际字音丢失”，不能把前者机械保护，也不能把前者直接宣称漏字；整词消失必须阻止写入，实际声音与重新识别交叉复核。此已确认个人偏好优先于下方默认保守句内处理。

用户明确要求去掉犹豫、思考产生的停顿时，句内与句间采用同一收紧目标：不得因它属于完整句子内部而保护无意义空白。拖音可保留，但拖音结束至下一起音之间的空白仍要检查。只保护实际发声、构成字音的闭塞及必要演示声音，不把 ASR 标注范围内的全部低能量都视为有声。用户尚不能给出具体间隔时，先选其指出的真实片段，制作原状及两档收紧试听；以听感选择确定后续全片尺度，试听参数不得未经确认升级成统一默认值。以下默认保守流程不能覆盖此项明确偏好。

气口精修先确定完整句子或意群的承接边界，再分析声音。连续意群内部的字间停顿、辅音闭塞和短暂低能量默认保留；字幕换行、ASR 换条或静音检测命中本身都不是下刀授权。只有已确认的犹豫、废弃起头或明显拖沓空白才可在句内增加剪口。先恢复被过度拆开的连续表达，再调整句间总停顿；禁止遍历每个词间空隙批量收紧。剪口需兼顾上一句自然收音和下一句完整起音，不能尾部贴词切、头部机械留白。波形外形只是定位证据，显示采样间隔和音画时间偏移也会造成视觉断崖；不把梯形外观或音频间隙检测阈值当作自然连贯的验收标准。

气口精修以自然承接为验收目标，不以逐毫秒消除静音为目标。用户波形标线用于表达大致收紧方向，不能当作精确切点；几十毫秒偏差通常可接受，不因孤立的短时长数值继续分割、重剪或重新识别整片。先处理听感明显拖沓的停顿，只有可听残音、断字或可见异常跳切才继续返修；最少必要剪口优先于机械清零。气口精修同时检查片段内部和每个保留片段的首尾，不能只删片段内部静音。静音检测只能提出候选，实际剪除调用 `workflows/laohu-video/模板/video-editing/safe-speech-gap-refinement.mjs`：候选区内所有保留词都扩成禁剪区，剪刀只能取禁剪区之间的安全内核；起音与收音余量由局部波形确定，不把 `0.14 / 0.10` 秒当不可缩短的固定下限；词级保护与波形共同确定边界，证据不清时保守保留。实际收紧结果必须进入 EDL，不能只生成静音审计而不执行。拼接后检查残留孤立字音、词尾截断和停顿总长，不能以 ASR 文字相似度代替剪口节奏验收。任何新 EDL 必须与上一个已确认 EDL 做词级差分，除明确列入删除清单的词外，`lostWords` 必须为 `0`。

Cap 字幕写入必须同时维护两个层级：`captions.segments` 是可重新派生的源字幕权威，`timeline.captionSegments` 是当前冻结 EDL 上的展示轨。只写展示轨会在工程重载或重新派生时被清空；只写源字幕则不能证明当前展示断句和 T2 映射正确。双语展示字幕调用 `cap project captions materialize`，按 `trackId=zh-CN` 与 `trackId=en` 建成两条可编辑轨；同一屏中英两段共享 `pairId` 与 T2 起止，中文字幕使用老胡预设的大字号主行，英文使用较小字号副行。写入后 `captions.displayMode` 必须为 `materialized`，防止编辑器用源 ASR 自动投影覆盖翻译和顺句结果。字号、字重和位置以用户最新命名预设及当前明确调整为准；不得用物化脚本中的固定字号覆盖用户设置。位置与字号属于语言轨，面板、预设、预览和导出应一致；兼容旧发布版必须使用单条覆盖时，应明确记录该限制，重物化时保留用户已调好的轨级位置。EDL 一旦改变，两条展示轨必须重新物化。写入完成后必须关闭或重载解析一次，再验证源字幕非空、展示轨恰好两条、每个 pair 两侧齐全、数量和 T2 时码符合预期。

整条视频还必须有一条可复述的观看路径。相邻任务的 `handoffOut` 必须能被下一任务的 `handoffIn` 接住；同一种信息已经由录屏或证据承担时，不再用动画重复解释。删除、调换或替换一个覆盖任务而不影响理解，说明它只是装饰，不是章法的一部分。

## 动画建议的设计准备

制作脚本允许只提供口播、段落位置、材料与粗略动画建议。后期负责人先调用 `laohu-animation-director` 的创意转译入口，产出具体的画面、对象动作、镜头/焦点、节拍、声音设计和收束，再把结果写入同一任务的 `annotation`、适用的 `knowledgeVisual` 与 `overlayContinuity`。已有合同只深化，不反转已确定主张。不要把尚未完成的设计伪装成一个通过校验的执行任务。

整片/章节总装不能只把脚本中已有 `REMOTION` 标记逐个派发。后期负责人先给动画导演该范围的虚拟成片连续文字、保留片段顺序与词级映射、源媒体和底画状态，让它形成“讲解单元与画面安排”：判断哪些片段合成一个解释，是否需要动画，实际覆盖起止、局部/全幅/保留底画、图片/截图/文字需求与缺口。没有动画的讲述也要有简要安排；后期负责人回收并检查与录屏、证据、人物、字幕和其他覆盖的冲突，再编译成执行任务。原脚本粗建议可调整，已锁定承诺与用户决定必须保护。

一个语义单元可跨多条字幕与多个相邻保留片段；内容范围与动画实际可见范围分开记录。成片中不连续的覆盖拆成多个 `finalRange` 和任务，必要时用原 `overlayContinuity.groupId/order` 接住状态，不能用最小/最大时码把中间操作一起盖住。正式任务起止由导演提出、后期按冻结映射验证；不得把这一步变成重新剪辑或自动重跑 ASR。

完整后期必须先完成虚拟粗剪、虚拟精剪并通过阶段检查，再在同一份审稿文档里完成可讨论的动画设计，只有预计时间时标为预期成片时间或相对节拍。用户提出图片、效果、覆盖或节奏修改时，直接更新对应单元并处理时间与衔接影响；整份当前修订批准前，不执行剪辑、作品动画实现、渲染或生成媒体。取得整体批准并冻结 T2 后，将已确认设计编译成正式合同、补足工程细节并执行，不再自行重设画面方向。执行字段以 `references/handoff-contract.md` 为准；必须校验画面方案完整、反馈与材料取舍已解决、批准覆盖剪辑与画面且对应当前修订。纯剪辑不因此扩大范围。`REMOTION_ANNOTATION_INCOMPLETE` 等原执行检查继续保留。

| 任务 | 改变观众什么 | 使用条件与材料 | 开始—变化—收束 | 错用风险 |
| --- | --- | --- | --- | --- |
| `SCREEN_RECORDING` | 看清真实操作 | 第二遍录屏、操作语句、指针状态 | 先定位界面，再完成动作，最后停在结果 | 乱序会让操作状态断裂 |
| `EVIDENCE` | 相信结论 | 截图、数据、出处与引用位置 | 先提出判断，再显证据，最后回扣结论 | 无出处会把推测伪装成事实 |

| `AVATAR` | 保持人物讲述连续性 | T2 对应的最终真实音频、连续组 | 延续前姿态、完成一段语义、在自然边界收束 | 按 40 秒机械截断会断句和跳姿态 |

`REMOTION` 必须调用 `laohu-animation-director`；`AVATAR` 必须调用 `runninghub-avatar`。字幕文字校对调用 `correct-srt-subtitles`；交付可返工 Cap 工程时，使用 `cap project captions materialize` 写入两条展示轨并由 Cap 导出时渲染，不再额外调用 ffmpeg 烧录。只有任务明确交付仓库外的直接 MP4 且不要求可编辑字幕轨时，才调用 `burn-subtitles`。

每个任务都要说明：它承接什么、要把观众从什么状态带到什么状态、为什么当前媒介比口播或现有画面更合适、把什么结果交给下一段。技法名称、任务类型和时间范围不能代替这些判断。

## 法度与验收

- 输入任务包必须是 `laohu.video-postproduction-handoff/1`，phase 固定 `SECOND_PASS_POSTPRODUCTION`。
- 底层原始录制与最终主音频必须保留；媒体在仓库外，仓库内只存文字记录和索引。
- 保守剪辑必须提交词级内容覆盖审计；任何不在明确排除清单中的有效词丢失，返回失败而不是静默缩短成片。
- 最终 ASR 必须在最后一次 EDL 精修和最终媒体渲染完成后重新生成。此后 EDL、媒体、ASR JSON 或 SRT 任一文件变化，旧验收立即作废；用 `validate-final-asr-provenance.mjs create` 生成哈希回执，并在交付前以 `validate` 复核，禁止把精修前 ASR 复制成“最终验证”。
- 字幕覆盖检查对显式标注的系统声音演示使用 `--exclude-ranges` 排除；其余词级麦克风人声必须 `uncoveredWordCount=0`。时间重叠通过只证明字幕在场，还必须抽查字幕文字是否由对应 `sourceRanges` 的可听语义支持。
- Cap 工程字幕验收必须同时通过源字幕、展示轨和重载持久性三项检查；界面暂时看见字幕不等于工程已经可靠保存。
- 程序动画唯一引擎是 Remotion；外部数字人和 AI 视频是覆盖素材，不冒充 Remotion 源动画。
- 本项目不调用 AI 视频生成接口。`AI_VIDEO` 只负责验收、导入和组装用户手动生成的成片；资产缺失时返回缺口，不擅自生成或替换。
- 上层写入前用 `verifyFrozenPackageFiles()` 复核 EDL 与映射哈希，再用 `buildOverlayCommandPlan()` 和 `executeOverlayCommandPlan()` 执行 revision-safe Motion 命令；revision 冲突立即失败，不覆盖新修改。同一 `groupId` 必须按 `order` 连续写入，并把合同作为组件 props 保留到渲染和返工阶段。
- 硬校验通过只证明规格成立。还必须观看检查口播自然、节奏、焦点、动画克制和数字人连续性。
- 底线门检查可播放、可追溯、时码与接口正确；巅峰门检查主线、观众变化、关键材料、跨段承接、专业知识增益和最强段落。两道门必须分别给出结论。
- 关键段落存在真实表达取舍时，比较至少两个方向不同的候选；只换颜色、词序和组件皮肤不算候选。
- 如果仍有一个已知、可执行并会明显提高主胜负手的修改，不能因为任务包、渲染和 Cap 写入已经成功就交付。
- 最终回传实际输入、产物路径、revision、哈希、测试、失败项和 `PASS / OBSERVE / FAIL / UNKNOWN`。

## 失败回传

使用稳定错误码，不隐瞒缺口：`WRONG_PHASE`、`PRE_EDIT_REVIEW_REQUIRED`、`PRE_EDIT_REVIEW_INCOMPLETE`、`PRE_EDIT_VIRTUAL_EDIT_INCOMPLETE`、`PRE_EDIT_UNCERTAINTIES_UNRESOLVED`、`PRE_EDIT_REVIEW_NOT_APPROVED`、`PRE_EDIT_VISUAL_PLAN_INCOMPLETE`、`PRE_EDIT_VISUAL_APPROVAL_REQUIRED`、`PRE_EDIT_APPROVAL_STALE`、`CAP_REVISION_CONFLICT`、`EDL_NOT_FROZEN`、`MAPPING_STALE`、`REMOTION_ANNOTATION_INCOMPLETE`、`KNOWLEDGE_VISUAL_CONTRACT_INCOMPLETE`、`OVERLAY_CONTINUITY_INCOMPLETE`、`OVERLAY_STATE_DISCONTINUITY`、`AI_HOST_COMPATIBILITY_INCOMPLETE`、`AVATAR_SEGMENT_TOO_LONG`、`RUNNINGHUB_FAILED`、`MEDIA_QA_FAILED`。只重试失败资产，不整批无脑重跑。

## 反馈进化

收到失败或反馈时，依次记录：现象 → 根因属于方向/链路/材料/规格哪一层 → 可证伪假设 → 修改最接近根因的唯一权威 → 回归当前、旧任务和相邻任务 → 标记 `KEEP / OBSERVE / REVERT`。一次反馈不能直接变成无边界永久禁令。

项目级规则修改不由本 Skill 自行沉淀，交给 `laohu-video-evolution`。写回前用 `validateEvolutionRecord()`（`scripts/evolution-record.mjs`）验证记录；回归必须分别覆盖当前失败、旧能力保护和相邻任务，不能用三个同类新案例冒充保真。

## 已有个人预设的执行回执

开始实际剪辑时读取用户命名预设的展示配置和 `agentProfile`，把紧凑气口、动画背景及字幕轨配置逐项落实到当前任务包；应用展示预设本身不等于执行了Agent偏好。交付前核对设置→实际行为→导出画面/声音证据。预设包含tight却没有剩余静音分类，或dimFullFrame却只出现中央面板，均为未完成。

双语字幕位置与字号必须一起继承。旧预设缺少trackStyles时，不得擅自缩小英文后继续沿用旧位置并宣称复现了预设；以已确认画面或当轮明确反馈校准真实字形外缘间距，再把两轨字号与位置一起保存到同一用户预设。老胡当前确认的效果为中英黑色描边之间仅留一条窄缝、约描边宽度，不能把两行贴叠，也不能用坐标差代替可见间距。实际像素、画幅和字体共同决定效果；具体值归用户预设，不写进公共渲染器。

完整剪辑进入字幕与动画前、最终交付前，都必须检查剩余静音，逐项处理超过0.2秒的区间，并抽听更短的连续气口。老胡录屏口播采用上文发声约定：无有效声音的等待按B档约20ms总余量收紧，不能用EVENT、屏幕动作或动画需求保护。例外只记录实际字音/辅音闭塞、有效系统播放或用户明确指定保留。片段内部、首尾及拼接后的累计空白都要检查；字词覆盖、解码和音画对齐不替代听感验收。

源麦克风时码必须按原录制起始时钟及播放器实际seek方向验证，不能凭offset名字猜正负。先用短段导出与独立音频相关比对校准一次，再全片落剪；已发现的方向错误写回转换入口与回归，不能靠每条作品临时补常数长期维持。

字幕位置返修先确认固定锚点和允许移动的轨道。用户指定“中文往下”时，英文位置、字号等未授权字段保持原值，只下移中文；不得因两种移动能得到相似间距就擅自替换。老胡当前双语偏好以英文原位置为锚点，中文向下靠近；参数保存到Laohu命名预设。验收同时比较前后两轨坐标与实际字形，不能只看最终间距。

### 逐句审稿的数据与判断补强（2026-10-01）

- `segments[].text` 是将来屏幕字幕的候选正文，不是原始 ASR 展示层；专名、大小写、同音错词、断句和语序必须结合上下文修正。原始 ASR 只保存在输入/源证据中。
- 每条源引用必须同时保留源文件局部时码 `start/end` 与跨录制段连续的 `globalStart/globalEnd`。HTML 第二列默认显示连续原始时码，必要时再显示局部文件时码；不得把重排后的 T2 时间冒充源时间。
- 剪辑判断以意图和最小语义单元为准：同一说话意图的重说、补说、改口和自我纠正，即使文字不完全相同，也按重复候选比较，默认删前留后；前句独有条件、对象、证据或结论不得随重复一并删除。
- 句首独立“嗯/啊/然后呢/这个呢”等默认不进入字幕；句尾有情绪或承接作用的语气词保留。单独标点、残句、没有承接作用的现场口头反应，若删除不损失信息则标 `DELETE`。
- 补录或后说片段若语义属于前一章节，允许在 EDL 中移动；必须在 `sourceRanges` 保留真实原始位置，在 `finalRange` 写重排后的成片位置，并在 `note` 说明“补录重排”。
- `note` 只记录异常处理：删除、重复对照、字幕纠错、语序调整、补录重排、保留的特殊语气或疑难。默认保留、默认句首清理等常规动作不逐句重复书写。
- 每个动画单元必须带独立的 `mode/status/reason/visibleRanges/phases`，并由 `laohu-animation-director` 和选定的动画 Skill 独立完成具体设计。审稿 HTML 中的动画备注是范围与观看目的，不是替代上游动画 Skill 的制作合同；无动画的单元不得伪造动画计划。

### 全量上下文精剪闸门（2026-10-01）

逐句审稿不是把 ASR 条目逐条标成 KEEP。执行顺序固定为：

1. **恢复原始证据**：每条候选同时记录源文件局部时码和跨段连续原始时码；重排只改变 T2，不改变源证据。
2. **恢复完整句**：把跨 ASR 条目的半句、补语、后置宾语合并阅读；单独标点、残句、悬空连接词和没有上下文作用的口头反应先列删除候选。
3. **意图去重**：比较相邻及近邻片段表达的意图，不要求字面相同。重说、改口、发现问题后的重新表述默认删前留后；前句独有条件、对象、证据和结论必须保护。
4. **语序重建**：识别补录晚说但语义属于前一步的片段，移动到正确章节；在 `note` 写“补录重排”，并保留原始 sourceRanges。
5. **字幕成稿**：第三列只写处理后的可播字幕。错词、大小写、专名、数字、断句和不通顺表达必须结合上下文修正；不能把原始 ASR 当作最终字幕。
6. **异常备注**：只记录实际发生的删除、合并、替换、重排、疑难和特殊语气。默认处理不重复写到每一行。
7. **全量复审**：不得只处理用户点名的 ID；完成后必须扫描全片的残句、相邻意图重复、同一编号重复、章节顺序冲突和字幕语序问题，并把候选写入 `fullContextAudit`。未扫描全片不得进入批准。

同一意图可以合并为一个字幕单元；合并后 `sourceRanges` 可包含多个原始片段，`finalRange` 是连续成片时间。动画单元可以跨这些字幕单元组合，但不得把合并字幕重新拆回 ASR 机械分段。

### 内容结构保护边界（2026-10-01）

完整口播的章节、案例、个人经历、个人网站/产品展示、skill目录和收束必须默认保留。精剪只允许删除句内口水词、明显重复的最小语义单元、错误重说、残句和不影响结构的局部语气；允许移动补录片段，但不得因为“低价值”“节奏慢”或“动画难做”删除整段结构。任何跨多句、跨章节或涉及个人资产展示的删除，必须单独列出范围、理由和理解风险，并等待用户明确授权。

### 删除权限与结构保护闸门（2026-10-01）

删除决定分三级，执行者不得跨级：

- `MICRO_DELETE`：句内独立语气词、口吃、紧邻重复词、单独标点或错误重说；可在逐句审稿中直接提出。
- `LOCAL_DELETE`：相邻一至三句的完整重复、残句或无承接补充；必须保留删除前后文本、源时码、保留后句和理解影响。
- `STRUCTURE_DELETE`：章节、案例、个人经历、个人网站、skill 展示、方法演示、结尾收束或跨章节片段；默认禁止，只有用户明确授权并在审稿中单独确认后才能执行。

当无法判断某句属于局部细节还是内容结构时，按结构保护处理，标 `QUESTION`，不得以“低价值”“节奏慢”“动画不需要”为理由自动删除。任何一次审稿生成必须输出 `deletionLedger`，逐项记录级别、源范围、删除理由、保留的信息和授权状态；没有删除台账不得冻结 EDL。

恢复或返工时，原始 ASR/源工程只负责补回缺失的证据和源时码，不能覆盖已经存在的人工审稿结果。当前审稿 JSON、用户明确确认的删改、字幕修正和备注优先于原始 ASR；只有缺少对应单元时才允许从原始证据新增。禁止用“恢复结构”把已确认删除的句子、重复默认备注或旧注释重新放回。生成前后比较章节、案例、个人资产展示和收束节点数量；结构节点减少时自动失败并返回 `PRE_EDIT_STRUCTURE_SCOPE_BREACH`，除非存在用户批准记录。

### 恢复后的逐章复核闸门（2026-10-01）

任何从原始 ASR 恢复结构、撤销误删或大范围返工后，之前的审稿结论全部失效。必须重新建立章节边界，并逐章完成一次上下文复读：每个片段检查前后语义、完整句、意图重复、补录归属、字幕通顺度、专名/数字/大小写和结构作用。复核结果写入 `contextReview`，至少包含 `status=COMPLETED`、章节计数、片段计数、逐片段记录和结构节点前后计数。

`contextReview` 不是机械正则扫描的替代品。正则只能产生候选，不能把全片质量标为通过；若存在未听音的候选，必须标 `REVIEW`，不得声称已冻结。HTML 重新生成、结构校验通过或时码连续，只能证明格式成立，不能代替逐章语义复核。若恢复后发现正文、删除决定或备注发生回滚，状态必须改为 `NEEDS_REVIEW`，不得继续声称全量完成；只有重新逐章检查并确认人工基线未被覆盖后才能恢复 `COMPLETED`。

审稿备注只记录异常处理：错词、语序、合并、删除、重排、特殊语气或疑难。不得把“逐句审稿”“句首口水词已候选删除”等默认流程文字写入每一行；恢复源证据时也不得恢复这类旧模板备注。

### 最终字幕物化与跨表一致性闸门（2026-10-01）

`sourceDecisions`、`segments`、`visuals` 和 `deletionLedger` 不是四份并列记录：`sourceDecisions` 先决定，`segments` 只能由已确认决定物化，`visuals` 必须引用物化后的 segments，HTML 只展示这一条结果链。原始 ASR 只提供源证据和时码，不得直接覆盖人工修订。

- `DELETE` 的源决定对应片段不得存在于最终 `segments` 或 `visuals.segmentIds`；否则校验必须失败。
- `KEEP` 或已修正的源决定，其最终字幕正文必须与 `segments[].text` 一致；差异必须显式标为 `QUESTION`，不能静默覆盖。
- 任何人工确认的删改、专名修正、合并、重排和备注都要进入当前修订的结果基线；从原始 ASR 恢复结构时只能补缺失证据，不能重建并覆盖已有结果。
- HTML 生成前必须做反向审查：逐条检查残句、逗号开头、孤立标点、重复编号、相邻意图重复、悬空补语和专名变体。只通过 JSON 结构校验不算审稿完成。
- `contextReview.status=COMPLETED` 只有在跨表一致性、句级意群检查和人工修订回归全部通过后才允许使用；发生任何回滚时必须降为 `NEEDS_REVIEW`。

### 屏幕字幕成稿层（2026-10-01）

审稿正文与屏幕字幕不是同一层：`segments[].text` 用于确认剪辑语义，`segments[].screenCaptions` 才是最终画面字幕候选。每个屏幕字幕必须落在所属 `finalRange` 内，按完整意群、标点和屏幕可读长度拆分；不得把长句原样塞进一条字幕，也不得为了拆分改写事实或观点。屏幕字幕可不以句号结尾，但问号、感叹号、省略号等有语义作用的标点应保留。HTML 必须同时展示审稿正文和屏幕字幕层，用户审批的是屏幕字幕层；剪辑删除、重排和字幕成稿分别记录，不能互相覆盖。

### 屏幕字幕分句原则（2026-10-01）

屏幕字幕的分句以口播完整意群为第一优先级，标点只是候选边界，不是自动切刀。每个字幕单元应尽量承载一个完整意思，保留主谓宾、修饰关系和重音落点；禁止把“回避”“主角”“不就是”等无法独立成立的单词或残句单独显示。拆分前先检查词组、固定搭配、转折关系和下一条是否只是当前句的补语；若拆分后只剩孤立尾词、词内断裂或语义悬空，必须并回前条。字幕长度不足以承载完整意群时，优先在自然停顿、重音转折或完整语法边界拆分，再用屏幕时长和字数做次级约束。标点可作为视觉节奏参考，但不得凌驾于真实口播逻辑。

### 跨剪辑片段屏幕字幕组合（2026-10-01）

剪辑片段边界与屏幕字幕边界是两套边界。连续的多个音频片段如果共同组成一个完整意群，屏幕字幕可以跨片段组合；不得因为 ASR 或剪辑把一句话拆成多条，就把字幕也机械拆开。组合字幕必须保留每个原始音频片段的 `sourceRanges`，并在字幕组中记录多个 `segmentIds`、连续 `finalRange` 和各段真实音频映射；只有字幕合并，不能篡改或吞掉音频片段。

屏幕字幕拆分按以下优先级：
1. 一个完整意思或重音单元；
2. 主谓宾、修饰关系和固定词组完整；
3. 自然口播停顿与画面节奏；
4. 并列枚举按独立要素拆分，例如“构图 / 造型 / 姿势 / 表情”应分别成为可读字幕单元；
5. 最后才用字数、标点和屏幕停留时长微调。

逗号不是默认字幕边界。长句中逗号两侧若仍属于同一完整意群，应合并；并列短语若每项具有独立重音，即使原句只有逗号，也应拆成多个屏幕字幕。禁止把词组后半段、孤立尾词或单个补语当成字幕。组合和拆分都必须在 HTML 中显示：用户看到的是实际屏幕字幕组，同时能追溯到组成它的多个剪辑片段。

### 屏幕语义单元与标点边界（2026-10-01）

“完整意群”不等于“一整句原样出屏”。屏幕字幕应把一条口播拆成观众能依次读懂的语义单元：引入、对象、解释、结论和重音落点可以分别出屏，即使它们在语法上属于同一句。例如“这里我给大家演示一下我之前从来没有研究过的一个问题，也就是爱情”应拆为“这里我给大家演示一下 / 我之前从来没有研究过的一个问题 / 也就是爱情”。

标点是候选边界，但不能机械切割：逗号、冒号、问号前后若形成独立的动作、对象、解释或结论，应优先拆分；若逗号后只是补语、固定词组后半段、单独尾词或无法独立成立的残句，则并回前条。屏幕字幕验收同时检查“拆开后每条能否独立承担一个观看动作”和“合并后是否过长、重音是否被埋掉”。

### 屏幕字幕承载与重复闭环（2026-10-01）

屏幕字幕只能显示对应真实口播已经说出的内容。短片段不得承载来自相邻片段的长句；跨片段合并时，`finalRange` 与 `sourceRanges` 必须同时覆盖全部被引用片段，并清除原片段中的重复显示。全量验收必须扫描：过短时长承载过长文本、相邻片段重复字幕、同一语义前缀重复、字幕文字与来源范围不相称。音频可以因内容决定保留，但同一语义不能在屏幕上重复出现。

### 语义删除先于字幕物化（2026-10-01）

如果后句是前句的更完整重说、修正或同一意图的顺表达，先在 `sourceDecisions` / `deletionLedger` 中按“删前留后”删除前句，再生成 `segments` 和 `screenCaptions`；被删除片段不得继续进入最终审稿轴或 `visuals`。若表达尚未完成，例如“有些 skill 还没有……创建”，必须跨相邻源片段恢复完整谓语，再按“还没有创建”成稿，不能把后一个动词误生成“创建很多东西”。“很多东西还在脑子里”属于后续状态说明，必须与前句分开但承接自然。校验必须同时检查删除决定、字幕物化和画面引用三者一致。

同一口播单元内部也要做最小重复清理：连续的“这个 skill 这个 skill”、重复起头或自我修正只保留最终自然表达；删除的重复词不能进入 `segments[].text` 或 `screenCaptions`，但源时码仍保留在审稿证据中。

### 口播不通顺在音频层收口（2026-10-01）

**观众听到第几遍，才算删到第几遍。** 录制口播时人会说错、改口、重说，会被自己的停顿把一句话切成两半，念稿时还会先念出错误版本的第一个音再改口。这些都属于剪辑要处理的事，处理落在 EDL：变的是保留区间，字幕只反映结果。同一语义保留最后一遍时，它的音频与字幕一起进入成片；被删的那一遍，音频与字幕一起离开。

审稿单元按 ASR 语句切分，所以这些问题天然以“相邻两条”的形态出现。执行时按四类识别，每类都有确定的音频动作：

| 形态 | 识别特征 | 音频动作 |
| --- | --- | --- |
| 同一句说了两遍 | 相邻两条正文相同，或一条包含另一条且较短者占较长者 75% 以上 | 删前留后，前一遍的区间写进 `deletionLedger` |
| 被停顿切开的一句 | 后一条承接前一条缺的主语、谓语或宾语，两条之间是 0.3 秒以上停顿 | 合并为一个成片单元，保留多个 `sourceRanges`，`finalRange` 连续，屏幕字幕只在该单元出现一次 |
| 相邻重启 | 前一条不超过 4 个字，且是后一条的起头 | 删前一条的音频 |
| 念稿改口的孤立音节 | 分句中间夹着一个不成词的单字，或分句以单字收尾而下一分句换成了正确的词 | 剪掉该字及其前后停顿，保留修正后的完整表达 |

啊、哎、哦、嗯、呃、唉、诶、呀、哇、哈这类语气词属于自然口语，单独成句并承担停顿作用时保留；判断依据是它是否只在给下一句留气口，而不是它字数少。可视字数不超过 3 个的单元，在 `note` 里写明它是保留的语气词还是待合并的残词。

**屏幕字幕由本段音频支持。** 每条屏幕字幕的字与词，都能在本单元的 `sourceRanges` 里找到对应发音；跨片段合并时 `finalRange` 与 `sourceRanges` 同时覆盖全部被引用片段，并清除原片段中的重复显示。字幕成稿可以修正错词、调整语序、去掉口吃，但写不出本段没有说过的话，也不把相邻单元的内容并进来。

**正文按音频补全，字幕按语义成稿。** 合并单元与跨片段补全谓语之后，`segments[].text` 与 `sourceDecisions` 的结果文本一起补到和音频相称的完整表达；字幕层按语义修正的错词同时落到 `text`，两处用词一致，审稿正文与屏幕字幕不各说一套。

### 从局部反馈反查共性缺口（2026-10-01）

发现一个片段的重复、错拼或阅读歧义时，不能只修该编号。必须沿同一生成链回查全片：源决定是否先于 `segments` 物化、被合并片段是否变成一个审稿行、合并行是否保留全部源时码、屏幕字幕是否只出现一次、短片段是否承载邻段长句、未完成谓语是否被错误拆成新意图。当前案例中的 `C138/C144/C146` 属于语义重复删除，`C151/C152` 属于未完成谓语跨片段拼接，`C165/C166` 属于前后重说删前留后，`C177` 属于单元内部口吃清理，`C181/C182` 属于合并后单行物化；这些不是编号特例，而是后续全量审稿和验收的共性类别。

审稿 HTML 的阅读对象是最终结果，不是内部中间片段：真正合并的片段显示为一行，第一列使用合并后的成片范围，第二列保留一个或多个源范围，第三列只显示最终内容。不能保留一个空字幕行来暗示“已合并”，否则用户会把源片段误读成仍然存在的独立字幕。

HTML 只呈现最终成片时间轴。被 `sourceDecisions` 标为 `DELETE` 的源范围不在 HTML 中显示空档，后一个保留片段直接接续前一个保留片段；删除证据只留在内部 JSON 和源决定审计中。只有确实属于最终成片、但暂时没有屏幕字幕的保留音画，才允许在 HTML 中显示字幕空档。

### 四层字幕验收与词级源映射（2026-10-01）

字幕生成必须分别完成四层检查：

1. **文字纠错**：重复字、同音错字、语序不通和明显口播修正，先修 `segments[].text`，再同步 `sourceDecisions` 的结果文本；不能只修屏幕显示层。
2. **意图删重**：比较相邻和近邻片段的主语、对象、条件、动作与结论；后句更完整时删前留后，删除片段不能进入最终 `segments`。
3. **屏幕分句**：独立意群、逗号并列项和完整谓语分别成屏；`screenCaptions` 不能把逗号两侧独立意思压成一条，也不能把未完成谓语拆成孤立动词。
4. **词级源映射**：每条屏幕字幕的 `sourceRanges` 只覆盖实际使用的源词区间；同一 ASR 片段被拆成多屏时，第二列不得重复引用整条大范围。若当前没有可靠词级映射，必须标记待补，不得伪装成精确切点。

HTML 的第一列是最终成片时间，第二列是该字幕实际取用的一个或多个源音频范围，第三列是最终显示文字。三列职责不同，不能用整条 ASR 的 `sourceRanges` 冒充每条屏幕字幕的真实音频范围。

### 虚拟剪辑对照视图（2026-10-01）

审稿 HTML 默认是虚拟剪辑对照结果，不得把原始 ASR 直接改写成最终字幕。每个成片单元同时保留 `rawAsrText`（原始 ASR，只读）、精剪后的成片文本、成片 `finalRange`、一个或多个实际输入 `sourceRanges`，以及最终 `screenCaptions`。粗剪删除、精剪删重、顺序移动和片段拼接改变的是音频片段链；错字修正、语义整理和分句只写入最终字幕层。HTML 应让用户能对照“原始说了什么、哪些源片段进入成片、最后屏幕显示什么”，删除项保留在虚拟剪辑对照数据中，但不伪装成最终成片内容。
