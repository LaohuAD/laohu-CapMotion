# 修正SRT字幕

目标是把机器识别 SRT 变成可发布的准确文字，同时保留原始识别结果和每一处修改依据。

## 输入

优先读取：

1. 当前指定成片及其新识别 SRT、原始时间戳 JSON。
2. 已确认 EDL 映射、源片 SRT、口播稿和项目术语。
3. 当前作品控制文档、素材索引和上下文。

媒体只从外部绝对路径读取，不复制进项目。

## 在完整剪辑流水线中的位置

当用户同时要求“粗剪、精剪、修正SRT字幕”时，本 Skill 是同一成片流水线的最后阶段，不代表还要额外交付一份“字幕修正版视频”。粗剪视频先作为精剪素材，精剪视频再作为字幕识别和校对对象；默认只交付完成三个阶段后的最终成片和正式校对 SRT。前两阶段媒体和字幕草稿只放临时目录，最终验证后删除。用户单独触发本 Skill 时，只校对当前指定成片，不自动补做粗剪或精剪。

完整流水线优先采用虚拟剪辑：粗剪和精剪先共同形成可追溯 EDL，不分别渲染媒体。会改变保留区间、剪口或顺序的疑难项必须在 EDL 冻结和无字幕成片渲染前确认；只影响错词、断句和展示文字的疑难项，可在无字幕成片验证后、字幕烧录前确认。复杂重排、大量短剪口、同步异常或映射冲突时，对成片完整重新 ASR；简单且映射可靠的顺序剪辑，可使用 EDL 映射加剪口重点抽查。

## 固定流程

1. 保留新识别原始 SRT，不覆盖、不改名冒充校对稿。
2. 校验时码单调、条目非空、末条不超过成片时长。
3. 逐条检查人名、账号名、软件名、模型名、品牌、英文缩写、数字、专业术语、明显同音错词、上下文不通、标点断句和剪口残句。
4. 用成片音频语义、上下文、源材料、项目术语及 EDL 映射交叉判断。不能仅凭“看起来更通顺”改写口播原意。
5. 将判断分为三类：
   - `确定修正`：上下文和证据足够，写入修正草稿。
   - `需用户确认`：存在两个以上合理候选、专名无法核实或需要回听，原文暂时不改。
   - `保留原文`：虽有口语感但语义成立，不为了书面化擅自改写。
6. 生成文字型产物：
   - `字幕修正记录.md`：全部确定修改，含时码、原文、修正、原因、依据。
   - `字幕疑难清单.md`：只放不确定项，含时码、原文、候选、疑问和推荐判断。
   - `*_修正草稿.srt`：只应用确定修改，不确定项保持原文。
7. 用户确认疑难项后，生成或更新职责明确的 `*_校对.srt`，再校验格式、时码、末条、断句和修改点。

## 校对稿与展示稿的边界

`*_校对.srt` 是“说了什么”的保真主稿，不等于可以直接烧录的屏幕展示稿：

- 校对稿负责纠正错词、专名和识别异常，保留真实口语、重复和原 ASR 分句，部分条目可以较长。
- 烧录展示稿负责“观众一次看到多少”，由 `burn-subtitles` 结合原始 JSON 的词级时间戳重新分段，并按固定规则轻度清理语气词、口吃和自我修正。
- 不得为了让校对稿看起来像成片字幕而丢掉可追溯的真实口语；也不得把十几秒的校对条目原样烧到画面上。
- 原始词级 JSON 是从校对稿生成展示稿的时间依据，必须与校对 SRT 一起保留。只有粗粒度 SRT、没有词级时间时，不能按字符数平均分配时间；应重新识别或做强制对齐。

## 约束

- 不把 ASR 的错词直接烧录进视频；“修正SRT字幕”本身不授权烧录。
- 不删除真实口语内容，不借校对之名重写观点、调整语序或继续精剪。
- 候选不能冒充确定答案；证据不足时明确写“需用户确认/需回听”。
- 原始 SRT、修正草稿、正式校对稿职责不同，不创建 `_v1`、`_最终版` 等版本文件。
- 所有输出都是文字记录，保存在当前作品目录；视频仍保存在主输入媒体所在目录。
