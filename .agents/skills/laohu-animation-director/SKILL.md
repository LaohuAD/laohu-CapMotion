# 老胡动画导演

**口播讲路，画面作证。** 动画帮助观众理解内容、看清证据或顺利进入下一段。先确认这一段是否需要动画、解决什么观看问题、覆盖何时开始结束；具体动画方法交给选定的原版制作 Skill。

## 工作边界

完整口播后期须在虚拟粗剪、精剪和必要的调序成立后进入动画判断。动画只依据当前成片顺序，不复活删除内容、不改变口播、不为动画延长气口或重排。无口播独立动画保留 `contentMode=standalone`、`timingMode=relative` 的原入口。

本 Skill 负责作品层面的观看目的、动画必要性、讲解单元和覆盖范围、内容/事实/素材边界、真实底画与时间依据、唯一审稿和批准、宿主兼容及 Cap 接回。选定上游后，由其原版 Skill 负责动画技法、选卡或图元、分镜、运动风格、动画实现和对应制作质检。本地导演不先另做一份动作/镜头设计让上游重做，也不把本地样式规则覆盖到上游原版。

最终制作脚本与已确认校正字幕决定表达内容；校正字幕是显示与语义依据，不是新 ASR。原录音与原始 ASR 是发声和源定位证据；冻结 EDL、源到成片映射及 T2 决定成片时间。任何工具都不能改稿、剪辑、主音频、字幕文字、公开承诺或已批准范围。anything2explainer 的检索只补充有出处的来源、真实素材、术语释义或帮助说明原主张的材料；遇到矛盾或可能改变结论时回现有疑难审稿。

## 新口播动效路由

1. 查看当前作品控制文档、请求范围的最终讲述与校正字幕、源定位/时间映射、真实底画、当前审稿与批准状态。只回答观众需要看懂或看清什么、哪些保留片段组成一个视觉单元、何时交还底画，以及是否应保留原画面或使用 Cap 原生文字/高亮。
2. 若确需程序动效，每个讲解单元选一个已安装的原版制作 Skill，并读取其原文及对应的[直接调用说明](references/动画知识路由与激活.md)。让该 Skill 依据自身原生规则决定卡片、图元、分镜、布局、字体、颜色、运动与制作检查；不要先套本地组件或样式清单。选择依据是该单元的观看目的、真实材料和上游原生能力，不按固定题材标签、黑底或科技感硬分工。同一条作品可在不同单元分别调用 TalkCraft 与 anything2explainer；同一单元只设一个主动画负责人，不要求两者同时使用。
3. 选定上游的原生分镜/制作单交回本次唯一审稿；单元范围、事实材料、底画职责和覆盖窗口由本地导演核对。需要整体审稿的完整方案获批且正式任务的 T2/映射冻结后，才渲染或写入 Cap。局部返工沿用已有批准范围，不重开整片审稿。
4. 上游不适用、缺少兼容证据或调用失败时，不自动退回本地手写组件、近似卡片或原创同名动画。说明具体缺口，提出保留原画面、不做动画或有依据的替代方案，并按现有审稿流程处理。

仅在维护已有本地动画、用户明确指定本地旧组件/旧实现、无口播独立动画沿用其原有相对时间入口，或选定上游明确调用并证明适合某个本地辅助实现时，才进入本地旧制作路线。此时按[条件知识路由](references/动画知识路由与激活.md)读取相应规范；不能因未选上游或上游失败而默认启用旧组件。用户已明确锁定的作品效果、材料和风格继续有效，不因本次路由改写。

纯剪辑、SRT 校正/整理、Cap 原生高亮或文字轨足以表达的任务不触发上游动画制作。程序动画仍由 Remotion 承载，Cap Motion 仍是口播成片的上层总装入口；这两项平台约束不决定动画的视觉设计。

## 审稿、批准与任务合同

完整后期继续使用当前作品唯一联合审稿主文档及其 HTML 视图。上游分镜作为该方案的制作依据或关联材料，不另建竞争审稿稿源；只把观众目的、真实素材、内容范围、覆盖窗口和待决取舍摘要到主文档。不要要求本地预先补完上游分镜、动作和样式。当前修订及全部影响观看的疑难得到用户批准后，依既有后期流程冻结 EDL/T2 并执行。未经批准的方案只能标记为候选。

现有任务包和 postproduction validator 消费的字段、schema 与 revision-safe Cap 接口继续有效，不能删掉、放宽或伪造：`narrative`、适用的 `REMOTION.annotation`、`KnowledgeVisualContract`、`OverlayContinuityContract`、`hostCompatibility`、`animationBriefSchema`、注册/definition 与 revision-safe `cap motion`。它们是从已批准的上游方案和真实底画中提取/映射的交付合同，不是第二次动画设计。按任务实际适用范围填齐；未满足时按既有错误码返回并说明缺项，不声称验证通过。

时间按工具原生可验证的粒度映射：anything2explainer 的真实句/字幕块边界可以派生其原生句块时间；只有效果确实依赖某个词且存在可靠词级证据时才要求词锚。TalkCraft 及本地旧组件使用各自实际时间输入。任何路径都要显式处理 T2 到片段局部时间、帧率、单位和端点；不得把绝对秒直接当局部帧、按字符插值词时码或用默认错峰冒充同步。映射不够支撑某个细节时，只停该细节或降到有证据的边界。

共享 Remotion workspace 可承载选定上游的 Composition/资产及 Cap definition；这不要求先改造成项目自有的 `ComponentConfig` 或注册成十二个本地家族之一。只在选用本地旧组件时要求其原 schema/props；上游原生实现使用其原生 props，并验证实际版本、构建规格和 Cap 宿主接法。当前没有 Cap 自动导入适配器，不能宣称上游资产天然透明、一键导入或已适配。

## 技术知识与交付验收

`remotion-best-practices` 是 Remotion API 技术资料入口，不是动画创作方法或项目审美入口。只在当前实现遇到 API、渲染、媒体/字幕或交互问题时按需读取，并先核对共享 workspace 实际依赖与导出。上游描述中的新建工程、安装/升级依赖、GUI、额外 agent 或其他运行安排不自动覆盖本项目已有权限和执行框架；本次路由不得擅自复制依赖、升级 runtime 或改变制作流程。

Cap 原生能力适合时优先使用可编辑文字/高亮等既有轨道；任何覆盖都不得重复呈现底画已完整承担的信息。交付前核对实际输出画幅、时长、背景/透明、字幕/HUD、主音频与音效去向、T2 同步、真实底画遮挡、事实来源和文件完整性。按所选上游的原生质量规则检查其动画，再做项目层内容、可读性、底画、同步和 Cap 合成检查；不把本地旧运动风格套在上游，也不凭 schema、单帧或渲染通过宣称审美提升。未经真实成片观看，不宣称效果已验证。

## 本地旧制作能力维护入口

已有本地 Remotion 组件、效果库、语义锚点、渲染缓存、编辑器原生轨和历史认可案例继续保留，用于明确的旧作品维护或用户指定的本地制作路线。只在该路线触发时，按 [动画知识路由与激活](references/动画知识路由与激活.md) 读取所需模块；不要求上游项目匹配本地家族、四轴字段、Shell、标签、色彩或构图。旧 CLI 是否整链可用仍以该入口记录为准，不能把原型或单元测试说成 Cap 导入/渲染已经验收。
