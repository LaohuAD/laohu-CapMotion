# 动画知识路由与激活

这份 Reference 解决“知识已经在项目里，却没有进入本次取舍”的问题。不要每次全读；先判断当前缺口，再加载最小必要知识。

## 条件路由

| 当前判断缺口 | 读取位置 | 必须形成的中间结果 |
| --- | --- | --- |
| 整片/章节还没有确定哪里要做动画、怎样组合片段、覆盖多久及缺什么材料 | `workflows/laohu-video/规范/动画导演转译规范.md` 第 2A 节 | 覆盖请求范围的讲解单元与画面安排；包含不做动画的理由、时间依据与实际底画证据 |
| 只有灵感、粗建议、参考图，或缺少具体动作/镜头/声音设计 | `workflows/laohu-video/规范/动画导演转译规范.md` | 画面理解、材料边界、逐拍动作与焦点、声音去向、结果和实现交接 |
| 不知道画面该补什么、是否越过口播边界 | `workflows/laohu-video/规范/画面补充策略.md` | 补充内容、来源层级、不能补充的边界 |
| 需要把抽象关系变成完整 MG 过程 | `workflows/laohu-video/规范/MG动画表达方法.md` | 承接—展开—收束的关系变化 |
| 需要选择流程、矩阵、层级、趋势或证据图解 | `workflows/laohu-video/规范/图表关系表达规则.md` | 信息形状、连线语义、焦点与停留时间 |
| 已确定关系，但不知道怎样动才自然 | `workflows/laohu-video/规范/动效规则.md` | 入场、变化、强调、退场与前后镜承接 |
| 需要查找具体动画手段 | `workflows/laohu-video/规范/动画效果库.md` | 被选效果的作用对象、使用理由和过量风险 |
| 需要校准项目气质、色彩、层次和禁区 | `workflows/laohu-video/规范/视觉风格.md` | 本段继承与例外，不是复制整份风格表 |
| 需要借鉴以前博主的画面机制 | `知识沉淀/案例参考.md`、`好画面片段库.md`；编辑叠层时读 `参考视频拆解与编辑型信息叠层进化计划.md` | 只选适合本段的机制，写清证据、可迁移部分和不复制的皮肤/材料 |
| 需要选择、升级或创建组件 | `workflows/laohu-video/规范/组件设计方法论.md`、`组件规则.md` | 适配 / 升级 / 新建 / 拒绝及其依据 |
| 准备交付 | `workflows/laohu-video/规范/质检清单.md` | 硬检查结果、观看问题与待改增益 |

`workflows/laohu-video/规范/提示词模板.md` 只在需要向外部生成模型或其他项目交付文字任务书时读取；普通 Remotion 实现不读取。`workflows/laohu-video/规范/制作流程.md` 由后期总装负责，本 Skill 不重复承担整条成片调度。

## 激活回执

重要动画至少记录一次：

```text
资产：本轮读取的规范、案例或组件说明
触发：当前哪个判断缺口要求读取
取得判断：得到的关系、方法、边界或否决依据
改变决定：因此保留、删除、降级、改写或否决了什么
结果位置：变化落在哪个批注、节拍、配置或验收项
未用边界：哪些内容与本段无关，为什么没有采用
```

只写“已读取视觉风格”“参考了动画效果库”不算激活。读取前后没有决定变化，也没有排除一个合理替代方向，视为本轮未使用。

## 外部 Remotion 知识的身份

`.agents/skills/remotion-best-practices/` 是实现知识，不负责决定本项目为什么做这段动画、选什么材料或是否值得出现。项目判断先由 `laohu-animation-director` 完成，再调用外部知识解决 React、Remotion、渲染、字幕或交互实现问题。

官方聚合包是唯一技术权威，版本和逐文件校验值见其 `upstream-lock.json`；嵌入模块现在使用 `REFERENCE.md`。本地旧同名 Skill 仅转发，不能再把旧副本与新参考同时当成两套方法。文档已更新不代表依赖已升级：先检查共享 workspace 的实际 Remotion 版本与导出，再采用官方 API。
