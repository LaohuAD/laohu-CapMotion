# 动画知识路由与激活

先确认本次使用哪条制作路径，再读取其所需知识。选定原版上游 Skill 时，不把本地视觉、动效或组件规范叠成第二套制作方法。

## 条件路由

| 当前需要 | 读取位置 | 形成的结果 |
| --- | --- | --- |
| 新口播后期需要程序动效 | 按讲解单元选择 `video-talkcraft` 或 `anything2explainer`，直接读取[TalkCraft 调用说明](video-talkcraft直接调用.md)或[anything2explainer 调用说明](anything2explainer直接调用.md)，并由其引向原版 `SKILL.md` 与所需原生材料 | 上游原生分镜/制作依据回到本次唯一审稿；本地只确认内容、事实、时间、范围、底画、批准与 Cap 接回。不要同时执行本表中的本地创意/组件方法 |
| 选用上游后遇到实际 API、Remotion 渲染或媒体兼容问题 | `.agents/skills/remotion-best-practices/SKILL.md` 及其按需技术页面；检查共享 workspace 的实际依赖和导出 | 记录兼容实现、验证结果及确切缺口；官方 API 文档不替代上游动画方法，也不意味着升级依赖 |
| 有任务字段需交给实际 postproduction validator | `laohu-animation-director/SKILL.md` 的“审稿、批准与任务合同”及 `workflows/laohu-video/规范/动画导演转译规范.md` 第 5 节 | 从已批准的上游结果映射既有必要字段；字段/schema/错误码继续有效，不预先另做一套视觉设计 |
| 需核对真人/录屏/证据底画的真实接回 | 本 Skill 的宿主兼容合同及当前 Cap/任务包接口 | 将真实底画和获准覆盖范围带入实际合成检查；不得凭单独渲染帧宣称宿主已适配 |
| 用户明确指定维护本地旧动画、某个旧组件，或继续旧作品已锁定的效果 | `workflows/laohu-video/规范/动画导演转译规范.md` 中“本地旧制作路线”；按缺口选择 `画面补充策略.md`、`MG动画表达方法.md`、`图表关系表达规则.md`、`动效规则.md`、`动画效果库.md`、`视觉风格.md`、`组件设计方法论.md`、`组件规则.md` 或其具体组件说明 | 仅对所选旧组件/作品补充真实输入、维护其既有方法并验收；不将该方法外溢为新上游动效的默认要求 |
| 本地旧组件、图表或 Shell 的明确维护任务 | 先看 `workflows/laohu-video/模板/components/README.md` 与被点名的 `workflows/laohu-video/模板/components/<组件名>.md`；需要结构性决定时才读组件方法论/规则及 `workflows/laohu-video/模板/remotion-assets/workspace/src/registry/componentRegistry.ts` | 按该组件真实 schema/props 与既有作品决定维护；不要求上游原版先映射成本地家族、`EditorialOverlayShell` 或 `ComponentConfig` |
| 明确选择本地语义锚点或案例检索路线 | `workflows/laohu-video/模板/remotion-assets/workspace/README.md` 的“确定性语义锚点/可复用案例检索”及 `src/semantic/` | `semantic:anchors`、`semantic:index`、`semantic:search` 是本地旧能力原型。锚点读取真实冻结映射、源词 ID/索引或段内 sourceRange；案例检索只给候选。当前未完成 EDL/ASR 输入、动作参数、注册表与 Cap 历史识别的整链生产验收，只能在被明确选用时做隔离核验，不作为上游默认制作入口或自动回退链 |
| 本地 Remotion 资产需要渲染/缓存 | Cap Motion 的 `cap motion render` 操作与 workspace README 的“本地 Remotion 渲染缓存”分别核对 | `cap motion render` 是 Cap 工程定义的轨内渲染；`npm run render:cached`（`render:cached`）是独立 workspace 的确定性资产缓存/渲染。两者输入、receipt、放置与验收职责不同，不可互相声称完成；只用与当前选定资产入口相符的命令 |
| 明确制作 Cap 原生文字或高亮轨 | `workflows/laohu-video/规范/Cap Agent 工程接口.md` 的原生轨章节与 `scripts/cap-project-native-tracks.py` | 仅通过窄白名单补充/移除原生文字或高亮；保留 revision、锁、原子写和回执。纯字幕修正/烧录仍走各自 Skill，不触发上游程序动效 |
| 底画为 AI 生成全幅视频 | 当前任务的 `OverlayContinuityContract`/`hostCompatibility`、workspace `schemas/director.ts` 的 `AI_VIDEO_FULL` 条件以及 `scripts/postproduction-package.mjs` 对应校验 | `AI_VIDEO_FULL` 仍须提供并通过宿主兼容信息；由获准上游结果映射必要字段，按真实画面验证保护区、运动负荷、亮度、注意力交接和禁止叠加窗口。不能因上游样式自由而跳过合同 |
| 明确使用无口播独立动画的本地相对时间入口 | 本地任务原入口与 `workflows/laohu-video/模板/remotion-assets/workspace/src/schemas/director.ts` standalone 条件；必要时再读对应组件说明 | 保持 `contentMode=standalone`、`timingMode=relative`，提供正数 `durationInFrames` 并保证相对事件落在该时长内；不伪造 T2、ASR 或口播宿主合同 |
| 已选上游不适用、运行失败或接入证据不足 | 不转读旧组件规范来自动补做；将具体上游能力、素材或宿主缺口交回本次审稿 | 提出保留原画面、不做动画或有依据的替代；不得声称上游调用、渲染或兼容验证已通过 |

新上游由本地导演按讲解单元及实际观看目的选择，不按固定题材表分类。可在同片不同单元分别调用两个上游；同一单元只有一个主动画负责人，不要求每条作品两者都用。两种原版能力若重叠，按各自原生说明与实际结果比较；不要再经过本地组件家族或风格清单转译。具体步骤与内容边界分别见两份直接调用说明。

anything2explainer 的研究只补充有出处的来源、真实素材、术语释义或帮助解释原主张的材料；研究不能改定稿、校正字幕、事实结论或时间轴。真实句/字幕块边界可按原版 timeline 派生帧；只有明确要求踩词而且有可靠词级证据时才依赖该词锚。TalkCraft 使用其原生语义标注、选卡、SHOTBOOK 与时间实现。两者都须遵循当前项目的批准、T2/映射、素材授权、音画及 Cap 总装边界。

## 条件激活本地旧知识

本地旧规范和案例不是新上游任务的默认必读资料。确实进入本地旧制作路线时，只加载所选模块，并留下必要回执：

```text
资产：读取的本地规范、案例、源码或组件
触发：本地旧任务中的具体缺口
取得判断：改变或确认的本地维护决定
结果位置：变化落到的场景、任务字段或验收
未用边界：未采用的旧规则及其不适用原因
```

选用上游时，激活回执记录它的原版能力如何处理本单元，以及本地时间/事实/宿主检查改变了什么；不因读取了本地风格文件就把其美学、组件字段或动作节拍追加进上游设计。

## 外部技术知识的身份

`.agents/skills/remotion-best-practices/` 只提供 Remotion API 与技术文档入口。`video-talkcraft` 和 `anything2explainer` 分别提供其原生动效制作能力；只有按单元选中后才调用对应原文和实现。它们不是审稿权威或 Cap 自动导入器。上游的 agent、runtime、GUI 或建项目说明仍受本项目当前权限与执行框架约束。
