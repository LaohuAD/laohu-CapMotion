# 口播精剪审稿模板

本模板用于口播视频粗剪、精剪和复剪。它的目的不是增加流程负担，而是在动手剪之前先保护内容完整度：先知道什么必须保留、什么可以删除、为什么删除，再生成技术剪辑清单。

包含画面增强的完整后期在本文件内同时审动画与素材方案。用户先看、讨论、修改这份方案，整份确认后才执行剪辑和动画制作。只要求粗剪/纯剪辑时，画面部分标记不适用，不自动增加制作范围。同一文件持续更新，不创建版本副本。

## 默认交付：可视化 HTML 审稿

本文件继续定义内容要求，新任务给用户的主审稿交付默认是 HTML 时间轴。采用刚刚完善的联合审稿内容，不退回只有时码、字幕、备注的旧表。每条作品在已有 `分析/` 中维护 `预剪辑审稿.json`，由 `scripts/pre-edit-review.mjs` 生成同目录 `预剪辑审稿.html`。JSON 是同一方案的结构化编辑来源，HTML 是给用户阅读的派生视图；不再手动维护另一份内容相同的 Markdown 主稿。已有历史审稿不删除、不自动迁移批准；确需导入旧稿时核对完整内容和当前时间依据，过期时码标为 `HISTORICAL`。

固定阅读顺序：

1. 标题、审稿范围、当前修订与整体确认状态；本片主线、观众和字幕样式可展开核查。
2. 顶部疑难区，待解决与已解决分开标识。每项包含问题、上下文、建议/已确认结论、关联单元与跳转。
3. 中央一条竖向成片轴。左侧三列为成片时码、源时码、最终拟用字幕/无字幕事件，备注与关联疑难紧贴对应行。源时码支持一条字幕来自多个文件或保留区间。
4. 右侧画面方案跨越它对应的连续字幕行，直接展示组合理由、实际覆盖窗口、效果概要、局部/全幅/保留底画、交给下一段的方式。图片排列在该说明旁，逐张写图号、用途、来源和状态。逐拍动作、镜头、音效及反馈历史按需展开。
5. 保留源素材的完整审稿决定，包含删除项及理由；它们在源审稿折叠区核查，不混入成片轴。

轴上时间来自真实保留词流与映射，不从字幕字数、页面高度或动画文案反算。为保证可读性，页面按段排布，高度不代表时长；起止时间始终明确。没有展示字幕的间隙标为间隙，不能因此推断无声或删除。跨不连续片段/章节的动画拆成多个展示单元，可用共同 `groupId` 与文字交接保持关系；多个单元不能争用同一字幕行。一个连续单元中的多个实际可见窗口逐一列出，动作不得落在窗口以外。

### 数据和生成

可从同目录 [预剪辑审稿示例.json](预剪辑审稿示例.json) 了解完整字段，但不能把示例的字幕、时码、图片占位或批准套进真实作品。所有秒数为数值，源文件引用支持多个区间，`isExample` 仅供格式演示。

| 字段 | 职责 |
| --- | --- |
| `schema / id / title / revision` | 固定 `laohu.pre-edit-review/1`，作品身份与当前修订 |
| `scope / timing` | 审稿范围起止，`basis=PROVISIONAL / FROZEN / HISTORICAL`，以及映射文件/时间依据 `reference` |
| `brief` | `audience / mainline / captionStyle`，本片观众、主线与已确认的字幕样式 |
| `approval` | `PENDING / APPROVED`；批准时必须有真实 `reference`、`reviewRevision` 和 `scope=EDIT_ONLY / EDIT_AND_VISUALS` |
| `segments` | 每行 `id / finalRange / sourceRanges / kind=CAPTION或EVENT / text / chapter / note / questionIds`；源引用为 `file / start / end`，正式数据的 `file` 为绝对路径，可多项 |
| `visuals` | `id / segmentIds / mode=BASE或LOCAL或SIDE或FULL / status=PENDING或REVISED或CONFIRMED / title / reason / summary / visibleRanges / handoff / phases / assets`；可选 `materialPlan / feedbackHistory / groupId` |
| `phases` | `range / cue / action / camera / sound`，明确口播触发与动作，不要求把短设计硬拆成长表 |
| `assets` | `id / label / use / status=READY或MISSING或PLANNED / path / source`；实际可预览图片用绝对 `path`，用途不能只写文件名 |
| `questions` | `id / question / status=OPEN或RESOLVED / targets`，可附 `category / context / suggestion / resolution` |
| `sourceDecisions` | 原始素材全范围的 `id / sourceRanges / text / decision=KEEP或DELETE或QUESTION / reason` |

```bash
node scripts/pre-edit-review.mjs /绝对路径/分析/预剪辑审稿.json /绝对路径/分析/预剪辑审稿.html
```

模板实现固定在 `预剪辑时间轴模板.html`，生成不需要网络或安装依赖。实际图片以轻量 PNG/JPEG/WebP/GIF 预览嵌入 HTML，合计不超过 12 MB；大图提供预览路径，`source` 保留外部原图位置，不复制源视频。缺图片如实写 `MISSING` 或 `PLANNED`，不能用示意图冒充已到位资产。示例专用的 `SCHEMATIC / diagram` 不用于正式数据。

反馈先在对话中提出，或在网页疑难/方案下填写后复制、下载交给执行 AI。浏览器草稿仅暂存本地，不会自动回传、改 JSON、写入 Cap 或产生批准。执行 AI 核对导出意见中的作品、修订与内容标识，将反馈合入唯一 JSON，处理字幕、时码、布局与素材依赖，再重新生成同一个 HTML；不同修订/内容的浏览器草稿不自动混用。方案整体确认机制沿用下文规则。任务包 `edit.preEditReview.documentPath` 指向用户实际看过的 HTML，控制文档记录 JSON 路径与当前修订。

验收必须确认：源时码未丢、无字幕事件仍在、跨字幕动画的左右对应正确、疑难跳转可用、图片可读、备注与修改可追溯、无横向溢出。生成器只检查结构和范围，不证明真实语义、源审稿覆盖完整或用户已经同意；这些仍由执行 AI 核实。

多个视频共用一条合并后 SRT 时，在审稿前先登记每个源视频的精确时长和累计偏移：

```text
source-1  全局 00:00.000 起，局部时间 = 全局时间
source-2  全局从 source-1 时长起，局部时间 = 全局时间 - source-1 时长
source-3  全局从 source-1 + source-2 时长起，以此类推
```

源文件分界点必须单独抽查前后句。分辨率不同的源视频先统一画布，并默认用等比缩放加留边保留完整操作区域。

## 审稿决策表

```text
| ID | 开始 | 结束 | 正文 | 状态 | 理由 |
|---|---:|---:|---|---|---|
| s1 | 00:00.000 | 00:02.000 |  | 保留 | 交代背景 / 进入话题 |
| s2 | 00:02.000 | 00:04.000 |  | 删除 | 重复试说 / 废弃起头 |
| s3 | 00:04.000 | 00:06.000 |  | 待确认 | 节奏价值和信息价值需要取舍 |
```

状态只用三类：

- `保留`：独立信息点、背景、转折、论据、完整句尾、情绪表达、必要呼吸。
- `删除`：空白停顿、重复试说、口误重说、废弃半句、无意义连接、离题支线。
- `待确认`：有内容价值但可能影响节奏，或有节奏价值但可能偏离主线。

## 预期成片字幕与画面安排

先在文档中完成虚拟初剪、虚拟精剪、字幕切分与顺句，按保留词流连续计算预期成片时间。这里的目标时间是审稿方案，批准冻结后才成为正式 T2；每条须能回溯源片段与词范围，不沿用被删除的 ASR 条目。

| 成片片段 ID | 源文件/源时码/词范围 | 预期成片起止 | 最终拟用字幕 | 画面安排/动画单元 ID |
| --- | --- | --- | --- | --- |
| C01 | 填实际源引用 | 填实际映射结果 | 填完整意群 | 保留人物/录屏/证据/动画 A01 |

### 动画与画面方案（纯剪辑填不适用）

| 单元 ID / 对应讲述 | 组合片段及理由 | 预期显示起止与边界理由 | 展示方式与目的 | 素材及准备情况 | 方案状态 |
| --- | --- | --- | --- | --- | --- |
| A01 / 填对应几句口播 | 填 C01–C03 等实际引用及共同解释的问题 | 分别写内容时间与画面可见窗口；不连续窗口分开列 | 局部/全幅/保留底画；为什么这样更易理解 | 图片/截图/文字/图形，真实来源或尚缺项 | 待讨论/已修改待确认/已确认 |

每个动画单元在表下补一小段效果说明，复用同一 ID：

```text
A01 画面效果：从什么画面开始 → 哪句口播触发什么变化 → 最后停在什么结果。
材料怎么用：哪些图先出现、哪些对比或放大、哪些标签必须出现；是否需要另取截图。
人物与操作：覆盖哪些区域、保护哪些内容、何时交还真实录屏/人物。
镜头与声音：镜头是否移动及目的；音效何时出现/不需要音效，声音实现或素材缺口。
可调整细节：不改变以上观看效果的缓动、轻微间距、帧取整等留给执行 AI。
```

无动画区间也写明保留人物、操作或证据的安排；不要求每句配动画，也不因画面静止就遮住人物。多个相邻成片片段可共用一个动画，不连续区间不可用一个大范围吞掉中间演示。

### 讨论、修改与整份批准

| 对应单元/剪辑项 | 用户意见 | 当前方案已怎样修改 | 尚待确认 |
| --- | --- | --- | --- |
| 填稳定 ID | 填实际反馈 | 同步修改上文效果、材料用途、节拍、时间与衔接 | 无 / 明确取舍 |

例：收到“这里加我给的三张截图”，应更新三张图的展示顺序、放大对象和阅读时间；如果原窗口不够，先改方案讨论，不自行延长已确认剪辑或压缩到看不清。

整份批准前集中核对：

- 源内容保留/删除、麦克风与系统声音分类、预期成片字幕、专名及样式已明确。
- 动画对应片段、显示起止、进入—变化—收束、覆盖方式、素材用途与音效安排已明确。
- 用户反馈已写回当前方案；未取得的材料已明确获取安排或经同意的替代方案。
- 所有影响成片的待确认项已解决；用户批准的是当前整份剪辑与画面方案。

```text
批准状态：PENDING / APPROVED
批准范围：EDIT_ONLY / EDIT_AND_VISUALS
批准对应的审稿修订：
用户整体批准回执：填真实对话定位，不得由 AI 自行宣布同意
```

单项同意只解决单项。后续反馈若改变画面内容、图片用途、显示起止、剪口或音效，应更新修订并重新取得整体批准；不重新询问已明确授权且不改变观看效果的实现细节。确认前仅做审稿必要的读取、分析和文字设计，默认不开始剪辑写入、动画代码制作或媒体生成；用户单独授权的试样只在该范围内执行。

## 剪辑清单

```text
| # | startMs | endMs | subtitleIds | 说明 |
|---|---:|---:|---|---|
| 1 | 0 | 2000 | s1 | 保留背景入口 |
| 2 | 4000 | 6000 | s3 | 保留更顺的一版表达 |
```

生成剪辑清单前要复查：

- 只读保留内容，是否还能听懂完整主线。
- 每个话题入口是否有背景，不会突然跳进答案。
- 每个独立信息点是否至少保留一版。
- 有没有为了剪短删掉只出现一次的完整句尾、情绪补充或限定条件。
- 句间无讲话停顿是否尽量压到 0.1 秒以内。
- 字面重复是否其实对应连续操作；不要把教程中的必要动作提示误判为废弃重录。
- 如果用户只要求粗剪，交付中是否没有擅自加入字幕、动画或画面包装。
