# 图表关系表达规则

本文件用于沉淀口播视频中的图表、箭头、流程、关系和信息密度表达规则。目标是避免画面停留在“文字 + 方框卡片”，让画面真正帮助观众理解结构、因果、流程和判断。

## 1. 核心原则

画面不是把文字摆好看，而是把关系讲清楚。

优先使用：

- 流程图。
- 箭头和连接线。
- 因果关系图。
- 层级关系图。
- 包含关系图。
- 漏斗图。
- 时间轴。
- 条形图。
- 折线图。
- 决策树。
- 象限图。
- 闭环图。
- 标注图。

不要长期只使用：

- 大标题。
- 两列卡片。
- 普通 checklist。
- 没有关系的独立方框。

## 2. 图表不是装饰

每个图表必须回答一个信息任务：

```text
这是流程吗？
这是因果吗？
这是对比吗？
这是包含关系吗？
这是趋势吗？
这是选择路径吗？
这是输入输出关系吗？
```

如果图表不能说明关系，只是为了让画面显得丰富，就不要使用。

## 3. 常用图解工具

### 3.1 流程图

适合：步骤、生产链路、发布流程、复盘流程。

要求：

- 有明确方向。
- 有节点。
- 有箭头或路径线。
- 节点应包含“动作 + 产物”。

### 3.2 箭头 / 连接线

适合：表示顺序、因果、转化、归属、推进。

要求：

- 每条箭头都要有意义。
- 箭头最好跟随口播逐步绘制。
- 不要用无意义箭头装饰画面。

### 3.3 包含关系 / 圆圈关系

适合：大系统包含小模块、主框架包含子步骤、账号方向包含内容形态和复盘指标。

可用形式：

- 同心圆。
- 大圆包小圆。
- 分层容器。
- 环形模块。

### 3.4 漏斗图

适合：注意力链路、传播链路、发布效果。

示例：

```text
3 秒停留 -> 完播 -> 互动 -> 复盘
标题点击 -> 封面停留 -> 内容观看 -> 评论反馈
```

### 3.5 条形图 / 柱状图

适合：相对强弱、门槛高低、复用性、风险程度。

没有真实数据时，只能做结构示意或相对表达，不要写具体数字。

### 3.6 折线图 / 趋势线

适合：长期迭代、复盘趋势、上一条到下一条的变化。

没有真实数据时，用“趋势示意”，不要伪造数值。

### 3.7 决策树

适合：路线选择、先做什么、不先做什么、主路线和辅助路线判断。

### 3.8 象限图 / 矩阵

适合：路线分类、投入产出、风险收益、长期短期。

### 3.9 标注图

适合：解释截图、PPT、工具界面、发布页面、视频画面。

要求：

- 标注必须指向具体区域。
- 标注文字短。
- 标注顺序跟口播一致。

## 4. 信息密度规则

一页画面不能太空。

如果一个 1920x1080 画面只有：

```text
1 个大标题 + 2 个大框 + 3 行短文字
```

通常会显得信息不足。

推荐结构：

```text
1 个主标题
1 个主图解结构
3-7 个信息节点
1-3 条关系线 / 箭头 / 连接
1 个当前重点高亮
1 个结论或下一步动作
```

增加信息量的方式不是堆长段文字，而是增加：

- 小标签。
- 输入 / 输出。
- 产物说明。
- 判断标准。
- 状态灯。
- 指标名。
- 箭头和连接。
- 局部标注。
- 层级关系。

## 5. 停留时间规则

大图解必须有足够阅读时间。

参考：

```text
小提示 / 单个标签：1.5-3 秒
单张卡片：3-6 秒
一组卡片：8-15 秒
完整流程图 / 关系图 / 控制台：至少 15-30 秒
复杂场景：覆盖对应 ASR 段落的大部分时间
```

大页正确做法：

```text
框架先出现并保持
局部内容随口播逐步填入
当前节点高亮
旧节点保留但降权
最后完整结构停留，让观众看懂
```

大页错误做法：

```text
出现 3 秒 -> 直接切走
```

## 6. 标题断行规则

中文标题必须人工控制断行。

允许断行：

- 标点后。
- 语义停顿处。
- 并列结构之间。
- “不是 A，而是 B”中间。
- “先 A，再 B”中间。

禁止断行：

- 关键词中间。
- 固定短语中间。
- 数字和单位之间。
- 动宾结构中间。
- `AI 音乐`、`内容闭环`、`发布复盘` 这类核心概念中间。

推荐在 HTML 中显式使用 `<br />` 控制标题断行。

## 7. 质检问题

输出前检查：

- 这一屏有没有图解关系，还是只有文字卡片？
- 箭头、连线、图表是否表达了真实关系？
- 大图解是否有足够停留时间？
- 信息密度是否足够，不显空？
- 标题是否在自然语义处断行？
- 没有真实数据时，是否避免编造数字？
- 观众是否能通过图形看懂口播没完全展开的结构？
