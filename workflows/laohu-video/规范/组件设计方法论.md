# 组件设计方法论

本文件定义 Remotion / HyperFrames 可复用组件的顶层判断方法。组件不是行业皮肤，也不是装饰效果；它用稳定的信息结构帮助观众理解、相信、选择、行动和记忆。

## 1. 四轴判断

设计或选择组件前，必须分别判断：

```text
communicationGoal：explain / compare / prove / choose / guide / warn / review / remember
emotionalTone：clear / calm / confident / energetic / futuristic / urgent / satisfying
informationShape：sequence / hierarchy / comparison / network / timeline / quantitative / transformation
motionIntensity：low / medium / high
```

四轴不能混为一个“风格”。例如流程图的信息形状是 `sequence`，目标可以是 `explain`，情绪可以同时是 `futuristic`。这样同一组件可以更清楚或更炫酷，但不需要复制成两个组件。

禁止先按科技、财经、知识等博主类型套模板。行业只能提供案例，不能决定组件。

## 2. 组件边界

一个公开组件家族只负责一种稳定的信息结构：

```text
组件家族：稳定的信息结构
mode：同类结构的表达变体
stylePreset：配色、字体、密度、线条和动势
config：这一次具体讲什么
```

内容变化但关系不变时复用组件；关系本质变化时更换组件。不要把流程、数据、矩阵、截图标注全部塞进一个万能组件。

内部视觉基础单元可以复用舞台、标题、卡片、连接线、图表轴、安全区和动效曲线，但这些基础单元不作为用户选择的公开组件。

## 3. 导演级与渲染级接口

导演级接口保留绝对时间和来源：

```text
AnimationBrief：ASR、时间段、用户要求、参考材料、输出方式
NarrativeBeat：时间、口播摘要、画面任务、屏幕内容、来源
ComponentRecommendation：主推荐、备选、理由、观众感受、风险、缺口
```

渲染级 `ComponentConfig` 使用相对帧和稳定字段：

```text
component / mode
title / subtitle / conclusion
communicationGoal / emotionalTone / informationShape / motionIntensity
stylePreset / renderMode / durationInFrames
items / links / highlightOrder / supportingLabels / mediaSrc
```

具体 Zod schema 以 `模板/remotion-assets/workspace/src/schemas/` 为准。文档不能创造代码里不存在的字段。

## 4. ASR 理解与画面补充

用户指定时间段时，不能只读取该段孤立字幕。默认读取：

```text
整段主题
目标时间段
前后上下文
用户提供的原始素材
当前作品控制文档
```

长段先拆成 3-7 个叙事节拍：引入、逐步建立、关系变化、收束和最终停留。若一段同时存在两种本质不同的信息结构，使用多个组件顺序组合，不让一个组件承担所有任务。

画面可以补充 ASR 没有说完的解释，但每条补充必须标记来源：

```text
asr：当前口播直接说到
context：根据前后文归纳
source-doc：来自用户材料，必须带 ref
editorial：帮助理解的编辑性解释
illustrative：仅为示意，不代表事实或真实数据
```

事实、数字、案例和外部结论不能只标 `editorial`。没有来源时应删掉、标成示意或向用户确认。

## 5. 组件推荐机制

顶层动画导演读取 `规范/组件规则.md`，按以下优先级判断：

```text
1. 信息结构是否匹配
2. 是否完成当前沟通目标
3. 时间长度和信息数量是否容纳得下
4. 情绪和动势是否适合口播
5. 组件是否已经达到可复用状态
```

用户明确指定方向，或主候选明显优于其他候选时，可以直接生成配置。存在真实视觉取舍时，输出一个主推荐和两个备选，必须说明：展示结果、观众感受、适配理由、需要补充的内容、风险。

禁止因为组件最近用过或视觉炫酷而优先选择。

## 6. 组件缺口与进化

现有 schema 无法满足需求时，依次判断：

```text
一次性配置：只影响当前作品，不进入长期组件
组件升级：信息结构没变，新增可选字段或模式能长期复用
新组件：信息结构已经改变，旧组件继续扩展会失去边界
拒绝：需求会降低可读性、真实性或让组件职责混乱
```

提出升级时说明缺口、新字段、观众收益、兼容性和复杂度风险。用户确认后同步更新代码 schema、组件说明书、登记表、示例和测试。

## 7. 引擎与输出

组件本身不依赖 HyperFrames。根据作品选择：

```text
standalone：Remotion 独立片段或独立成片
asset：透明 WebM、PNG 序列或完整图解资产
both：同一配置同时提供独立片段和外部调用资产
```

HyperFrames 是可选总装工具，不是 Remotion 的强制前置或最终出口。两者组合时，必须替换明确区域，禁止把 Remotion 贴在已有同类图解上造成重复。

## 8. 动画与可读性底线

- 复杂组件少于 6 秒时应缩减内容或改用简单组件。
- 最终完整态至少停留 30 帧或总时长 20%，取更长者。
- 主标题、关键判断和核心节点承担手机缩小后仍可理解的任务；辅助小字不能承载唯一关键信息。
- 中文标题不能留下孤字或难看断行。
- 组件必须使用显式帧驱动动画，禁止 CSS transition、CSS animation、随机数和无限循环。
- 完成后至少截图入场、展开、收束、最终态；同时检查 1920×1080 和 390×219 缩略观看。
- 发现空白、遮挡、重复、错误暗示或内容缺失时，先修正再交付。

## 9. 存储规则

```text
规范/组件规则.md：唯一组件登记表
模板/components/：12 个公开组件家族说明书
模板/remotion-assets/workspace/：共享源码、schema、preset、测试和依赖
.agents/skills/laohu-animation-director/：唯一动画导演 skill
作品/编号/分析/：当前作品推荐与配置
作品/编号/制作/assets/remotion-renders/：当前作品需要保留的渲染结果
```

共享 workspace 只安装一次 `node_modules`。作品目录不重复创建 Remotion 工程，除非需要独立交付、特殊依赖或冻结版本。
