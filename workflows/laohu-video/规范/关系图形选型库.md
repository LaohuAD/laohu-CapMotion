# 关系图形选型库

本文件解决一个具体缺陷：**同一种语义关系，反复只用一到两种图形语言**。三个「机制」镜头都用同一张「多源汇聚」卡、「对比」只有三张卡轮换，属于关系识别正确、表达方式枯竭。

本文件与 `图表关系表达规则.md` 分工不同：那份回答「这段口播属于什么关系、该不该上图解」；本文件回答「已经确定是某种关系之后，这一条还能换成哪几种图形语言」。

选型顺序：

```text
1. 先按口播确定关系类型（查第 1 节）
2. 再查该关系下的候选图形语言（查第 3 节）
3. 排除掉本片最近用过的（查第 4 节轮换规则）
4. 从剩下的里选与这句口播最贴的
```

来源标注约定，全文使用三种标记：

```text
【体系】= 有公开权威体系、论文、教科书或行业规范支撑
【经验】= 从业者经验、常见做法，公开出处多为教程、博客或作品惯例
【推导】= 本文件从【体系】原则推出的规则，公开来源里没有原话
```

## 1. 关系类型学：已有权威体系

不要自创一套分类再称其为标准。以下四套是有公开出处的分类体系，本节只做转述与对照。

### 1.1 四套权威体系及其原始分类

**Jacques Bertin《Semiology of Graphics》(1967/1983) — 视觉变量**【体系】

Bertin 提出图形记号可以被分解为若干「视觉变量」，并给出每个变量能表达的数据性质。这是所有后续编码理论的地基。

变量清单：位置（position，两个平面维度）、尺寸（size）、明度/值（value）、纹理（texture）、颜色/色相（color/hue）、方向（orientation）、形状（shape）。

来源：[Tamara Munzner, Visualization Analysis & Design 课程讲义](http://people.cs.ubc.ca/~tmm/talks/minicourse14/halfdaycourse14.pdf)、[Bertin 视觉变量法文研究文献](https://hal.science/tel-02120402v1/file/HDR%20Cecile%20REGNAULT%20Volume%202.pdf)

**Tamara Munzner《Visualization Analysis & Design》(2014) — What-Why-How 与通道有效性**【体系】

Munzner 把可视化设计拆成三问：What（数据是什么类型）、Why（用户要完成什么任务）、How（用什么视觉编码）。其中与「两个概念之间的关系」最相关的是她对**通道（channel）**的分类：

- 同一通道内的编码方式：位置、尺寸、明度、色相、方向、形状、纹理
- 能表达关系而非只表达数量的通道：**包含（containment）、连接（connection）、相似（similarity）**，以及用于表达数量差异的**分组（grouping）**与位置对齐

她还给出两条关键判据：**表达性（expressiveness）**——通道必须能表达该属性的类型（比如色相不能表达有序数量）；**有效性（effectiveness）**——同一属性用不同通道，判断准确度不同，顺序大致为：位置 > 长度 > 角度/斜率 > 面积 > 体积 > 明度/色相。

来源：[Munzner, Marks & Channels 讲义](https://www.cs.ubc.ca/~tmm/courses/436V-20/slides/marks.pdf)、[What-Why-How 半日教程](http://people.cs.ubc.ca/~tmm/talks/minicourse14/halfdaycourse14.pdf)、[VAD-2021 讲义（含通道排序）](https://www.cs.ubc.ca/~tmm/talks/vad/VAD-2021.pdf)

**William Cleveland & Robert McGill (1984) — 图形感知的基本任务排序**【体系】

对「人眼判断哪种编码最准」给出实验排序，从最准到最不准：位置（共同刻度）、位置（非共同刻度）、长度、角度/斜率、面积、体积、色彩明度、色彩饱和度。

这条排序直接决定：表现「量」的对比时，长度和位置优于面积和颜色深浅。

来源：[Cleveland & McGill, Graphical Perception（PDF）](http://info.slis.indiana.edu/~katy/S637-S11/cleveland84.pdf)、[Cleveland & McGill 层级排序转述](https://core.ac.uk/download/pdf/235078899.pdf)

**Jon Schwabish & Severino Ribecca — The Graphic Continuum (2014)**【体系】

将近 90 种图形归入**六大类**：Distribution（分布）、Time（时间）、Comparing Categories（类别比较）、Geospatial（地理空间）、Part-to-Whole（部分与整体）、Relationships（关系）。

来源：[PolicyViz: The Graphic Continuum](https://policyviz.com/2014/09/09/graphic-continuum/)

**Financial Times Visual Journalism Team — Visual Vocabulary**【体系】

在 Graphic Continuum 基础上细化为**九大关系族**：Deviation（偏离）、Correlation（相关）、Ranking（排序）、Distribution（分布）、Change over Time（随时间变化）、Part-to-Whole（部分与整体）、Magnitude（量级）、Spatial（空间）、Flow（流动）。每个族给出推荐图形与注意事项。

来源：[FT Visual Vocabulary 官方 README（含九族全部条目与注意事项）](https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md)、[九族完整图表清单与禁区（MIT 重述）](https://github.com/eforus-overseer/visual-vocabulary-skill/blob/main/skills/visual-vocabulary/references/chart-taxonomy.md)

**Ralph Lengler & Martin Eppler — A Periodic Table of Visualization Methods (2007)**【体系】

按**用途领域**六分：Data Visualization、Information Visualization、Concept Visualization、Strategy Visualization、Metaphor Visualization、Compound Visualization。另外每条方法都标注了「过程型 / 结构型」这一维度——过程型强调先后与因果，结构型强调同时并存的组成。

来源：[A Periodic Table of Visualization Methods（原站，图表为图片，需浏览器查看）](https://www.visual-literacy.org/periodic_table/periodic_table.html)、[PDF 版](https://www.visual-literacy.org/periodic_table/periodic_table_as_pdf.pdf)

### 1.3 关系必须落到视觉通道，否则选型没有依据

从 Munzner 的通道理论出发，每一种关系都有它**天然对应的视觉通道**。选型时先定通道，再定图形，才不会退化成「换汤不换药的两列卡片」。下表是本文件依据 Munzner 与 Bertin 的通道清单整理的对应关系【推导，依据 Munzner 通道分类与 Bertin 视觉变量】：

| 关系 | 天然通道 | 换成别的通道就是另一种表达 |
| --- | --- | --- |
| 对比 | 位置对齐 + 长度（Cleveland 排序中准确性最高的两项） | 换成面积、色深、角度，准确性下降 |
| 量级 | 长度、面积 | 位置只表达序，不表达量 |
| 相关 | 二维位置（散点） | 换成颜色矩阵（XY heatmap）会损失精度 |
| 排序 | 位置（有序轴） | 长度可兼表达量，但排序不必用长度 |
| 分布 | 位置 + 面积（密度） | 换成色深（热力图）损失精度但更紧凑 |
| 时间 | 位置（水平轴） | 角度（径向/表盘）能表达周期，不适合比较 |
| 组成 | 面积 + 包含（enclosure） | 包含通道是部分与整体的天然编码 |
| 层级 | 包含（enclosure） | 连接（树线）是另一种表达 |
| 连接 | 连接（connection） | 位置邻近（相似/分组）是弱化版 |
| 流动 | 长度 + 连接（带宽） | 位置（地图上的箭头）用于空间流动 |
| 汇聚 / 分叉 | 连接 + 方向 | 面积（漏斗）是另一种表达 |
| 映射 | 位置邻近 + 连接 | 对齐（并列两栏）是弱化版 |
| 循环 | 路径 + 方向 | 位置（环形布局）是形式而非通道 |
| 因果 | 连接 + 方向 | 位置次序（上下）是弱化版 |
| 并列 | 分组（grouping）+ 位置 | 包含（同一个容器）用于强调同层 |

**这张表的用法**：当同一个关系要换一种图形语言时，最省力也最不容易出错的做法是**先换通道，再换图形形状**。「多线汇一点」和「漏斗」看着完全不同，本质上都是连接 + 方向通道；而「两列卡片并置」与「同一张卡上下分屏」都在用位置通道，换形状不换通道，观众感受到的仍然是一张卡。

## 2. 从通道到图形的具体依据

本节的映射关系来自 FT Visual Vocabulary 与 Graphic Continuum 的原始归类，不是本文件发明。逐条列出，供第 3 节引用：

| 图形 | FT 归入的族 | 依据 |
| --- | --- | --- |
| Diverging bar / Diverging stacked bar / Spine chart / Surplus-deficit filled line | Deviation | [FT README](https://github.com/Financial-Times/chart-doctor/blob/main/visual-vocabulary/README.md) |
| Scatterplot / Bubble / Connected scatterplot / XY heatmap / Line+Column | Correlation | 同上 |
| Ordered bar / Ordered column / Slope / Lollipop / Dot strip / Ordered proportional symbol | Ranking | 同上 |
| Histogram / Boxplot / Violin / Population pyramid / Dot strip / Dot plot / Barcode / Cumulative curve | Distribution | 同上 |
| Line / Column / Stock price / Slope / Area / Fan / Calendar heatmap / Priestley timeline / Circle timeline / Seismogram | Change over Time | 同上 |
| Stacked column / Proportional stacked bar / Pie / Donut / Treemap / Voronoi / Arc / Gridplot / Venn / Waterfall | Part-to-Whole | 同上 |
| Column / Bar / Paired / Proportional symbol / Isotype / Radar / Parallel coordinates | Magnitude | 同上 |
| Choropleth / Proportional symbol map / Flow map / Contour / Cartogram / Dot density / Heat map | Spatial | 同上 |
| Sankey / Waterfall / Chord / Network | Flow | 同上 |

FT 同时给出了各族的关键禁区，选型时必须一起看【体系】：

- 条形/柱形比较量级时**必须从 0 起**；折线图的主题是「变化」而非「水平」，可以不在 0。
- **画出来的关系会被读成因果关系**，只表达相关性时必须标注，否则观众会自行推断因果。
- 组成类图形在分段变多后迅速失效；饼图与堆叠条超过少数几段就该换成排序条或矩形树图。
- 地图回答的是「在哪」而不是「多少」；等值线图（choropleth）应编码比率而非总量，否则画出来的其实是人口分布。
- 象形图（isotype）只能表示整数单位，不能把图标切开表示小数。

## 3. 关系 × 图形语言选型表

每格给出：**图形语言** | 适合什么 | 什么时候别用。

### 3.1 对比 / 差异

| 图形语言 | 适合什么 | 什么时候别用 | 来源 |
| --- | --- | --- | --- |
| 左右并置两栏（同一模板镜像） | 两项对等、结构相同的对比 | 当差异不在结构而在程度时，并置会迫使观众自己比，读数不准 | 【经验】 |
| 双轴折线 / 线 + 柱组合 | 一个量（柱）与一个率（线）同时变化的关系 | 第二根轴容易暗示并不存在的相关；两轴刻度可被操纵 | 【体系】FT Correlation |
| 斜率图（两点连线） | 只有两个时间点或两个类别的排名变化 | 数据点多于三个时会误导读者的趋势判断 | 【体系】FT Ranking / Change over Time |
| 背离条（从中轴向两侧延伸） | 围绕某个参照点的正负偏离 | 没有天然参照点（0、目标值、均值）时不要用 | 【体系】FT Deviation |
| 哑铃图 / 背靠背条 | 两组数值成对比较，强调差距本身 | 类别超过 8 个左右时行距会把差距压扁 | 【体系】FT Distribution（Dot plot） |
| 天平 / 杠杆隐喻 | 用支点表达权衡、取舍、代价 | 有精确数值时不要用隐喻替代读数 | 【经验】 |
| 前后分屏（同一位置时间切片） | 改变前后的同一对象 | 前后对象不是同一个时，「前后」框架会误导 | 【经验】 |
| 数字跳变 / 计数动画 | 两个结果值本身是重点 | 数值没有真实依据时，跳变会强化观众对假数字的记忆 | 【经验】 |
| 颜色反转 / 明暗对调 | 强调两项地位互换或性质相反 | 同一画面里已有靠颜色区分的其他编码时会冲突 | 【推导，依据 Munzner 通道可分性】 |
| 划线替换 / 删除重写 | 旧方案被新方案取代 | 两者是并存关系而非替代关系时不要用 | 【经验】 |
| 同一容器内切换高亮 | 差异只在「哪个是当前重点」 | 差异存在于多个维度时，单一高亮承载不了 | 【推导】 |
| 重叠对照（同一坐标系画两条） | 差距是「偏离量」而不是「两个水平」 | 两条线纠缠时读不出各自水平，改用小倍数（small multiples） | 【体系】FT Correlation |

### 3.2 相关 / 共变

| 图形语言 | 适合什么 | 什么时候别用 | 来源 |
| --- | --- | --- | --- |
| 散点图 | 两个连续变量的关系 | 点过多会重叠（overplotting），需要降透明或分箱 | 【体系】FT Correlation |
| 气泡图 | 散点 + 第三个变量编码为面积 | 面积判断精度低，只适合表达大致量级 | 【体系】FT Correlation + Cleveland 排序 |
| 连通散点（按时间连线） | 两个变量的关系随时间演化 | 数据没有清晰推进路径时，连线会造出不存在的轨迹 | 【体系】FT Correlation |
| XY 热力图 | 两个类别维度之间的模式 | 不适合读精确数值 | 【体系】FT Correlation |
| 平行坐标 | 多个变量同时比较 | 变量顺序会显著改变可读性，必须排列得当 | 【体系】FT Magnitude |
| 雷达图 | 多个变量的profile对比 | 轴顺序影响形状，且面积无意义 | 【体系】FT Magnitude |
| 趋势线 + 散点叠加 | 需要指出拟合方向时 | 没有统计依据时不要画拟合线 | 【体系】FT Correlation |
| 因果链条图 | 一个变量通过中间环节影响另一个 | 只有相关性时画成链就是伪造因果 | 【体系】FT 因果警告 |

### 3.3 时间 / 先后

| 图形语言 | 适合什么 | 什么时候别用 | 来源 |
| --- | --- | --- | --- |
| 折线 | 连续时间序列的标准做法 | 数据不规则时应加数据点标记 | 【体系】FT Change over Time |
| 柱形（按时间） | 离散时段，单一系列最清晰 | 多系列柱形随时间会很难读 | 【体系】FT Change over Time |
| 面积图 | 总量的变化 | 想看清各组成部分变化时不要用 | 【体系】FT Change over Time |
| 扇形图（fan chart） | 未来预测的不确定性随时间扩大 | 有确定数据时不要用 | 【体系】FT Change over Time |
| 普里斯特利时间轴 | 起止时间与持续时长都是重点 | 只关心单个时点时过于笨重 | 【体系】FT Change over Time |
| 日历热力图 | 日/周/月周期规律 | 需要精确数值时损失太大 | 【体系】FT Change over Time |
| 圆形时间轴（气泡在时间轴上） | 离散事件、量级不同 | 事件密集时圆会互相遮挡 | 【体系】FT Change over Time |
| 里程碑节点条 | 少量关键节点、非等距 | 节点之间的间隔有语义时才用等距排布，否则会误导时长 | 【经验】 |
| 阶梯进度条 | 线性推进阶段 | 非线性、有回退的流程不要用 | 【经验】 |
| 甘特条 | 并行任务与重叠区间 | 只表达顺序时过于复杂 | 【体系】Data Visualisation Catalogue: Ranges / FT Change over Time |

### 3.4 组成 / 部分与整体

| 图形语言 | 适合什么 | 什么时候别用 | 来源 |
| --- | --- | --- | --- |
| 堆叠条 / 100% 堆叠条 | 少量组成部分 | 超过少数几段即不可读 | 【体系】FT Part-to-Whole |
| 饼图 / 环形图 | 极少量分段的粗略印象 | 人眼比较角度能力差；分段多时换排序条 | 【体系】FT Part-to-Whole |
| 矩形树图（treemap） | 层级型组成 | 小分段难以辨读 | 【体系】FT Part-to-Whole |
| 华夫格 / 网格图 | 整数百分比 | 非整数百分比会误导 | 【体系】FT Part-to-Whole |
| 维恩图 | 集合重叠的示意 | 一般不用于定量 | 【体系】FT Part-to-Whole（原文：Generally only used for schematic representation） |
| 瀑布图 | 增减分量汇总到总量 | 分量之间有强依赖时，逐步累加会失真 | 【体系】FT Part-to-Whole / Flow |
| 弧形 / 半圆席位图 | 席位、配额类构成 | 与地理或时间无关时不要用弧形装饰 | 【体系】FT Part-to-Whole |
| 容器填充（一个容器被逐格填满） | 进度、配额完成度 | 总量不固定时不要用 | 【经验】 |
| 同心圆 / 层层包含 | 层级型的整体与局部 | 需要比较各层大小时，同心圆的面积判断很难 | 【经验】+ Munzner containment 通道 |

## 4. 同一关系下的入出场动画语汇

### 4.1 有公开规范支撑的部分

**时长与缓动是可查的硬数据**，以下直接引用，不是估计值【体系】：

Material Design（旧版，数值明确）：

```text
移动端转场通常 300ms
全屏复杂转场 375ms
元素进入 225ms
元素离开 195ms
超过 400ms 会觉得慢
平板约比手机长 30%；可穿戴约短 30%
桌面端 150–200ms
```

四条缓动曲线（Material 命名 → CSS）：

```text
标准曲线（ease in out）：cubic-bezier(0.4, 0.0, 0.2, 1)
减速曲线（ease out，元素进入）：cubic-bezier(0.0, 0.0, 0.2, 1)
加速曲线（ease in，元素离开）：cubic-bezier(0.4, 0.0, 1, 1)
锐利曲线：cubic-bezier(0.4, 0.0, 0.6, 1)
```

Material 同时给出「动态时长」原则：时长应按移动距离、元素速度和表面变化调整；离开屏幕的元素可以用更短的时长，因为它需要更少注意力。

来源：[Material Design 1: Duration & easing](https://m1.material.io/motion/duration-easing.html)

Material Design 3（现行 token，数值直接取自已发布的样式变量文件）：

```text
时长档位：short1 50 / short2 100 / short3 150 / short4 200
        medium1 250 / medium2 300 / medium3 350 / medium4 400
        long1 450 / long2 500 / long3 550 / long4 600
        extra-long1 700 / extra-long2 800 / extra-long3 900 / extra-long4 1000（单位 ms）
缓动：standard cubic-bezier(0.2, 0, 0, 1)
      standard-decelerate cubic-bezier(0, 0, 0, 1)
      standard-accelerate cubic-bezier(0.3, 0, 1, 1)
      emphasized cubic-bezier(0.2, 0, 0, 1)
      emphasized-decelerate cubic-bezier(0.05, 0.7, 0.1, 1)
      emphasized-accelerate cubic-bezier(0.3, 0, 0.8, 0.15)
      legacy（旧版标准曲线）cubic-bezier(0.4, 0, 0.2, 1)
```

来源：[Material Web 官方 motion token 源文件](https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-sys-motion.scss)、[M3 Easing and duration](https://m3.material.io/styles/motion/easing-and-duration/applying-easing-and-duration)（页面为 JS 渲染，正文需浏览器打开）

```text
productive（高效、克制）：用于用户需要专注完成任务时——按钮状态、下拉、展开信息、渲染数据表和可视化
expressive（表现力强、明显）：只用于偶发的重要时刻——打开新页面、点击主操作、动的本身就是含义时
```

Carbon 明确写了使用配比原则：「**把表现性动效留给偶发的重要时刻**，以更好地抓住注意力，并给高效体验提供一个节奏性的休息」。这是本项目能找到的、最接近「不要一直用同一种强度」的公开规范原话。

Carbon 的缓动三型与时长 token：

```text
标准缓动（元素全程可见）：productive cubic-bezier(0.2, 0, 0.38, 0.9) / expressive cubic-bezier(0.4, 0.14, 0.3, 1)
进入缓动（元素入场）：productive cubic-bezier(0, 0, 0.38, 0.9) / expressive cubic-bezier(0, 0, 0.3, 1)
退出缓动（元素离场）：productive cubic-bezier(0.2, 0, 1, 0.9) / expressive cubic-bezier(0.4, 0.14, 1, 1)

duration-fast-01      70ms   按钮、开关等微交互
duration-fast-02      110ms  淡入等微交互
duration-moderate-01  150ms  微交互、小展开、短距离移动
duration-moderate-02  240ms  展开、系统沟通、toast
duration-slow-01      400ms  大展开、重要系统通知
duration-slow-02      700ms  背景变暗
```

Carbon 还要求**不要使用暗示弹跳、拉伸或急停的缓动曲线**，并把线性运动判为「对人眼不自然」。

来源：[Carbon Motion Overview（仓库源文件）](https://github.com/carbon-design-system/carbon-website/blob/main/src/pages/elements/motion/overview.mdx)、[Carbon Motion 页面](https://carbondesignsystem.com/elements/motion/overview/)、[IBM Motion Generator](https://ibm.github.io/motion/)

NN/g 的时长区间与重复频率原则【体系】：

```text
大多数动画时长在 100–500ms 之间，取决于复杂度和移动距离
简单反馈（勾选框、开关）约 100ms，感觉是「立即」
涉及较大画面变化（如模态进入）200–300ms
500ms 开始感觉拖沓；100–400ms 是常用区间，400ms 已算非常慢
「动画越频繁被遇到，就应该越细微、越短」（the more frequent the animation, the more subtle and shorter you'll want it to be）
「动画太长远比太短更常见」（It is far more common for animations to be too long than too short）
```

NN/g 同时给出可动画的属性清单：opacity、position、scale、color、shape、blur、rotation；并指出**弧线路径通常比对角直线更自然**（与 Carbon 的圆角路径规则一致）。

来源：[NN/g: Executing UX Animations: Duration and Motion Characteristics](https://www.nngroup.com/articles/animation-duration/)

**动画过渡的分类，有论文支撑**【体系】：

Jeffrey Heer 与 George Robertson 的《Animated Transitions in Statistical Data Graphics》(IEEE TVCG / InfoVis 2007) 明确提出了**过渡类型的分类法（a taxonomy of transition types）**，并给出设计原则，还做了两组对照实验，结论是动画过渡能显著提升图形感知。论文里区分了**直接插值（direct interpolation）**与**分阶段过渡（staged transition）**——论文摘要页给出的例子是：从散点图过渡到条形图时，上路径直接在两态之间插值，下路径分两阶段：先把点移到各自的 x 坐标并更新 x 轴形成点图，再把点形变成条。

这条对本地流程直接可用：**同一组元素在两态之间做形变时，分阶段（先归位、再变成）比直接插值更容易被看懂。**

来源：[Stanford Vis Group: Animated Transitions in Statistical Data Graphics](http://vis.stanford.edu/papers/animated-transitions)、[UW IDL 论文页](https://idl.cs.washington.edu/papers/animated-transitions/)、[ACM DL 条目](https://dl.acm.org/doi/10.1109/TVCG.2007.70539)

**序列与错峰，有规范数值**【体系】：

Carbon 的 choreography 给出三条可直接落地的规则：

```text
错峰：多个元素入场时把入场时间分散开，而不是一次全部出现
      表格内容错峰 20ms 就能显著降低认知负荷
      根据错峰元素数量调整间隔，但总时长仍应控制在 500ms 以内
路径：元素在网格上运动，路径不跑对角线
      横向与纵向动画错开时间，形成带圆角的路径；不这样做会得到生硬的直线对角线
序列：按内容类型排序入场——静态内容（外壳、导航）→ 静态内容（正文、标题、图片）→
      动态内容（表格数据、查询结果）→ 主操作 → 动画内容（数据可视化）
```

同一页还给出两条与「避免单调」直接相关的一致性规则：

```text
语义一致性：承载相同含义或相同功能的元素，用相同的动效；含义不同则动效不同
刻意的不一致：当视觉上相似的两个动作在含义上有别时，刻意使用不同的动效来强调差别；
            一般「顺向的运动」表示确认，「反向的运动」表示取消
```

来源：[Carbon Motion Choreography（仓库源文件）](https://github.com/carbon-design-system/carbon-website/blob/main/src/pages/elements/motion/choreography.mdx)

**入场/出场运动的通用分类**，公开且可用的是 Disney 十二原则【体系（教科书结论，公开整理页可引）】。与「入场/出场」直接相关的条目：

```text
Anticipation（预备动作）：正式动作之前先有一个反向的小动作
Staging（场面调度）：一次只让观众看一件事，用构图和动作引导注意力
Straight ahead / Pose to pose：逐帧推进 vs 关键姿态推进
Follow through & overlapping action（跟随与重叠动作）：主体停止后附属部分继续运动
Slow in & slow out（慢入慢出）：动作两端减速
Arcs（弧线）：自然运动沿弧线，不沿直线
Secondary action（次要动作）：辅助主动作，不抢主体
Timing（节奏）：帧数决定重量与情绪
Exaggeration（夸张）：放大以传达本质
Solid drawing / Appeal：立体感与吸引力
```

来源：[Frank Thomas & Ollie Johnson《The Illusion of Life》原则的公开整理](https://www.studiobinder.com/blog/what-are-the-12-principles-of-animation/)

**尚未找到公开可引用的部分**，必须明确说明：

- **未找到**任何公开规范给出「哪种入场动画对应哪种语义关系」的对照表。Material、Carbon、Apple HIG、NN/g 组织动效的方式是「按用途/强度/时长」，不是「按关系类型」。因此第 4.2 节的对照是【推导】，依据的是第 1.3 节的通道理论、Carbon 的语义一致性原则与 Disney 的 staging / anticipation。

### 4.2 关系 × 入出场动画对照【推导】

推导链条：**入场动画应当把该关系的视觉通道显式演出来**；如果关系是「连接」，入场就该演出连接这个动作本身，而不是让元素淡入后静态地摆在那里。

| 关系 | 入场应演出的动作 | 候选入出场语汇 | 不要用 |
| --- | --- | --- | --- |
| 对比 | 先建立两个参照物，再显出差 | 交错登场（两侧先后 100–200ms）→ 共同高亮 → 差异项脉冲；或从中间中轴向两侧生长（背离条）；或同一元素瞬移换位 | 两侧同时淡入（差异没有被「发现」，只是被并置） |
| 相关 | 点逐个落到坐标上，再显趋势 | 散点依次落点 → 拟合线沿路径绘制（trim path）→ 离群点脉冲 | 一次性铺满所有点（丢失「关系是被发现的」） |
| 时间 | 沿轴推进 | 路径跟随生长 → 里程碑掉落并停稳（drop & settle）→ 数值滚动 | 整条时间轴淡入 |
| 组成 | 部分拼合进整体 | 碎片吸附拼合 → 容器逐格填充 → 各部分从总量中「切出」 | 各部分各自独立飞入（暗示彼此无关） |
| 层级 | 由外向内或由内向外逐层揭示 | 容器先出现再展开内层（container transform）→ 遮罩揭示 → 逐层缩进生长 | 所有层级同时铺开 |
| 流动 | 沿路径移动 | 粒子沿路径移动 → 带宽从细变粗 → 桑基带状沿路径绘制 | 静态画好再淡入（流的感觉丢失） |
| 汇聚 | 由多个源点向汇点收拢 | 多线依次绘制并汇于一点 → 元素被吸附聚拢 → 汇点最后脉冲放大 → 漏斗从宽端向窄端收束 | 先画好汇点再补线（因果顺序反了） |
| 分叉 | 由源点向外发散 | 单线先绘出，再在分叉处裂开 → 扇形展开 → 逐条支路依次点亮 | 全部支路同时出现（丢失「同一个源」） |
| 映射 | 两侧先立，再连 | 两栏分别入场 → 连线逐条绘制 → 对应项短暂同步高亮；或同位置直接对齐后再做一次位移确认 | 连线先于两端出现 |
| 循环 | 沿环运动且首尾相接 | 环路径生长并回到起点闭合 → 元素沿环循环一圈后停 → 飞轮加速旋转到位 | 一次画出完整圆（看不出是循环） |
| 因果 | 前因先落定，后果随后 | 前因块落定 → 箭头（或触发波纹）沿路径推进 → 后果块被推入或弹出 | 因果两块同时出现（因果顺序被抹掉） |
| 并列 | 同时或等节奏入场 | 统一入场 + 轻微错峰（20ms 级）→ 网格逐格填充 | 每一项用不同动画（违反 Carbon 语义一致性） |
| 量级 | 按量生长 | 条/柱从 0 生长 → 面积从中心放大 → 比例符号缩放 → 数字滚动 | 直接以最终尺寸淡入（量的大小没有被演出来） |
| 分布 | 逐个落点形成形状 | 点逐个落下 → 分箱柱逐步长高 → 密度曲线绘制 | 一次性显示统计图 |
| 空间 | 由全局到局部 | 缩放推进（zoom in）→ 地图定位平移 → 区域逐块点亮 | 无位置关系却用地图动画 |
| 连接 | 节点先立，线后连 | 节点布点 → 连线逐条绘制 → 结构稳定后整体轻微浮动收束 | 线和节点同时放大出现 |

**通用入场语汇清单**（同一关系内可横向替换的「动作」，来源见标注）：

| 语汇 | 动作描述 | 情绪/语义倾向 | 来源 |
| --- | --- | --- | --- |
| 淡入（fade） | 仅改透明度 | 中性、不强调 | 【体系】NN/g 属性清单；Carbon duration-fast-02 |
| 位移滑入（slide） | 从主视觉方向进入 | 明确、有方向感 | 【体系】Carbon choreography: sliding 用于更高层 |
| 缩放进入（scale in） | 由小到大 | 强调、出现 | 【体系】Material deceleration curve 中元素缩放描述 |
| 遮罩揭示（mask reveal） | 内容被逐步揭开 | 揭示、探索 | 【体系】Carbon: 同层用 pushing + mask |
| 擦除（wipe） | 一条边界扫过 | 快速切换、对比 | 【经验】 |
| 生长 / 绘制（draw-on, trim path） | 线条沿路径出现 | 建立、连接、推进 | 【经验】+【推导：对应 Bertin 方向通道】 |
| 坠落停稳（drop & settle） | 落下并回弹停住 | 落地、确定 | 【经验】+ Disney arcs/follow through |
| 弹入（overshoot / spring） | 超过目标再回来 | 活泼、轻快 | 【经验】；注意 Carbon 明确不鼓励暗示弹跳的曲线 |
| 吸附（snap / magnet） | 被吸引到目标位 | 归位、聚合 | 【推导：对应汇聚关系】 |
| 拼合（assemble） | 碎片合成整体 | 从散到整 | 【推导：对应组成关系】 |
| 爆炸/拆解（explode） | 整体炸开为部件 | 拆解机制 | 【体系】Data Viz Project: Exploded View Drawing |
| 形变（morph） | 一个形状变成另一个 | 转化、映射 | 【体系】Material: transforming material；Heer & Robertson staged transitions |
| 容器变换（container transform） | 元素放大成为容器 | 展开、进入下一层 | 【体系】NN/g 描述的形状过渡：圆形按钮扩展为圆角矩形卡片/模态 |
| 翻转（flip） | 沿轴翻转揭示背面 | 两面性、反转 | 【经验】 |
| 路径跟随（path follow） | 沿既定路径移动 | 流程、流动 | 【体系】Disney arcs；Carbon 圆角路径 |
| 逐字/逐条（type-on, stagger） | 按序逐项出现 | 叙述、递进 | 【体系】Carbon 错峰 20ms、总 500ms 内 |
| 粒子汇聚/消散 | 大量小元素集合或散开 | 聚合、消散 | 【经验】；Mayer 连贯原则提示其易成为装饰 |
| 数字滚动（count up） | 数值快速变化到目标 | 结果、达成 | 【经验】 |
| 高亮扫过 | 一条光带扫过关键词 | 强调当前重点 | 【经验】+ Mayer 信号原则 |
| 脉冲放大 | 短暂放大后回落 | 强调、指向 | 【经验】+ Mayer 信号原则 |
| 颜色反转 | 前景背景对调 | 地位互换、性质相反 | 【推导：对应对比关系】 |
| 慢入慢出（easing） | 两端减速 | 自然、有重量 | 【体系】Disney slow in & slow out；Material/Carbon 曲线 |
| 预备动作（anticipation） | 正式动作前反向的小动作 | 期待感、蓄力 | 【体系】Disney anticipation |
| 跟随重叠（follow through） | 主体停后附属部分继续 | 有机、不僵硬 | 【体系】Disney follow through |

**出场语汇**相对少，公开规范里的规则是：**离场用加速曲线，且时长可以短于入场**（Material：元素离开屏幕 195ms，短于进入的 225ms；「离开屏幕的元素可以用更短时长，因为需要更少注意力」）。Carbon 的例外规则值得记住：

```text
元素离开但仍在近旁、随时可能重新出现时（例如侧边面板），应该用标准缓动而不是退出缓动——
让它离开时减速，暗示它只是停在画面外，随时可以被召回。
```

【体系】[Material duration & easing](https://m1.material.io/motion/duration-easing.html)、[Carbon Motion Overview](https://github.com/carbon-design-system/carbon-website/blob/main/src/pages/elements/motion/overview.mdx)

## 5. 避免单调的编排规则

### 5.1 有公开出处支撑的部分

**可引用的原话只有两条**，其余都要自己推导，必须如实区分。

**其一：强度配比**【体系】。Carbon 原文——「把表现性动效留给偶发的重要时刻，以更好地抓住注意力，并给高效体验提供一个节奏性的休息」。这是公开规范里唯一一句直接讲「不要一直用强动效」的规则，且它给的是**定性配比**，没有给次数。

来源：[Carbon Motion Overview](https://github.com/carbon-design-system/carbon-website/blob/main/src/pages/elements/motion/overview.mdx)

**其二：重复频率反比原则**【体系】。NN/g 原文——「动画被遇到的频率越高，就应该越细微、越短」。这条可以直接推出「高频使用的图形语言必须更弱、更快」。

来源：[NN/g: Executing UX Animations](https://www.nngroup.com/articles/animation-duration/)

**其三：认知负荷约束**【体系】。Mayer 的多媒体学习原则里，与「画面变化频率」直接相关的有三条：

```text
连贯原则（Coherence）：排除无关信息，只保留最相关的视觉
信号原则（Signaling）：用色彩、对比和线索强调更重要的信息
分段原则（Segmenting）：把信息分成可消化的段落，而不是一整块连续呈现
时间邻近原则（Temporal Contiguity）：视觉元素应与讲述同时出现，而不是在讲述之前或之后
冗余原则（Redundancy）：图形 + 旁白已经足够，再加屏幕文字会造成过载
```

来源：[Mayer's 12 Principles of Multimedia Learning（Dartmouth 公开整理，原著 Mayer 2009）](https://services.dartmouth.edu/TDClient/1806/Portal/KB/PrintArticle?ID=171655)、[Principles of Multimedia Design, Cambridge](https://www.cambridge.org/core/books/abs/multimedia-learning/principles-of-multimedia-design/F4172C6C1CB040243FDDAC3455245DCB)

**其四：剪辑优先级**【体系】。Walter Murch 的「六准则」，带他自己给的权重：

```text
1. Emotion 情感 —— 这个剪接在此刻会如何影响观众的情绪（51%）
2. Story 故事 —— 这个剪接是否有效推进故事（23%）
3. Rhythm 节奏 —— 剪接点是否在节奏上成立（10%）
4. Eye Trace 视线轨迹 —— 剪接如何影响观众注视点的位置与移动（7%）
5. Two-Dimensional Place of Screen 画面的二维平面（5%）
6. Three-Dimensional Space 动作的三维空间（4%）
```

对画面的直接含义：**当「换个图形语言」与「观众此刻的情感/理解」冲突时，让位的是形式**。这条同时是「为了不单调而乱换」的解药。

来源：[Walter Murch and The Rule of Six（含权重数值）](https://gointothestory.blcklst.com/walter-murch-and-the-rule-of-six-47de34be834a)

**明确未找到**的部分，不要假装有：

- **未找到**任何公开规范写过「同一动效不要连续使用超过 N 次」这类硬性规则。Material、Carbon、Apple HIG、NN/g 均未给出次数上限。
- **未找到**「同一视觉元素不连续使用超过 N 次」的权威出处。
- **未找到**「说明性视频每隔 X 秒必须换一次画面」的有研究支撑的数字。此类数字在营销类博客中常见，但未找到可追溯的研究或规范。
- **未找到**公开的「动效预算（motion budget）」正式定义。

### 5.2 可执行规则【推导】

以下规则的推导依据逐条写在括号里，便于日后推翻或调整，不要把它们当成外部标准。

**R1｜同一关系类型，同一章节内不连续使用同一图形语言。**
依据：Mayer 连贯原则 + 信号原则——重复的视觉形式不再承担信号功能，观众会停止从中提取信息。（这也是本次缺陷的直接对治。）

**R2｜同一图形语言在同一章节内出现不超过 2 次；整片内不超过 3 次。**
依据：NN/g 的重复频率反比原则（高频必须更弱）的镜像用法。**数字是本文件设定的**，不是外部标准；可以按作品长度调整，但一旦设定就写进该作品的控制文档，不要临时改。

**R3｜连续两个镜头之间，至少要换掉以下三者之一：通道、构图、入场动作。**
依据：第 1.3 节的通道理论——只换图形形状而不换通道，观众感受到的仍然是同一个画面。（例：「两列卡片并置」换成「同一张卡上下分屏」不构成有效轮换，两者都是位置通道。）

**R4｜强动效（表现性）占比不超过两成，且不相邻。**
依据：Carbon 的 productive/expressive 配比原则——表现性动效留给偶发的重要时刻，并提供节奏性的休息。（比例为推导值，依据是该原则的定性表述。）

**R5｜同一入场动作连续使用不超过 2 次；第三个镜头必须换入场动作。**
依据：Disney staging（一次只让观众看一件事）与 Carbon 语义一致性原则的反向应用——动效相同会暗示含义相同，若含义不同却沿用同一动效，就是在传达错误的一致性。

**R6｜图形语言的选择必须先由关系类型决定，再排除最近用过的，而不是先选好看的形式。**
依据：FT Visual Vocabulary 的组织原则——按「读者应该看到什么」选图，不按图形形状或习惯选图。

**R7｜画面变化频率以讲述段落为单位，不以秒为单位。**
依据：Mayer 时间邻近原则与分段原则——视觉应与讲述同步并按可消化段落切分。本项目既有规则（`动效规则.md` 第 11 节：超过 45 秒的场景至少 2–4 个中段视觉变化）与此一致，继续沿用，不需要另立秒数阈值。

**R8｜轮换记录必须落在作品控制文档里。**
依据：Murch 的 Rhythm 与 Eye Trace 两条准则都要求剪接点服务于观众的注视轨迹，而注视轨迹只有跨镜头才能判断——所以轮换不能只在单个镜头内部决策。每一条动画方案落表时，同时记下它用的关系类型、图形语言、通道、入场动作四项，让下一个镜头能查重。

### 5.3 轮换查重表（落地格式）

每条动画在控制文档里登记一行，用于 R1–R5 的查重：

```text
| 成片时码 | 口播语义 | 关系类型 | 图形语言 | 主通道 | 入场动作 | 强度（productive/expressive） |
```

查重顺序：

```text
1. 关系类型相同的上一条，图形语言是否相同？相同 → 换图形语言（查第 3 节同关系的其他行）
2. 换了图形语言但通道没换？→ 换成另一个通道的方案
3. 入场动作与前两条是否重复？→ 换入场语汇（查第 4.2 节通用清单）
4. 强度是否连续两次 expressive？→ 本次降为 productive
```

## 7. 落到本项目流程的接入点

**未找到权威体系的部分已在上文逐条标注。** 本节只说明怎么用，不改动既有文件。

1. **动画导演选型时**：先按口播判定关系类型（第 1 节），再从第 3 节同关系的候选里挑，用第 4.2 节确定入场动作。
2. **轮换查重**：按第 5.3 节的表格式在作品控制文档里登记，执行 R1–R5。
3. **与既有文件的关系**：
   - `图表关系表达规则.md` 继续负责「这段口播该不该上图解、图解要回答什么信息任务」，本文件不重复它的内容。
   - `动效规则.md` 继续负责动效层级、节奏、Remotion 实现约束与禁区，本文件不重复它的内容。
   - `动画效果库.md` 是本地已实现的组件清单；选型定下来之后，先查它有没有现成实现。
4. **本文件的自有边界**：它只提供「同一关系还有哪些图形语言可选」，不判断某条作品该不该加动画，也不规定配色与排版。
