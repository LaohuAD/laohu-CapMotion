# Remotion 与 HyperFrames 引擎选择规则

Remotion 和 HyperFrames 都是一等制作工具。二者可以独立使用，也可以按作品组合；不存在“必须先 HyperFrames、最后必须回 HyperFrames”的默认链路。

## 三种工作流

### Remotion 独立

适合参数化组件、复杂图解、整段动画和需要直接导出 MP4/WebM 的内容。

```text
ASR / 素材 -> 动画导演 -> ComponentConfig -> Remotion -> 独立片段或成片
```

### HyperFrames 独立

适合长口播主时间线、快速场景编排、简单 HTML/GSAP 图解和已有工程继续迭代。

```text
ASR / 素材 -> 分镜和节拍 -> HyperFrames -> 预览与成片
```

### 按需组合

适合已有 HyperFrames 长片中需要一个明确 Remotion 高复杂片段的情况。

```text
Remotion 渲染透明或全屏资产 -> HyperFrames 在明确时间段替换对应区域
```

组合不是默认目标。先选择最能稳定交付作品的单一引擎；只有组合能明显提高表达质量时才增加集成成本。

## 选择标准

优先 Remotion：

- 组件需要 React、Zod、数据驱动和长期复用。
- 复杂路径、数据图、关系图、镜头推进、截图聚光或透明前景。
- 需要同一配置输出独立片段和调用资产。

优先 HyperFrames：

- 已有长视频工程主要在调整 ASR 时间和场景顺序。
- 画面结构仍在快速探索。
- 标题、简单清单、基础节点和普通入场即可完成任务。

## Remotion 输出模式

```text
standalone：带完整背景的独立片段
asset：透明 WebM、PNG 序列、静帧或无音频全屏图解
both：同一配置同时输出两种用途
```

共享 workspace：`模板/remotion-assets/workspace/`。依赖只安装一次；作品只保存自己的配置和必要输出。

## 组合约束

- Remotion 必须替换或承担一个明确区域的主表达，禁止叠在已有同类图解上。
- 透明视频进入 HyperFrames 后必须 `muted playsinline`。
- 组合后重新检查时间、层级、字幕、人像、进度条、黑屏和 seek 可见性。
- 视频层不稳定时可以降级为多个关键阶段 PNG，但阶段图仍要覆盖入场、展开和最终态。
- A/B 截图中组合版没有明显提高理解、丰富度或质感时，保留单引擎版本。

## 历史教训

作品 001 曾把 Remotion PNG 阶段图直接叠在已有 HyperFrames 图解上，造成重复、遮挡和停留过短。失败原因是职责重复，不代表 Remotion 必须依附 HyperFrames，也不代表以后不能组合。

当前 001 只把 Remotion 新组件作为独立验收样例，不修改现有 HyperFrames 作品。

## 交付检查

- 是否选择了最简单且能达到质量目标的引擎方案？
- Remotion 独立输出是否已经通过关键帧和手机缩略检查？
- 组合时是否删除或降权原区域，避免重复？
- 复杂图解是否有足够停留时间？
- 临时渲染是否已清理，作品目录是否只保留必要成品？
