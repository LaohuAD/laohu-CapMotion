# 画面表达规则

本文件是项目中最重要的规则文件。它决定画面“应该补充什么”，而不是只决定画面“长什么样”。

## 核心原则

口播负责讲解，画面负责帮助观众理解、记住、定位和行动。

画面不应该：

- 照搬 PPT。
- 复述口播原文。
- 把长段口播改成屏幕文字墙。
- 为了动而动。

画面应该补充：

- 结构：这段话在整个主题里的位置。
- 对比：A 和 B 的差异。
- 流程：先做什么，再做什么。
- 判断标准：如何判断对错、优先级和风险。
- 例子：把抽象观点落到具体场景。
- 清单：观众看完之后可以执行什么。

## 单屏信息规则

- 每屏最多 1 个主观点。
- 每屏建议 3 到 5 个辅助信息。
- 标题要像课程讲义，不要像营销海报。
- 中文标题必须检查断行，避免类似“起 / 点”这种割裂。
- 辅助信息宁愿少，也不要密。
- 核心场景不能长期只有“标题 + 两张大卡片 + 少量文字”。如果画面显空，应优先补图解关系，而不是单纯放大字号。
- 大页、流程图、矩阵、控制台、风险面板和执行清单必须有足够停留时间，不能 3 秒短闪。
- 中文标题应人工断行，断在标点、语义停顿、并列结构或“不是 A，而是 B / 先 A，再 B”的边界。
- 每个核心场景尽量选择一种图解工具：流程、箭头、关系图、矩阵、漏斗、时间轴、趋势线、产物流转或风险映射。
- 横版母版也要按“竖屏手机里缩小观看”质检：核心标题、节点、流程名、判断标准和动作词必须在手机上仍然可辨认。
- 为手机缩小观看优化时，不要只放大字。应同时提高画面占用率、减少小字依赖、压缩空卡片，并用图解关系承载信息。
- 排版要检查“空间是否被有效使用”。如果画面左侧只有一个小信息块，右侧却大面积空白，或卡片内部只有左上角一点内容，其余区域空着，应视为构图问题。解决方式不是随便补字，而是把主信息做大并居中、让图解铺满区域、增加关系线/示例/状态层，或重新做左右/上下版面分配。
- 当用户明确指出某个红框区域“空白、空着、要细化文本”时，必须优先处理这个具体区域：补步骤、例子、缺失项、判断标准或产出动作，并重新检查上中下信息层是否都成立。不能只在别处加一句话，也不能把内容挤在角落后继续留下大空区。
- 自检时不只看空白，还要检查文字本身是否顺：分段是否自然、标点是否舒服、标题是否顺口、表述是否完整、前后是否冲突、逻辑关系是否讲明白、示意关系是否到位。凡是会影响观众理解、停留、记忆和获得价值的细节，都算画面问题。
- 不允许出现“标题已经出现，但主体区域空着”的画面。只要出现容器、卡片、字段、图表区域，就必须填入示例、标签、图解、动效线或明确占位说明。
- 不允许用横线、下划线、大空框长期冒充内容。模板字段如果暂时没有真实案例，也要从口播素材里提取合理示例词填充。
- 用户截图里的红框、红线、手画箭头通常是反馈标注，不是设计素材。必须先理解用户指出的问题，再重新设计规整、可读、不遮挡文字的图解元素，禁止机械照搬标注形状。
- 进度条、装饰线、强调线属于辅助层，不能压在正文、标题、卡片内容和关键标签上。全局进度条优先放在顶部 HUD 附近的空区，并保留正文安全距离。
- 讲解型媒体卡不能只有标题、短文案和底部标签。卡片中段至少要补一种语义视觉：缩略图、流程线、歌词条、屏幕录制行、素材网格、人物关系点或两行适用场景 / 产出动作。

## 内容来源规则

```text
口播稿：决定内容主线
ASR：决定时间轴和对齐点
PPT / 截图：只参考视觉方向
资料库：用于补充案例、例子、流程和判断标准
画面补充策略：决定哪些延伸信息可以合理上屏
```

具体判断方式见 `规范/画面补充策略.md`。

## 输出前自查

- 这一屏有没有提供口播之外的理解价值？
- 这一屏是不是只是把口播换成字幕？
- 如果关掉口播，观众能不能大概知道这一段在讲什么？
- 如果只看画面，观众会不会被信息量压住？
- 如果把横版视频缩到竖屏手机信息流里，主标题、关键节点和关系箭头还能不能看清？
- 是否存在红框式空白：大容器里没有内容、字段只有线、卡片中部空着、标题下面没有解释？
- 是否把用户手画标注误当成了画面元素？
- 全局进度条或装饰线是否离正文足够远？
- 补充信息是否有合理来源，而不是 AI 自己发散？
- 动画是否让结构更清楚，而不是只增加热闹感？
