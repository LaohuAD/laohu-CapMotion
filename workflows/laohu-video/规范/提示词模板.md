# 提示词模板

本文件沉淀后续给 Agent 使用的固定提示词。提示词应服务一套稳定流程：输入理解 → 内容分析 → 画面补充 → 分镜设计 → Remotion 制作 → Cap 覆盖 → 质检复盘。

## 1. 新作品启动

```text
请先读取 README.md 和规范/ 下的项目文档；如果当前工作区存在 AGENTS.md、当前作品/控制文档.md 或知识沉淀/，再把它们作为本地补充规则读取。
重点读取：
- 规范/画面表达规则.md
- 规范/画面补充策略.md
- 规范/视觉风格.md
- 规范/MG动画表达方法.md
- 规范/动效规则.md
- 规范/组件规则.md
- 规范/制作流程.md
- 知识沉淀/用户偏好.md

然后基于我放在 作品/编号_主题/输入/ 下的资料，以及当前作品/控制文档.md 中的优化要求，先不要写 Remotion 代码，
先输出内容分析、画面补充策略、动画节拍、画面规划、时间轴和分镜。

如果当前作品还没有 控制文档.md，请先根据用户本轮反馈创建控制文档，再继续。
```

## 2. 学习用户指令并更新控制文档

```text
请根据用户本轮对作品的修改指令、控制意见、审美判断、临时补充方向、口头偏好或控制文档更新，提炼新的实践经验，并更新当前作品/控制文档.md。
不要只在用户明确说“我更新了控制文档”时才学习；只要用户的话会影响作品结果、制作方法、审美方向或后续复用规则，就必须沉淀。
控制文档需要写给后续执行 AI 读取，不能只写给人看；它应是有限自由度执行蓝图，而不是泛泛方向建议。如果本轮反馈更适合写入分析/输出记录，也要同步记录。
必须包含：
- 当前作品定位
- 用户不满意点
- 本轮优化总目标
- 必须强化的画面表达
- 不要做什么
- 逐场景或逐模块优化要求
- 每个场景的标题、副标题、必须出现文字、图形关系、布局结构和动效节拍
- 必须严格执行项和允许灵活调整项
- 画面风格控制
- ASR 驱动的 MG 动画节拍要求
- 动效节奏控制
- 质检标准
- 输出要求

控制文档应持续累加，但如果旧要求已经不适用，需要明确替换或标注已废弃。

更新后，请把本轮用户指令里的要求分流：
- 当前作品指令：留在当前作品/控制文档.md、分析/、输出/
- 长期视觉/动效/表达规则：同步写入 规范/
- 用户偏好、踩坑、视觉问题、动效问题：同步写入 知识沉淀/
- 可复用组件或模板：同步写入 规范/组件规则.md 或 模板/

如果新要求和旧经验冲突，以新要求为准更新旧经验；需要直接覆盖、删除或标注旧经验已被替换，不要让互相冲突的规则长期并存，除非明确标注适用边界。

最终回复必须说明：哪些内容已经沉淀到项目级文档，哪些只保留在当前作品，哪些旧经验被覆盖或调整。
```

## 3. 内容分析

```text
请基于口播稿和 ASR，分析这条内容的主线结构。
输出：
1. 核心主题
2. 目标观众
3. 章节结构
4. 每段主观点
5. 观众最容易不懂、记不住或不知道怎么做的地方
6. 哪些内容适合画面补充，哪些内容不应上屏

不要把口播逐句改写成屏幕文案。
```

## 4. 画面补充策略

```text
请不要复述口播原文。
请逐段判断画面应该补充：
结构 / 例子 / 对比 / 流程 / 判断标准 / 执行清单 / 风险提示 / 数据复盘 / 进阶延伸。

每段输出：
- 口播主观点
- 画面任务
- 建议补充的信息
- 补充信息的来源或依据
- 不应补充的内容
- 推荐组件
- 动效重点
- 需要用户补充或确认的资料

补充内容必须和口播主题强相关，不能为了显得高级而发散到新主题。
```

## 5. 动画节拍设计

```text
请通过 `.agents/skills/laohu-animation-director/SKILL.md` 为已定稿内容规划动画，并按它为每个讲解单元选择 TalkCraft 或 anything2explainer 原版能力。

提供已确认字幕、映射与底画，说明本次审稿范围及批准状态。让选定上游按其原生方法产出节拍或工作单，并明确哪些画面单元不需要动画。节拍应能追溯到原声、字幕块或冻结映射中有证据的时间；不得按字数插值或为节拍数量强行拆画面。

将候选并入唯一审稿资料，标注上游名称、单元范围、时间依据、材料来源和待确认事项。不要预先规定画面必须逐项出现、使用哪类图表、保持某种动效节奏或采用本地组件。
```

## 6. 分镜设计

```text
请直接使用当前选定的 TalkCraft / anything2explainer 原版 Skill、原生分镜规则和资产说明完成分镜，不要复制其能力另做一套模板。

保持已确认的讲述与结论；可按上游原生做法决定画面形态、布局、配色、信息数量、镜头和节奏。留白可以服务表达，不为填满画面添加组件。候选必须能对应当前单元与底画、保留必要来源，进入唯一审稿，不自行批准。
```

## 7. Remotion 制作

```text
对已经获准且 T2 已冻结的单元，直接执行所选上游 Skill 的原版制作步骤、组件/卡片、布局和适用技术检查。只实现当前获准单元，不扩展剪辑、ASR、稿件或配音流程。

使用真实上游源码与其约定的输入格式；如果原版流程要求将所选卡片 TSX 复制到制作工程，则按原版执行。只做 Cap 接回必需的最小宿主适配，不将上游能力参考后改写并长期维护为第二套自有动画库，也不复制整仓或依赖。完成后报告输出规格、实际运行的检查、尚未验证的兼容点，并按现有 revision-safe `cap motion` 流程接回冻结 T2。无法由原版输入/接口承接时，指出缺口，不自动改走本地旧方案。
```

## 8. 质检

```text
按所选上游 Skill 中当前适用的原版检查流程检查动画，并按项目任务包与 Cap 接口复核实际结果。

共同检查：动画是否遵守已定稿内容、时间映射、素材来源和批准边界；是否帮助理解而非误导；字幕、主音频及底画职责是否重复；实际画面是否清楚可读；上游不支持的输入或未运行的检查是否如实标明。布局、配色、字体、动势、信息数量与留白按本作品决定及选定上游规则判断，不按旧本地皮肤强行打分。
```

## 9. 复盘沉淀

```text
请基于本次作品和用户反馈，输出复盘总结。
重点回答：
- 哪些画面有效？
- 哪些画面只是复述口播？
- 哪些补充信息有价值？
- 哪些补充信息太发散？
- 哪些动效提升理解？
- 哪些动效显得廉价或抢戏？
- 本次用了哪个上游原版能力，其原生规则怎样影响设计？
- 哪些来源、时间或 Cap 接入问题需要记录？
- 只有在本地 workspace 组件被维护时，才记录是否需要更新自有组件、schema 或测试；按原版需要将上游资产纳入共享 workspace 时保留原实现，不另造第二套动画库。
- 哪些通用经验要写回 知识沉淀/ 或 规范/？
- 本轮用户指令中哪些新要求已经沉淀为长期规则？
- 哪些旧经验被新经验覆盖或调整？
- 下次创作开始前应该优先读取哪些新增规则？
```
