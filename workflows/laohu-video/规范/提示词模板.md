# 提示词模板

本文件沉淀后续给 Agent 使用的固定提示词。提示词应服务一套稳定流程：输入理解 → 内容分析 → 画面补充 → 分镜设计 → HyperFrames 制作 → 质检复盘。

## 1. 新作品启动

```text
请先读取 README.md 和规范/ 下的项目文档；如果当前工作区存在 AGENTS.md、当前作品/控制文档.md 或知识沉淀/，再把它们作为本地补充规则读取。
重点读取：
- 规范/画面表达规则.md
- 规范/画面补充策略.md
- 规范/视觉风格.md
- 规范/MG动画表达方法.md
- 规范/动效规则.md
- 规范/组件规则.md
- 规范/制作流程.md
- 知识沉淀/用户偏好.md

然后基于我放在 作品/编号_主题/输入/ 下的资料，以及当前作品/控制文档.md 中的优化要求，先不要写 HyperFrames 代码，
先输出内容分析、画面补充策略、动画节拍、画面规划、时间轴和分镜。

如果当前作品还没有 控制文档.md，请先根据用户本轮反馈创建控制文档，再继续。
```

## 2. 学习用户指令并更新控制文档

```text
请根据用户本轮对作品的修改指令、控制意见、审美判断、临时补充方向、口头偏好或控制文档更新，提炼新的实践经验，并更新当前作品/控制文档.md。
不要只在用户明确说“我更新了控制文档”时才学习；只要用户的话会影响作品结果、制作方法、审美方向或后续复用规则，就必须沉淀。
控制文档需要写给后续执行 AI 读取，不能只写给人看；它应是有限自由度执行蓝图，而不是泛泛方向建议。如果本轮反馈更适合写入分析/输出记录，也要同步记录。
必须包含：
- 当前作品定位
- 用户不满意点
- 本轮优化总目标
- 必须强化的画面表达
- 不要做什么
- 逐场景或逐模块优化要求
- 每个场景的标题、副标题、必须出现文字、图形关系、布局结构和动效节拍
- 必须严格执行项和允许灵活调整项
- 画面风格控制
- ASR 驱动的 MG 动画节拍要求
- 动效节奏控制
- 质检标准
- 输出要求

控制文档应持续累加，但如果旧要求已经不适用，需要明确替换或标注已废弃。

更新后，请把本轮用户指令里的要求分流：
- 当前作品指令：留在当前作品/控制文档.md、分析/、输出/
- 长期视觉/动效/表达规则：同步写入 规范/
- 用户偏好、踩坑、视觉问题、动效问题：同步写入 知识沉淀/
- 可复用组件或模板：同步写入 规范/组件规则.md 或 模板/

如果新要求和旧经验冲突，以新要求为准更新旧经验；需要直接覆盖、删除或标注旧经验已被替换，不要让互相冲突的规则长期并存，除非明确标注适用边界。

最终回复必须说明：哪些内容已经沉淀到项目级文档，哪些只保留在当前作品，哪些旧经验被覆盖或调整。
```

## 3. 内容分析

```text
请基于口播稿和 ASR，分析这条内容的主线结构。
输出：
1. 核心主题
2. 目标观众
3. 章节结构
4. 每段主观点
5. 观众最容易不懂、记不住或不知道怎么做的地方
6. 哪些内容适合画面补充，哪些内容不应上屏

不要把口播逐句改写成屏幕文案。
```

## 4. 画面补充策略

```text
请不要复述口播原文。
请逐段判断画面应该补充：
结构 / 例子 / 对比 / 流程 / 判断标准 / 执行清单 / 风险提示 / 数据复盘 / 进阶延伸。

每段输出：
- 口播主观点
- 画面任务
- 建议补充的信息
- 补充信息的来源或依据
- 不应补充的内容
- 推荐组件
- 动效重点
- 需要用户补充或确认的资料

补充内容必须和口播主题强相关，不能为了显得高级而发散到新主题。
```

## 5. 动画节拍设计

```text
请根据 ASR / SRT 和画面补充策略，为每个场景设计动画节拍。
要求：
- 不要一口气展示整屏内容
- 每个主要元素都要对应口播时间点或语义推进
- 标明元素是出现、连接、点亮、移动、变化、切换还是收束
- 标明本场景使用什么图解工具：流程图 / 箭头 / 关系图 / 漏斗图 / 时间轴 / 条形图 / 折线图 / 决策树 / 象限图 / 包含关系
- 流程类画面要有节点推进和路径变化
- 模板类画面要有字段逐步填入
- 对比类画面要有错误路径和正确路径的变化
- 数据类画面要有指标或时间窗口切换
- 风险类画面要有风险出现和规避动作出现

输出格式：
场景编号：
场景时间：
口播主线：
节拍 1：ASR 时间 / 口播关键词 / 画面动作 / 出现元素 / 强调方式
节拍 2：ASR 时间 / 口播关键词 / 画面动作 / 出现元素 / 强调方式
收束：ASR 时间 / 画面如何形成结论或下一步动作
```

## 6. 分镜设计

```text
请根据内容分析、画面补充策略和动画节拍，设计 HyperFrames 分镜。
要求：
- 每屏最多一个主观点
- 每屏 3 到 7 个辅助信息，避免画面过空
- 标明使用组件：title-card / flow-map / formula-card / comparison / checklist / risk-dashboard 等
- 标明使用的图表关系表达：箭头、连接线、流程、包含关系、漏斗、矩阵、时间轴等
- 标明动效方式：进入、点亮、对比、高亮、转场
- 标明和 ASR 或口播段落的时间对齐方式
- 标明是否建议后续用 Remotion 精修，以及原因
- 避免文字墙和 AI 味 PPT
```

## 7. HyperFrames 制作

```text
请基于已确认的分镜和动画节拍制作 HyperFrames。
制作前读取：
- 规范/视觉风格.md
- 规范/MG动画表达方法.md
- 规范/图表关系表达规则.md
- 规范/双引擎协作规则.md
- 规范/动效规则.md
- 规范/组件规则.md
- 规范/质检清单.md

要求：
- 先按动画节拍确定元素出现、连接、点亮、变化和收束的时间，再写布局和动画
- 组件尽量可复用
- 所有 timed element 遵守 HyperFrames 规则
- GSAP timeline 必须可 seek、可复现
- 不使用随机数、无限循环或异步时间轴
- 中文标题必须避免难看断行
- 禁止场景开头一口气展示所有信息，除非是短暂总览且后续有焦点推进
- 先用 HyperFrames 完成可预览结构；对复杂图解、路径动画、透明前景层或可复用精细动效，输出 Remotion 精修建议
```

## 8. 质检

```text
请按 规范/质检清单.md 检查当前 HyperFrames 作品。
重点检查：
- 是否只是复述口播
- 补充信息是否合理、有来源
- 是否有 ASR 对齐的动画节拍
- 是否避免一口气展示整屏内容
- 是否避免只有文字 + 方框卡片
- 是否使用图表、箭头、流程、关系或包含结构帮助理解
- 是否判断了哪些片段适合 Remotion 精修，哪些继续用 HyperFrames 足够
- 画面是否随着口播逐步出现、连接、变化和收束
- 中文断行是否难看
- 信息密度是否过高
- 是否有 AI 味 PPT 或廉价模板感
- 动效是否帮助理解，而不是为了动而动
- 是否存在布局问题
- HyperFrames lint / validate / inspect 是否通过
```

## 9. 复盘沉淀

```text
请基于本次作品和用户反馈，输出复盘总结。
重点回答：
- 哪些画面有效？
- 哪些画面只是复述口播？
- 哪些补充信息有价值？
- 哪些补充信息太发散？
- 哪些动效提升理解？
- 哪些动效显得廉价或抢戏？
- 哪些组件可以沉淀为模板？
- 哪些经验要写回 知识沉淀/ 或 规范/？
- 本轮用户指令中哪些新要求已经沉淀为长期规则？
- 哪些旧经验被新经验覆盖或调整？
- 下次创作开始前应该优先读取哪些新增规则？
```
