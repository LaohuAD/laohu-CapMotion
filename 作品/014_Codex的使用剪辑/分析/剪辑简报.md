# 《Codex 的使用》剪辑简报

## 交付目标

- 交付一版粗剪：删除明显空镜、长停顿、废弃起头、口误重说和无效重复，保留原始讲解顺序与完整信息。
- 交付一版精剪：在粗剪基础上继续删除口水化表达、同义反复、弱铺垫和低价值支线，让观众沿一条清楚的知识主线看完。
- 不烧录字幕，不添加动画包装，不改变画面内容。
- 最终统一做温和响度校准，目标约为 `-16 LUFS / -1.5 dBTP`。

## 观众与成片风格

观众是希望学习 Codex、建立个人 AI 工作方式，但对 Agent、skill、知识库等概念并不熟悉的人。成片保持老胡真实口播和边演示边思考的质感，但减少会阻碍理解的停顿、拖音、重复起头和无效绕行。

## 必须保留

1. 安装前提、遇到术语时让 AI 解释的学习方法。
2. 为什么要创建属于自己的 Agent，以及共享 Agent 与个人 Agent 的区别。
3. “老胡文稿”示例所体现的个人内容观、工作流和自进化能力。
4. 外部内容输入、AI 分析、观点讨论、本地沉淀的完整闭环。
5. 视频下载、火山引擎与豆包输入法两种转文字路径。
6. 用提示词让 AI 分析文稿，并把结论沉淀到本地项目的过程。
7. 不接受浅层答案、继续追问、调用 skill 深化分析的方法。
8. “解释一下”命令和把 Codex 调成说人话的长期实践。
9. 选题案例、个人痛点、内容方向放大的方法。
10. 关于个人性格、想到什么说什么、发散思维、适合直播等形象表达。这些属于人格和信任信息，不按口水话删除。

## 可以删除

- 独立的“嗯、呃、啊”等语气词和拖音。
- 连续重复的字词、重复起头、说错后立即重说的废弃版本。
- 不承担逻辑作用的“然后呢、这个呢”等堆叠口头连接。
- 已经讲清后再次重复、但没有新增信息的解释。
- 与教程主线关系较弱的招生和关注引导。
- 结尾检查 GitHub 等没有形成有效结论的临时绕行。

## 内容主线

```text
先准备好 Codex
  → 创建个人 Agent
  → 用“老胡文稿”理解个人 Agent 的价值
  → 把外部视频变成可分析的文字
  → 让 AI 分析、讨论并沉淀成本地知识
  → 对浅层回答继续追问并调用 skill
  → 用“解释一下”和长期规则把 AI 调成说人话
  → 把方法应用到选题和内容生产
  → 总结为可持续自进化的个人工作流
```

## 顺序判断

原始讲解顺序已经符合观众的理解路径：先建立工具和 Agent，再输入材料、分析材料、沉淀知识，最后进入更深的内容判断和选题应用。因此精剪不做章节重排，只做章节划分、句内修剪和低价值内容压缩。这样既能让脉络更清楚，也不会破坏屏幕操作的连续状态。

## 精剪章节

1. 安装前提与 Agent 定义
2. 创建属于自己的个人 Agent
3. “老胡文稿”的能力、内容观与自进化
4. 外部输入到本地知识库的闭环
5. 豆包输入法与分析提示词
6. 本地项目、自进化与话题放大
7. 质疑浅层回答与 skill 调用
8. “解释一下”与说人话的长期调教
9. 选题案例与方法收束
10. AI 剪辑闭环与结尾
