# 审计发现

- `recording-meta.json.segments[]` 是原始录制段真实顺序；编辑时间线不能替代录制顺序用于第一遍源媒体索引。
- 多段 Studio 的麦克风在每段 `mic.path`，旧单段可在 `audio.path`，系统声音是独立媒体来源。
- 第一遍转写只服务上游内容重建；第二遍最终覆盖必须基于冻结的 `S2→T2` 映射。
- Cap Motion 原本已有定义、段、Remotion 渲染与上层合成；缺口是外部已生成视频的 revision-safe 导入，本轮已补齐。
- Cap 当前仍缺 EDL 直接写入底层可编辑视频轨的确定性接口，必须明确标为 UNKNOWN。
- RunningHub 附件确认 `94/audio`、`234=false`、`233=false`、`241=2`、`244=1`；没有证明两个 select 数值对应的 UI 语义标签。
- RunningHub 结果 URL 仅短期有效，因此 SUCCESS 后立即下载是不可交换步骤。
- RunningHub 提交和查询响应的 `taskId/status/results` 位于顶层；两个关闭开关的 `fieldValue` 按附件是字符串 `"false"`。
- 数字人必须由冻结后的最终主音频驱动；用脚本文字或第一遍音频都会破坏时间和口型权威。
- 清单哈希只记录不复核没有意义；上传前必须重算源主音频和每段 WAV 哈希，导出后还必须 probe 实际时长。
- 机械规格只能证明文件、时间、分辨率、横屏和哈希，不能证明口型、人物一致性和观感；后者必须人工观看。
- 程序动画当前只由 Remotion 承担。旧 HyperFrames 中可复用的节拍和表达原则已迁移，旧运行文件与作品源工程不保留在当前工作树。
- 本机系统 FFmpeg 8 缺失动态库，但 FFmpeg 7 可用；媒体脚本必须使用统一解析器，不能依赖 PATH 中的坏版本。
