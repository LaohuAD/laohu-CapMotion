# 画面补充策略

本文件用于判断：当口播稿没有直接说出某些信息时，画面可以补充什么、补到什么程度、哪些内容不能乱加。

核心目标：让画面从“复述口播”升级为“帮助理解、记忆、定位和行动”。

## 1. 基本原则

画面补充的信息必须满足至少一条：

- 帮观众看懂结构：这段内容在整体主题里的位置。
- 帮观众降低理解成本：把抽象说法变成流程、图示、例子或判断标准。
- 帮观众记住关键方法：把口播里的方法变成公式、清单、模板或步骤。
- 帮观众发现隐含关系：展示口播没有展开的前因后果、对比关系或风险点。
- 帮观众知道下一步怎么做：给出可执行动作、检查项或复盘路径。

画面补充的信息不能只是为了显得高级、热闹或复杂。

## 2. 合理补充的边界

### 可以补充

- 口播观点背后的结构关系。
- 口播方法对应的步骤、模板、公式和清单。
- 口播案例里的关键变量和可复制点。
- 口播风险对应的错误示范、红线和判断标准。
- 观众执行时需要用到的提示、检查点和下一步动作。
- 与主题强相关的进阶理解、延伸视角和常见误区。

### 谨慎补充

- 数据、结论、行业判断：没有来源时只能写成“参考维度”“观察方向”，不能写成确定事实。
- 具体案例：没有用户提供资料时，可以做通用示例，但不能冒充真实案例。
- 工具、平台、规则：如果可能随时间变化，需要标注为“可按实际平台调整”。
- 用户没说过的观点：只能作为辅助理解，不能改变口播主张。

### 不要补充

- 与当前口播主题无关的新观点。
- 没有依据的数字、排名、结论和承诺。
- 把简单内容强行包装成复杂模型。
- 只为了炫酷而增加的无意义图表、装饰和动效。
- 会抢走口播注意力的大段解释。
- 和老胡表达立场相冲突的判断。

## 3. 口播类型与画面补充方式

| 口播内容类型 | 画面应优先补充 | 常用画面形式 | 注意事项 |
| --- | --- | --- | --- |
| 概念解释 | 定义、边界、误区 | 定义卡、三分区、关键词拆解 | 不要写成百科解释 |
| 方法论 | 公式、步骤、变量 | 公式卡、流程图、执行模板 | 变量不宜超过 5 个 |
| 流程说明 | 先后顺序、节点产物、卡点 | 时间线、流程地图、节点点亮 | 每一步要有明确产物 |
| 对比判断 | A/B 差异、选择标准、适用场景 | 对比卡、决策树、象限图 | 不要把对比做成口号 |
| 案例讲解 | 关键变量、可复制点、失败原因 | 案例拆解卡、标注图、因果链 | 没有真实案例时避免伪造 |
| 风险提醒 | 红线、错误示范、后果、检查项 | 风险面板、警示卡、避坑清单 | 不要制造恐吓感 |
| 数据复盘 | 指标、观察窗口、下一步动作 | 数据看板、趋势卡、复盘表 | 没有真实数据时用结构占位 |
| 执行建议 | 清单、优先级、最小闭环 | checklist、行动卡、MVP 路径 | 每项最好能被观众执行 |
| 情绪动员 | 关键句、阶段目标、信心建立 | 主张大字卡、进度条、总结页 | 不要变成鸡汤海报 |
| 故事叙述 | 时间顺序、转折点、因果关系 | 故事线、节点卡、前后对照 | 不要打断叙事节奏 |

## 4. 单段口播的判断流程

每处理一段口播，按以下顺序判断：

```text
1. 这段口播的主观点是什么？
2. 观众听到这里最容易不懂、记不住或不知道怎么做的地方是什么？
3. 画面最应该补充哪一类信息：结构 / 例子 / 对比 / 流程 / 判断标准 / 清单 / 风险 / 数据？
4. 这条补充信息是否能从口播、资料库或通用常识中合理推出？
5. 这一屏是否仍然只有一个主观点？
6. 如果关掉声音，只看画面，观众能不能知道这一段在解决什么问题？
7. 如果打开声音，画面是否和口播互补，而不是抢戏？
```

## 5. 补充信息的三层模型

### 第一层：口播显性信息

口播已经明确说出的关键词、步骤、观点和结论。

使用方式：只保留最关键的词，不要整句搬上屏。

### 第二层：口播隐含信息

口播虽然没有逐字说出，但能从上下文合理推出的结构、前后关系、判断标准和执行步骤。

使用方式：这是画面最应该补充的部分。

### 第三层：资料库延伸信息

来自用户提供的案例、PPT、截图、工具资料、行业经验、历史作品和复盘记录。

使用方式：可以增强画面，但必须和当前段落强相关；没有资料支撑时不要写成确定事实。

### 第四层：口播背后的原始大素材

当用户额外提供“口播原始素材 / 长文资料 / 控制前的大稿”时，这类资料通常比实际口播更丰富。它不替代口播稿和 ASR，但可以作为画面补充细节的重要来源。

使用方式：

- 口播稿决定主线，ASR 决定节拍，原始大素材补充图解细节。
- 优先提取口播没有展开但能帮助理解的结构、例子、判断标准、执行清单、风险动作和流程关系。
- 不要把原始大素材逐段搬上屏，也不要因为素材丰富就另起主题。
- 适合用于补强流程图、关系图、模板卡、风险面板、数据复盘面板和执行清单。

## 6. 画面补充的信息密度

每屏建议：

```text
1 个主观点
3 到 5 个辅助信息
1 个明确视觉关系
1 个主要动效节奏
```

优先减少文字，而不是压缩字号。

横版视频如果会被竖屏手机用户缩小观看，信息密度要用“少量大字 + 大图解关系”解决：

- 主标题、关键节点、流程动作、判断标准要足够大。
- 小字只能作为辅助，不能承载核心理解。
- 画面不能大面积空置；优先使用流程图、关系图、漏斗、路线图、箭头、时间轴、风险映射等结构填充。
- 如果某段适合图片、路径图或关系图表达，不要退回纯文字卡片。

常见错误：

- 一个屏幕同时解释两个观点。
- 用 8 到 10 个卡片展示所有信息。
- 把口播长句拆成多行字幕。
- 辅助信息之间没有关系，只是并列堆放。
- 横版画面在电脑预览看着清楚，但缩到手机信息流后关键字和图表标签看不清。

## 7. 常用补充模板

### 结构地图

适用：开头、章节切换、复杂主题总览。

```text
当前位置：现在讲到哪里
上一步：刚解决什么
下一步：接下来要解决什么
最终目标：观众要获得什么
```

### 方法公式

适用：讲方法、选题、判断、执行策略。

```text
结果 = 变量 A + 变量 B + 变量 C
每个变量配一个短例子或检查点
```

### 错误示范 / 正确示范

适用：纠正常见误区。

```text
错误做法：看起来在做什么
问题所在：为什么无效
正确做法：应该替换成什么
```

### 执行清单

适用：段落结尾、章节总结、落地动作。

```text
今天可以做什么
发布前检查什么
复盘时看什么
下一条只改什么
```

### 风险面板

适用：合规、版权、平台规则、素材风险。

```text
风险点
触发条件
后果
规避动作
```

## 8. 输出格式要求

在每条作品的 `分析/画面补充策略.md` 中，建议按段落写成：

```text
段落编号：
口播主观点：
画面任务：结构 / 例子 / 对比 / 流程 / 判断标准 / 清单 / 风险 / 数据
建议补充：
不应补充：
推荐组件：
动效重点：
资料需求：
```

如果某段缺少资料但又适合补充案例，应标记为：

```text
待补资料：需要真实案例 / 工具截图 / 数据来源 / 用户确认
```

## 9. 最终自查

生成画面规划前，必须检查：

- 这条补充信息是不是服务当前口播，而不是另起一个主题？
- 这条补充信息有没有改变老胡原本表达的意思？
- 这条补充信息是不是能让观众更容易理解、记住或行动？
- 这条补充信息有没有明确来源：口播、ASR、PPT、资料库、项目规则或通用常识？
- 如果用户追问“这从哪来的”，是否能解释清楚？
