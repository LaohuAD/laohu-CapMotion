# MG 动画表达方法

本文件定义如何把口播内容转化为随 ASR 推进的动态讲解画面。目标不是制作动态 PPT，而是制作“口播驱动的 MG 动画讲解”。

## 1. 核心定义

本项目里的 MG 动画，不是简单让文字和卡片淡入，而是让信息随着口播逐步建立：

```text
口播说到一个点 → 画面出现一个元素
口播解释一个关系 → 画面建立连线、层级、对比或路径
口播给出结论 → 画面高亮、收束或形成闭环
```

观众不应该一开始看到整页完整内容，而应该跟着讲解一点一点看见信息被搭建出来。

## 2. 和动态 PPT 的区别

| 动态 PPT | MG 动画讲解 |
| --- | --- |
| 页面排好后整体展示 | 信息随口播逐步生成 |
| 主要是标题、卡片、列表 | 可以是流程、图表、关系、路径、状态变化 |
| 开头进场后长时间静态 | 场景内部持续有重点变化 |
| 观众自己找重点 | 画面主动引导观众看重点 |
| 动画只负责装饰 | 动画负责解释关系 |

如果一个场景去掉动画后仍然像完整 PPT 页面，说明动画设计不够。

## 3. ASR 驱动原则

制作前必须先把口播段落拆成动画节拍：

```text
ASR 时间点
口播关键词
画面动作
出现元素
强调方式
```

示例：

```text
05:20 讲“选题不是歌词起点” → 出现错误路径：歌词先行
05:32 讲“谁在什么场景需要这首歌” → 出现人群 + 场景两个字段
05:48 讲“五个要素” → 公式变量逐个出现
06:10 讲“传播潜力” → 五个变量合成选题卡
```

## 4. 单场景三段式结构

每个关键场景尽量使用三段式：

### 4.1 引入

作用：让观众知道这段要解决什么问题。

常见动画：

- 问题文字出现。
- 错误状态出现。
- 断裂路径出现。
- 空白模板出现。
- 初始数据面板出现。

### 4.2 展开

作用：跟着口播逐步补充信息。

常见动画：

- 节点逐个点亮。
- 卡片逐个进入。
- 连线逐步绘制。
- 变量逐个填入。
- 图表逐步增长。
- 对比项左右分化。
- 风险和处理动作先后出现。

### 4.3 收束

作用：让观众记住结论或下一步动作。

常见动画：

- 重点区域放大。
- 结论高亮。
- 散点收拢成闭环。
- 清单勾选完成。
- 进度条推进到下一章。
- 画面聚焦到“下一步”。

## 5. 常用 MG 动画表达模型

### 5.1 流程推进动画

适合：步骤、流程、路线、生产链路。

画面方式：

```text
节点 1 出现 → 线条连接 → 节点 2 出现 → 产物卡弹出 → 当前节点高亮
```

适合本项目：

- 7 步 AI 音乐流水线。
- 最小闭环路径。
- 发布前后流程。

关键要求：流程节点必须展示“动作 + 产物”，不能只写名词。

### 5.2 关系生成动画

适合：概念之间的因果、层级、关联。

画面方式：

```text
中心概念出现 → 分支向外生长 → 每个分支出现解释 → 相关分支被连线或分组
```

适合本项目：

- 选题如何影响歌词、画面和发布。
- 账号路线如何决定内容形态和复盘指标。
- 记录如何影响下一条优化。

### 5.3 正误对比动画

适合：误区纠正、错误路径、方法替换。

画面方式：

```text
先显示错误路径 → 出现断点或红色标记 → 正确路径补全 → 两边差异高亮
```

适合本项目：

- “生成一首歌”不等于“完成一条内容”。
- “先写歌词”不等于“先做选题”。
- “发出去就结束”不等于“发布后要复盘”。

### 5.4 模板填写动画

适合：公式、工作表、可执行模板。

画面方式：

```text
空模板出现 → 字段逐个填入 → 示例占位出现 → 完整模板被框选 → 下一步动作出现
```

适合本项目：

- 选题卡。
- 发布包。
- 复盘表。

关键要求：模板必须可执行，不能只是把公式写大。

### 5.5 数据 / 指标切换动画

适合：复盘、数据观察、指标判断。

画面方式：

```text
空数据面板出现 → 2h 指标亮起 → 24h 指标切换 → 72h 指标切换 → 得出只改一个变量
```

适合本项目：

- 2h / 24h / 72h 复盘。
- 完播、互动、收藏、评论关键词。

没有真实数据时，不要编造数字，可以用结构占位和指标名称。

### 5.6 风险处理动画

适合：合规、授权、平台规则、素材风险。

画面方式：

```text
风险点出现 → 警示状态亮起 → 规避动作出现 → 留痕记录进入文件夹或清单
```

适合本项目：

- 授权记录。
- AI 标识。
- 肖像声音。
- 素材来源。
- 生成记录。

关键要求：不能只列风险，必须给处理动作。

### 5.7 视觉焦点转移动画

适合：长段落内部避免静态。

画面方式：

```text
当前重点区域变亮 → 其他区域降低透明度 → 讲到下一点时焦点移动 → 旧信息退居背景
```

适合本项目：

- 路线选择长段。
- 画面和视频长段。
- 授权规则长段。

## 6. 001 作品优先使用的动画模型

知识讲解类口播的下一版可优先使用：

| 场景类型 | 推荐 MG 模型 |
| --- | --- |
| 开场误区 | 正误对比动画 |
| 7 步流水线 | 流程推进动画 |
| 路线选择 | 关系生成动画 + 视觉焦点转移 |
| 选题公式 | 模板填写动画 |
| 歌词音乐 | 对比动画 + 版本筛选动画 |
| 画面视频 | 漏斗 / 传播链路动画 |
| 发布包 | 模板填写动画 + 清单勾选 |
| 数据复盘 | 数据 / 指标切换动画 |
| 最小闭环 | 流程推进动画 |
| 产物留存 | artifact-grid 逐步生成 |
| 合规风险 | 风险处理动画 |
| 结尾清单 | 清单勾选 + 闭环收束 |

## 7. 动画节拍设计模板

每个场景制作前，先写动画节拍：

```text
场景编号：
场景时长：
口播主线：

节拍 1：
- ASR 时间：
- 口播关键词：
- 画面动作：
- 出现元素：
- 强调方式：

节拍 2：
- ASR 时间：
- 口播关键词：
- 画面动作：
- 出现元素：
- 强调方式：

收束：
- ASR 时间：
- 画面如何形成结论或下一步：
```

没有动画节拍，不应直接写 HyperFrames 代码。

## 8. 质检标准

- 画面是否随着 ASR 推进逐步生成？
- 是否避免了一口气展示整页内容？
- 每个场景内部是否有明确的动画节拍？
- 动画是否解释了关系，而不是只让元素出现？
- 观众是否能看出当前重点在哪里？
- 流程、模板、图表、风险、数据是否有对应的动态表达？
- 是否避免了“静态 PPT 加淡入”的感觉？
