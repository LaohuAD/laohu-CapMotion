# 案例参考

本文件记录可参考的案例、画面方向和可迁移方法。

## 当前参考方向

- 口播人像作为底层或侧边画面。
- 前景叠加标题、重点词、流程图、卡片、箭头、字幕和数据面板。
- 按 ASR 时间轴逐段出现信息。
- 如果有词级时间戳，可探索逐词高亮和关键词卡点。
- 如果只有句级时间戳，优先做章节级画面对齐。

## 案例拆解要求

后续看到喜欢的视频、PPT、网页动效或知识类包装案例时，不只保存链接，要拆解它为什么有效。

```text
案例名称：
链接或文件位置：
内容类型：口播 / 评测 / 教程 / 商业分析 / 数据讲解 / 其他
值得学的地方：
- 信息层级：
- 镜头节奏：
- 画面结构：
- 动效方式：
- 细节质感：
不适合照搬的地方：
可迁移到本项目的组件：
可迁移到本项目的提示词规则：
```

优先收集：

- 开场 5 秒能快速建立期待的案例。
- 复杂观点讲得清楚的案例。
- 人像 + 信息层结合得好的案例。
- 流程、公式、对比、数据复盘做得好的案例。
- 动效高级但不抢内容的案例。

## 参考项目：roughcut-pipeline

案例名称：`xiaoniiii/roughcut-pipeline`

本地位置：`参考项目/roughcut-pipeline`

内容类型：口播 / 访谈 / 多机位素材的本地粗剪管线

值得学的地方：

- 信息层级：把媒体工程、字幕、审稿决策、剪辑清单、导出结果、验证报告拆成不同职责，避免一边判断内容一边直接硬剪。
- 剪辑流程：先建立目标时长、剪辑偏好、必须保留、可以删除、观众和输出风格，再生成 AI 初稿审稿表，让用户审核保留 / 删除，而不是让用户从零标每一句。
- 内容判断：先定义一条成片主线和 4-7 个故事节点，保护背景、转折、结论和情绪落点，防止剪成散碎高光。
- 技术导出：由字幕审稿表生成 `keepRanges` / `cut_manifest` 一类的剪辑清单，再导出视频，最后验证流、时长、抽帧和同步。
- 多机位：先确认主音频机位、素材顺序和排除文件，非主机位先做同步检查，再导出全片。

不适合照搬的地方：

- 许可证是 PolyForm Noncommercial License 1.0.0，只适合参考学习；当前项目不要直接复制其源码或把它当作商业可复用依赖。
- 它偏“粗剪管线工具”，不是 Remotion 画面包装系统；对本项目更有价值的是审稿流程、结构化文件和验证思路。

可迁移到本项目的组件：

- 剪辑简报：目标时长、观众、输出风格、必须保留、可以删除、主线、故事节点。
- 审稿决策表：每条字幕标注 `保留 / 删除 / 待确认` 和删除理由。
- 剪辑清单：把审稿结果转成可执行的 `startMs / endMs / subtitleIds`。
- 交付验证：`ffprobe`、demux 检查、`silencedetect`、开头中段结尾抽查、音画同步检查。

可迁移到本项目的提示词规则：

- “先保护成片主线，再压缩冗余。”
- “强句只在服务主线且上下文完整时保留；孤立高光不能替代完整表达。”
- “删除必须有理由，不能只因为它让成片更短。”
- “把只保留内容读成大纲，如果像碎片合集，就恢复必要上下文。”
