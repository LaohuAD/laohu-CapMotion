# Cap 个性化预设与 Agent 接口进化计划

> **执行约束：** 本计划在当前单工作目录中使用普通 Git 分支逐项执行，不创建 worktree，不在开发排错期间反复打包 CapMotion，不覆盖已有未提交改动；只有开发验证完成且用户明确要求打包时才更新独立版。

## 目标

把公共可配置能力、用户个性预设和单个工程内容分开。`Laohu` 只作为老胡本机的用户预设，不再是所有用户都看到的内置字幕样式。Agent 通过稳定命令读取、修改和应用预设，不直接替换工程 JSON。

## 当前失效点

- 最早失效点：`apps/desktop/src/store/captions.ts` 把 `Laohu` 写进公共 `CAPTION_STYLE_PRESETS`，把个人数值误当成产品默认能力。
- 链路失效：`createPresets.ts` 保存接近整份 `ProjectConfiguration`；`preset-config.ts` 只在应用时临时护住部分轨道，保存端仍可夹带字幕正文、素材路径和轨道状态。
- 接口失效：已编译 CLI 只能修改某一工程的字幕样式，没有用户预设的 list / inspect / save / style / apply 接口。

## 设计

1. **公共能力**：以白名单 schema 公开字幕、画布背景、摄像头外观、鼠标动效和色彩校正等可复用展示参数；公共默认不携带老胡个人数值。
2. **用户预设**：沿用已有 store 数据格式，但写入前将工程投影为可复用白名单；清空时间轴、片段、字幕正文、Remotion 覆盖、注释、源音轨编辑和素材绝对路径。
3. **工程实例**：应用预设时只合并白名单展示参数，保留 `projectRevision`、时间轴、素材、字幕内容、音轨、动画和工程背景来源。
4. **Agent 界面**：新增预设库 revision；写操作必须携带 `expectedRevision`，通过锁文件、临时文件和原子替换写入，输出 JSON 回执。预设库默认定位 CapMotion 用户数据，同时允许显式 `--store-path` 便于测试和其他发行版。
5. **界面**：内置字幕样式只保留公共模板；字幕样式面板根据当前用户预设动态显示个人样式卡，因此老胡看到 `Laohu`，其他用户只看到自己保存的名称。

## 续篇：同一可见预设关联 Agent 制作偏好

### 已批准设计

用户只感知一个命名预设，例如 `Laohu`。该条目内部分为两种职责：

- `config`：Cap 编辑器和渲染器可直接应用的展示参数，人可通过现有界面编辑常用字段。
- `agentProfile`：不直接写入 `.cap` 时间轴的制作偏好，供 Agent 在剪辑、字幕和动画决策前读取。它只保存稳定、有枚举或布尔边界的偏好，不把一次作品的具体台词、EDL、时码或素材塞进预设。

`agentProfile` 首版只收纳已稳定的三类偏好：

1. 字幕：语言模式、意群切分、可读性顺句和最大行数。
2. 剪辑：自适应气口、保留个人表达、删除独立语气词和优先保留后面更完整的重录。
3. 动画：Remotion 唯一引擎、操作画面中默认不覆盖、需要全屏遮罩时的背景策略。

公共 schema 只公布字段、枚举和默认解释，不携带 `Laohu` 的具体值。新用户预设的 `agentProfile` 默认为空，不继承老胡偏好。

### 续篇实施步骤

1. 先用 Rust 和 TypeScript 测试定义旧预设无 `agentProfile` 仍可读、新建预设默认为空、保存画面设置不会丢失 Agent 偏好。
2. 在 `cap-project` 定义唯一类型和校验，Tauri store 与 CLI 共用，不各写一套字段。
3. 新增 `cap presets agent-profile <name> --profile-json ... --expected-revision ...`，继续使用 store revision、文件锁、原子替换和 JSON 回执。
4. `cap presets inspect` 返回同一条目的 `config + agentProfile`；`cap project preset apply` 明确只应用 `config`。
5. 回归旧预设、新命令、公共 schema 无个人值、工程内容保护和前端保存不丢 profile。

### 续篇实施结果

- 已在 `cap-project` 建立唯一的 `AgentEditingProfile` 类型与校验；Tauri 可见预设和 CLI 共用该类型，没有各自维护另一份字段定义。
- 已为同一条可见预设增加可选 `agentProfile`。旧预设缺少该字段时仍可读取；新建预设保持为空，不会继承老胡偏好。
- 已增加 `cap presets agent-profile <name> --profile-json ... --expected-revision ...`。写入继续使用预设库 revision、锁文件和原子替换；保存视觉 `config` 时保留已有 Agent 偏好。
- 已把第二遍后期入口接到 `cap presets inspect <name> --json`：任务明确指定预设时，Agent 在剪辑、字幕和动画判断前读取并记录 store revision；当轮明确指令始终高于持久偏好。
- 已用正在运行的 CapMotion 真实 store 副本完成端到端写入和读取；副本 revision 从 0 递增到 1，原 store 哈希保持不变。未重新打包、未修改运行中的用户数据，因此界面内编辑 Agent 偏好与运行中热刷新仍为后续能力。

## 续篇：原 Cap 工程直接后期与双语可编辑轨

### 新反馈暴露的最早失效点

此前 MP4 成片链虽然已经能生成双语字幕，但进入 Cap 工程时仍把“最终展示字幕”当成一组扁平片段：中文和英文没有稳定轨道身份，编辑器会继续用源 ASR 自动投影覆盖人工顺句与翻译；背景预设又只清除了旧图片路径，没有保留“每条新录制都绑定自己的当前桌面快照”这一意图。结果是导出视频看似接近目标，可返工工程却无法稳定复现同一结果。

### 本轮固定的老胡工程预设

- 画布：`16:9`。
- 背景：`currentDesktop` 语义绑定；每条录制解析到自己的 `assets/current-desktop-background.jpg`，不得保存另一工程或旧 worktree 的绝对路径。
- 主画面：保持录屏完整、等比显示，中心上移到 `x=0.5 / y=0.44`，为下方双语字幕留下稳定区域。
- 公共字幕外观：思源黑体粗体、白字、黑描边、黑色阴影、无实心底框、无弹跳动画。
- 中文字幕轨：`trackId=zh-CN`，默认 `64px`，中心 `y=0.92`。
- 英文字幕轨：`trackId=en`，默认 `34px`，中心 `y=0.972`。
- 同一意群共享 `pairId` 与起止时码；中文和英文是两条可分别选择、改字和调整时码的轨，不是把两种语言焊进同一字符串。

这些数值属于本机 `Laohu` 用户预设和轨级展示参数，不写进公共初始默认。运行中的 CapMotion 对外部 store 写入没有可靠热刷新，因此本轮先完成源码、接口和回归；只有应用退出且用户明确要求重新打包时，才更新独立版并迁移真实预设库。

### 新工作流

```text
用户交付正式录制 original.cap
→ 校验 original.cap 并保持只读
→ 在同一磁盘建立 edited.cap 工作副本
→ 读取并应用 Laohu 预设
→ 新 ASR 与全片虚拟剪辑审稿
→ 用户确认
→ EDL 冻结并写入 edited.cap
→ 根据冻结 T2 重新派生中英展示字幕
→ cap project captions materialize 写入两条轨
→ 重载工程，验证源字幕、双轨、pair、样式、画布、背景和 revision
→ 用户在同一个 edited.cap 中查看并持续返工
```

### 本轮实现与保护

- 新增 `captions.displayMode=materialized`，阻止最终双语字幕被源 ASR 自动投影覆盖；旧工程默认仍为 `autoProject`。
- `timeline.captionSegments` 新增 `trackId / trackLabel / language / pairId / manualPositionOverride`，旧单轨字段缺失时仍按原行为读取。
- 编辑器时间轴按轨道分组为“中文字幕”和“English Captions”两行；两轨共享公共样式，但保留各自字号和垂直位置。
- 渲染器同时绘制两条字幕轨；旧单轨仍只绘制一次。
- 新增一等命令 `cap project captions materialize`，用 project revision、工程锁和配对校验写入双轨；源字幕主稿保持不变。
- 任务包强制 `sourcePath != path`、`nonDestructiveCopy=true`，并强制 `SEPARATE_BILINGUAL` 两轨合同。

## 续篇：界面按改动字段保存个人预设

### 失效点

界面虽然已有新建、应用、保存、设默认、重命名和删除，但原“保存到预设”会重新截取当前工程的整份可复用配置。用户只改字幕字号时，工程里与目标预设不同的背景、画幅或其他参数也可能一起被保存，无法保证“一次操作只修改用户实际改动的那一栏”；同时界面没有恢复未保存改动的明确入口。

### 固定行为

- 应用预设时，保存合并后的可复用配置作为本次编辑基线。
- 保存时比较“应用基线”和“当前工程”，只把真正发生变化的字段合并到预设的最新值；其他字段即使被外部接口更新，也不得被旧基线覆盖。
- 打开编辑器时就捕获本次会话基线，因此不需要先应用目标预设；打开预设的二级菜单也不得暗中应用它，否则会在保存前把用户刚修改的值还原。
- “重置未保存的更改”重新应用预设当前保存值，不写预设库。
- 设默认继续由正式录制完成后的工程创建流程读取；普通更新沿用当前用户 store。
- 重命名、局部保存和整份展示设置保存都不得丢失同条预设的 `agentProfile`。

### 验证

- 纯函数回归覆盖单字段修改、外部并发更新保留、可选字段新增和删除。
- 前端类型检查覆盖预设应用基线、字段级保存、重置入口和中英文提示。
- 公共模板中仍不存在 `Laohu`；`Laohu` 继续只是当前用户的一条命名预设。

## 续篇：字体、中文空格与描边阴影的渲染闭环

### 本轮失效点

- 工程里的 22 条中文字幕含“汉字 + ASCII 空格 + 汉字”，换字体也不会消失，视觉上被误判成字距或字体未生效。
- 旧描边只绘制八个方向的整段文字副本，4px 粗描边在汉字转角和细笔画上会不均匀；字幕效果边界只预留约 2px，较粗描边和阴影会被裁切。
- 原 `shadow` 和 `outlineShadow` 被设计成两套割裂效果，这与字体描边后阴影应从描边外缘延伸的实际语义不符。
- 字体选择器直接显示内部英文 family ID，中文界面无法辨认思源黑体、思源宋体和霞鹜文楷。
- 更深一层的实帧对照发现：工程字段从思源黑体改为思源宋体后，两张导出帧的 SHA-256 完全相同。原因是旧版只加载可变字体，fontdb 可以查到 family，但只暴露为字重 `250`；当字幕请求 `700` 时，cosmic-text 拒绝该命名字体并把黑体、宋体都静默回退到同一系统 CJK 字体。
- 同类审计还发现：字幕斜体被工程和 CLI 保存但渲染器从未读取，且随包中文字体没有斜体字面；字间距把界面的像素值直接交给以 EM 为单位的排版库；未实现的历史 `lingerDuration` 仍被公共 schema 宣称为可配置。这三项都会制造“参数已改、成片不变或严重失真”的假能力。

### 固定行为

- 内部始终保存稳定字体 family ID；中文界面只本地化显示名称，不改写旧工程里的技术标识。`Source Han Sans CN VF` 显示为“思源黑体（简体中文）”；渲染时兼容映射到随包的 `Source Han Sans SC` 静态字重家族。
- 随包下载思源黑体和思源宋体的 `400 / 500 / 700` 静态字重，不再依赖排版库无法精确匹配的单个可变字体文件。霞鹜文楷随包提供真实 `300 / 400 / 500` 字重，界面不再提供该字体不存在的粗体。
- 系统无衬线、系统衬线和系统等宽体在中文字幕中分别绑定明确的本机 CJK 字体，并把界面的常规/粗体请求映射到这些字体真实存在且视觉不同的字重；所有六个字体名称均按界面语言显示，工程仍保存稳定英文 ID。
- 字间距按“设计像素 ÷ 配置字号”换算为 EM 后再随输出尺寸统一缩放。旧工程的斜体字段继续进入 shaping，`italic` 与未实现的历史 `lingerDuration` 都保留读取兼容，但在中文斜体能力可验证前不再作为公共可用参数对外展示。
- 中文字幕轨物化时仅清除相邻汉字间的 ASCII 分隔空格，英文词间空格原样保留；保真字幕主稿不被改写。
- 公共样式只向用户和新 Agent 暴露一套 `shadow*`。未描边时它是字形阴影，已描边时它自动从描边外缘扩展；旧 `outlineShadow*` 仅作兼容输入并在读取或下次修改时迁移。
- 渲染器用更密的内外两圈采样生成描边，并按“描边宽度＋统一阴影外扩”计算裁切边界。
- 字幕动画选择“无”时，渲染器将全局和单条淡入淡出时长都视为 `0`，界面不再展示不生效的时长滑块。
- 工程里的临时字体测试不等于保存预设；只有显式保存已更改设置才写回用户预设。

## 续篇：预设会话差量、轨级位置、入场动画与统一存储

### 最早失效点

- 预设菜单的子菜单触发器同时绑定了“应用”，用户只是打开菜单准备保存，界面改动就已被还原。
- 保存逻辑只认“上次应用的预设”，无法表达“从本次打开工程以来，用户真正改过什么”。
- 字幕拖动把位置写到单条 segment，导致同轨字幕漂移；旧动画共用淡入淡出和出场延时，“无动画”、“弹跳”与“弹入”在观感上不够独立。
- 存储设置只影响录制工程，截图工程和自定义背景仍写入 Application Support，所以用户明明选了外置目录，系统盘仍继续增长。

### 固定行为

- 编辑器打开、显式应用预设或成功保存后更新会话基线。保存只递归合并基线之后改动的展示字段，以预设存储中的最新值为合并底稿；未改字段与 `agentProfile` 均原样保留。
- 手动字幕位置存入 `CaptionSettings.trackPositions`，坐标以 1920×1080 设计画布的中心为 `0,0`。拖动、X/Y 输入和方向键都更新选中字幕所在的整条轨，同时清理该轨的历史单条位置覆盖。
- 动画保留 `none / fade / bounce / pop` 兼容值，界面呈现为“无动画 / 渐显 / 上移显现 / 弹入”。四者只处理入场，字幕到达结束时间立即结束，不再为出场动画延长 segment。
- 用户选定的存储根同时管理新录制工程、新截图工程和工程自有媒体。截图工程放在自定义根下的 `screenshots/`，导入背景放在所属 `.cap/assets/backgrounds/`；旧默认目录和历史自定义目录继续被扫描，不强制搬迁。

### 验证与状态
