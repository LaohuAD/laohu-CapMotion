# 编辑型信息叠层 Implementation Plan

> **For agentic workers:** 本计划在当前单工作目录内直接执行；项目规则禁止额外 worktree。执行采用测试先行，完成后以关键帧渲染和手机缩略图共同验收。

**Goal:** 从参考视频中提炼一套可复用的“口播底画 + 编辑型信息叠层”Remotion 能力，让现有语义组件既能做整屏图解，也能在不遮挡人物的情况下做高密度、渐进式的侧边讲解。

**Architecture:** 不新增万能动画组件，也不逐屏复制参考视频。为公共 schema 增加舞台/叠层呈现方式、位置和语义色角色；为公共视觉层增加透明叠层容器、玻璃面板、微标签和安全区；先升级观点、数据、对比、流程四个现有组件，再用四个有来源标记的演示配置验证。参考视频中的真人、B-roll、网页截图和字幕属于底画或素材层，Remotion 只承担结构化解释层。

**Tech Stack:** Remotion 4、React 19、TypeScript、Zod、Vitest、ffmpeg 7。

## 一、来源与判断边界

- 来源视频：`/Volumes/Laohu_Work/下载/douyin_7425882531418965049.mp4`
- 技术信息：1920×1080、30fps、约 402 秒、H.264 + AAC。
- 本轮采用 1fps 全片接触表定位，再对高价值片段以 5fps 复核进入、展开和收束；这比机械逐帧看六分多钟更快，也足以识别 0.2 秒级的主要动画节拍。
- “由 Remotion 制作”是用户给出的来源事实；对单个元素的制作方式仍按画面证据分层判断。

### 可确定的分层

| 层 | 视频中的表现 | 本项目对应 |
| --- | --- | --- |
| 底画 | 真人口播、办公室/会议/网页等 B-roll、RGB 灯光、镜头剪辑 | Cap 基础视频或外部素材，不由叠层组件重复制作 |
| 素材 | 搜索页、文档、新闻截图、手机界面、头像、图标、股票/会议画面 | `mediaSrc` 或 Cap 底层证据素材，保留来源 |
| Remotion 结构层 | 大标题、章节号、卡片、图表、进度环、连接线、红框、高亮条、数字和结论条 | 现有 12 个语义组件 + 本轮新增的叠层呈现能力 |
| 字幕 | 底部中英字幕，连续贯穿不同素材 | 独立字幕流程，不纳入本轮动画组件 |

点阵地球、复杂网页滚动等元素可能是预渲染素材，也可能由程序绘制；仅凭成片不能证明其源码来源。本轮把它们视为可替换媒体，不伪称为已还原的纯代码动画。

## 二、全片价值画面记录

### 00:23–00:29｜概念定场

- 画面：近黑整屏，左侧超大 `GEO`，右侧点阵地球，蓝色英文展开名、中文定义和琥珀标签分层出现。
- 有效原因：先交代“这是什么”，再给技术气质；一个主概念占据绝对层级，小字只作身份说明。
- 可复用：`KineticStatement.keyword` 的整屏模式。
- 延伸：可替换成工作流、模型、四层能力等抽象概念；媒体对象不必总是地球，可以是文件、时间轴、关系网络。
- 风险：点阵和英文微标签只能增强气质，不能承载唯一关键信息。

### 00:30–00:38｜观点 + 趋势证据

- 画面：真人居中偏右，左侧先出现两行观点，右侧半透明图表面板随后进入；折线绘制完成后，`+114.79%` 和来源小标签最后出现。
- 有效原因：观点先告诉观众“看什么”，图表再回答“凭什么”；数字不是一开始就剧透，而是收束证据。
- 可复用：`KineticStatement.claim` + `DataStoryChart.trend` 的左右组合。
- 延伸：适用于“问题 + 成本”“动作 + 结果”“规则 + 违规率”等证据结构。
- 风险：未经来源确认的数字不能照抄；叠层必须避开人脸和字幕。

### 00:38–00:53｜步骤卡与议程栈

- 画面：左右步骤卡依次建立，随后变成带编号的纵向议程；旧条目保留，新条目继续累积，最后出现行动条。
- 有效原因：观众随口播看到结构被搭建，而不是面对一张已经填满的 PPT。
- 可复用：`FlowNodeGraph.linear` 的叠层模式。
- 延伸：清单、课程章节、四层架构、制作阶段、检查门都可用相同语法。
- 风险：条目过长会变成文字墙；每项应是动作或产物，而非抽象名词。

### 00:54–01:10｜概念转证据页面

- 画面：真人旁先给定义，随后切换 Google / 搜索列表 B-roll；Remotion 只保留新旧标签、得分或首项高亮。
- 有效原因：程序动画不重复画网页，而是帮助观众在真实页面里找到证据。
- 可复用：`ScreenExplainer.spotlight`、`EvidenceBoard.source-trail`。
- 延伸：软件教学、数据报告、官方文档和后台页面都应优先采用“真实界面 + 最小标注”。
- 风险：完整重绘真实页面会降低可信度，也增加维护成本。

### 01:13–01:20｜技术过程条

- 画面：左上两行大标题“讨好 / 爬虫”，紫色作技术语义色；虫形图标面板出现，旁边暗色容器横向扩展，过程条逐条填入。
- 有效原因：图标提供对象，条带提供过程，标题提供结论；三者分工清楚。
- 可复用：`FlowNodeGraph.linear` 的技术叠层变体。
- 延伸：上传、识别、剪辑、渲染、回填等后台流程可以用动态状态条表现。
- 风险：不能把无意义进度条当“科技感”装饰；每条必须对应真实状态。

### 01:21–01:47｜AI 回答与数字证明

- 画面：手机/文档底画先建立语境，AI 回答面板逐行出现品牌、引用和来源；随后大数字 `69%` 进入，最后用 `GEO ≫ SEO` 收束。
- 有效原因：先让观众看到证据如何形成，再给结论；数字承担转折，不是孤立海报。
- 可复用：`EvidenceBoard.proof-stack` + `KineticStatement.number`。
- 延伸：ASR 准确率、剪辑前后时长、转化、成本和错误率都可以由证据栈导向单一数字。
- 风险：数字来源不明时只能标“示意”，不能视觉上伪装成事实。

### 01:49–02:14｜可信度、广告警告与排名

- 画面：动势标题使用琥珀色；搜索结果中红色“软文/广告”标签逐个打入；排名列表先完整出现，再单独点亮目标项。
- 有效原因：颜色承担语义而不是装饰；先给全貌再聚焦，观众知道目标项位于什么上下文。
- 可复用：`KineticStatement.claim`、`RiskActionLoop.redline`、`DecisionCanvas.ranking`。
- 延伸：可用于证据等级、方案筛选、风险标记和错误诊断。
- 风险：大面积红色会疲劳；红色只给被否决的对象和最终风险结论。

### 02:18–02:27｜先发优势记忆锚点

- 画面：左侧巨大 `FIRST MOVER / 先发优势` 长时间保持，下面的小利益标签根据口播逐个补齐。
- 有效原因：核心词不移动，变化集中在解释层；既稳定又有持续响应。
- 可复用：`KineticStatement.keyword` 叠层模式。
- 延伸：四层能力可使用“灵魂定向 / 筋骨成篇 / 血肉生变 / 表皮成形”作为稳定锚点，下面只切换其领域解释。
- 风险：工程化英文微标签不得替代观众可理解的中文。

### 02:29–03:26｜步骤章节、文件卡与可信度进度

- 画面：`STEP 01/02` 先建立章节；反爬开关、文件窗口、输入条目和正确项逐步完成；权威背书以徽章、进度条和 `可信度 +1` 收束。
- 有效原因：每一段都有“未完成 → 操作 → 完成”的状态变化，动画真正解释了过程。
- 可复用：`FormTemplateBuilder.form-fill`、`RiskActionLoop.compliance`、`EvidenceBoard.claim-evidence`。
- 延伸：可表现任务包校验、ASR 结果、EDL 冻结、素材补齐和 Cap 回填状态。
- 风险：没有真实开关或状态时，不能伪装成已经执行成功。

### 03:28–03:49｜关系网络与公式组合

- 画面：人物/主体节点先出现，来源和传播节点环绕进入；两个来源卡用加号连接，最后合成为结果卡。
- 有效原因：关系通过位置和连线表达，口播不必重复解释“谁影响谁”。
- 可复用：`SystemMap.hub-spoke`、`FlowNodeGraph.artifact-flow`。
- 延伸：四层架构可展示“箴言决定取舍 → 章法组织步骤 → 技法组织材料 → 法度完成形态”，并显示反馈回流。
- 风险：节点太多会像脑图；主路径必须比旁支更亮。

### 03:57–04:48｜双面判断与证据红线

- 画面：绿色正确侧和红色危险侧先建立，再逐项给动作；新闻/文档底画上使用少量红框、下划线和可信度归零面板。
- 有效原因：先判断，再拿真实证据落锤；警告最终落到“公平、客观、真实”的行为标准。
- 可复用：`CompareTransform.myth-fact`、`ScreenExplainer.annotation`、`RiskActionLoop.redline`。
- 延伸：适用于“形式漂亮但内容断裂”“能渲染但不可追溯”等项目质量冲突。
- 风险：反馈截图里的红框不是设计稿；标注只指向证据，不机械照搬。

### 04:49–05:26｜市场柱图、利润环与价格对比

- 画面：三根柱按年份依次长高，数值随后出现，`CAGR 40.6%` 最后进入；价格卡先出现容器再填金额；利润环从 0 数到 40%，下方再出现传统广告对照条。
- 有效原因：同一数据区有明确阅读顺序：类别 → 值 → 关键结论 → 比较基准。
- 可复用：`DataStoryChart.bars`、`DataStoryChart.counter`、`CompareTransform.a-b`。
- 延伸：适用于时间节省、精剪压缩、ASR 成本、动画覆盖率和交付状态。
- 风险：柱高、环形比例和数字必须一致；观察窗口不能画成业绩柱。

### 05:29–06:13｜路径身份、风险与选择标准

- 画面：巨大路径号建立章节，身份标签逐个点亮；风险段切换 B-roll 并叠加红卡；专业服务标准改用琥珀清单，最终收束到“建立壁垒”。
- 有效原因：同一结构通过语义色改变情绪，而不每段重做视觉语言。
- 可复用：`DecisionCanvas.scorecard`、`RiskActionLoop.risk-action`、`FlowNodeGraph.linear`。
- 延伸：同一四层框架可针对“写作、动画、剪辑、字幕”切换材料与验收，不复制四套模板。
- 风险：颜色切换应随判断变化，不能为了刷新画面随机换色。

### 06:15–结束｜对比柱与品牌收束

- 画面：琥珀与蓝色薪资柱建立强对比，右上结论卡后出现；片尾保留头像、名称、承诺和单一行动按钮。
- 有效原因：最后阶段减少信息，只保留差异和下一步，避免观众在结尾重新学习复杂结构。
- 可复用：`DataStoryChart.bars` + `KineticStatement.claim`。
- 延伸：片尾可收束本期生成的具体产物，而不是通用“点赞关注”。
- 风险：品牌片尾不能过长；行动必须与本期承诺一致。

## 三、从一个案例推出来的长期视觉语法

1. **底画稳定，信息侧写。** 真人或证据素材负责真实感，Remotion 只占人物以外的安全区；除章节定场外，不轻易整屏盖住底画。
2. **先立观点，再给证据。** 标题先进入，图表、文档、数字或标注随后建立，最终结论最晚出现。
3. **累积而非替换。** 每个新元素都补全正在解释的结构；旧元素降权但保留，观众始终看得到来路。
4. **语义色不是主题皮肤。** 蓝色=过程/信息，绿色=增长/成立，琥珀=权威/价值，红色=风险/否决，紫色=技术过程；中性玻璃面板保持一致。
5. **微标签制造精度，中文主句承担理解。** 英文、编号、细线和 ID 只能提供编辑感，关键结论必须是手机缩小后仍看得清的中文。
6. **动作短，停留长。** 主要进入使用 0.3–0.8 秒的小位移、展开和绘制；完成态留给观众阅读，不做持续晃动。
7. **每屏只赢一个点。** 高信息密度不等于多主角；标题、主图解、最终数字三者必须有先后等级。

### 举一反三

- 口播观点 + 侧边折线，可延伸为“判断 + 证据”“问题 + 成本”“规则 + 风险率”。
- 纵向议程栈，可延伸为四层能力、后期工序、检查门、任务状态和素材补齐。
- 技术状态条，可延伸为 ASR、粗剪、EDL、字幕、Remotion、数字人、Cap 回填的真实运行状态。
- 证据红线，可延伸为软件界面讲解、官方文档引用、数据核验和错误定位。
- 进度环/柱图，可延伸为可验证指标；若没有数值，则改用清单完成度，不能编造比例。
- 侧边长期锚点，可延伸为章节名或核心模型，解释项随口播累积，主体始终不跳动。

## 四、四层根因与取舍

### 灵魂

现有组件能把信息“做成一页”，但参考视频更强的地方是把信息“送进正在发生的讲解”。主胜负手因此不是增加特效，而是让真实底画保持可信，让动画只在需要理解、证明、选择或提醒时出现。

> 底画留住真实，叠层指出要害。

### 筋骨

旧链路只有 `配置 → 整屏组件 → 渲染`。本轮补成：`配置 → 选择 stage/overlay → 计算人物安全区 → 主观点进入 → 结构累积 → 数字/结论收束 → 透明资产 → Cap 上层轨`。删除“位置、语义色、呈现方式”任何一步，叠层都会退回全屏 PPT 或遮挡底画。

### 血肉

真正有效的材料不是更多装饰，而是标题、真实证据、过程节点、数值、风险和结论。每种材料都说明进入时机和作用：标题定焦，图解解释关系，数字落锤，结论转行动；无来源事实不得用高精度视觉伪装。

### 表皮

硬规格：1920×1080；叠层只占安全侧区；透明渲染可复现；中文主句手机可读；颜色满足语义；入场、展开、收束、最终态均能 seek；最终态至少停留 30 帧或 20%。审美验收还要比较人物是否被遮、是否像广告海报、微标签是否喧宾夺主。

### 第一轮遗漏及修正

1. **所有文字共用一套系统字体。** 这会让数字、英文和中文都拥有相同宽度，画面缺少编辑层级。现已拆成 `display / body / number / micro` 四套字体栈。
2. **使用 550、650、850、950 等不存在的字重。** 浏览器会合成假粗体，字腔被挤小，用户看到的“加粗后像换了字体”由此产生。当前公共组件只使用真实的 500、700、800、900 档，并有全组件扫描测试保护。
3. **字距使用固定像素。** 相同 `1.3px` 在 18px 与 90px 字号上不是同一视觉关系。现改用 `em`：展示字负字距，英文眉题高正字距，正文零字距。
4. **中英文眉题挤在同一行。** 参考片通常是英文技术标签在上、中文解释在下；现在 `splitBilingualLabel` 只在斜杠后确实是中文时分层，`DATA / PROOF` 这类纯英文结构保持原样。
5. **两行主标题只有一种颜色。** 参考片常用“白色对象 / 语义色变化”建立关系。schema 新增 `titleLines`，由制作脚本显式决定完整意群、断行和语义色，不按字数自动猜。
6. **数字没有专门格式。** 数字现使用窄体字栈、紧行高和等宽数字；类别名仍用中文卡片字，避免数据图像普通列表。
7. **正文过粗、断行随容器漂移。** 正文恢复 500 字重和 1.38 行高；主标题必须由脚本按意群手工断行。当前四层演示已用“声音定路 / 画面作证”两行配置验证。

### 字体、色彩与排版新增认识

1. **章节状态常驻。** 左上角经常保留很小的章节/主题标签，主信息则在其下方继续演进。它告诉观众“现在仍在讲哪一件事”，不与当前结论争第一焦点。
2. **英文负责分类，中文负责解释。** 英文标签常为全大写、高字距、小字号；中文展示字更粗更大。英文不是随机装饰，而是给能力、状态和关系命名。
3. **数字是独立版式角色。** `95%`、`5→10` 等数字明显比标题更高、更窄，说明数字不能继承中文标题字形和行高。
4. **语义色形成系统。** 蓝色偏信息/能力，绿色偏成立/岗位，黄色偏价值/条件，红色偏风险/否决，紫色偏对照/未知；同一小节中颜色稳定，不按镜头随机轮换。
5. **底画本身就是调色层。** 真人底画使用红/青两侧光，动画卡片保持低透明深色、细描边和轻微外发光。高饱和色只落在关键词、线和状态，不把整张卡涂满。
6. **字幕安全区被长期保护。** 主要解释层集中在左上、上中或人物两侧；底部中英字幕区基本不被覆盖。宽信息面板也会在字幕上方停止。
7. **确切字体仍未知。** 只能确认是几何无衬线/现代黑体体系、真实粗体、紧标题字距、宽眉题字距；不能从成片断言具体商业字体名。

### 动效的真正新增规律

第二条参考片证明，项目原来的“自动错峰”只解决了元素不同时弹出，却没有解决元素是否与口播语义同步。参考片更接近以下章法：

```text
先定对象 → 口播到达一个完整语义点 → 增加一个对象或关系
→ 已建立内容继续保留 → 最后一层给结论 → 留出完整阅读时间
```

典型对象在约 0.25–1 秒内完成轻位移和淡入；真正重要的是触发时机，不是统一动画时长。长比较可保持十几秒，期间只增加内容，不反复清空。整体退出发生在一个论证单元完成时，而不是每句话结束时。

因此新增公共字段 `items[].revealAtFrame`：

- 表示当前 Remotion composition 内的相对帧；
- 用完整语义点对齐，不按字数或元素数平均猜测；
- 对象进入后默认累计保留；
- 未提供时沿用旧自动错峰，保护已有配置；
- 值必须小于 `durationInFrames`，越界由 schema 拒绝；
- 它不是绝对 T2 时码，绝对成片时间继续只放 `sourceTimeRange`。

### 组件映射与“不新增组件”的决定

| 参考结构 | 当前唯一组件 | 本轮处理 |
| --- | --- | --- |
| 概念标题、行动句、记忆句 | `KineticStatement` | 使用 `titleLines`、语义色与精确出现帧 |
| 多卡能力矩阵、流程条、工具替换 | `FlowNodeGraph` | 按语义帧逐卡累积，不另建“卡片动画” |
